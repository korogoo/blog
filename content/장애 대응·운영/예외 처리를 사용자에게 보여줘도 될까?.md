## 예외의 종류와 복구 가능성

> 모든 예외가 같지 않다
> 
> ==복구 가능한 예외와 그렇지 않은 예외==를 구분해야 한다

---

### 복구 가능한 예외

사용자의 잘못된 입력이나 일시적 오류처럼, 재시도하면 정상 동작할 수 있는 예외

```java
// 사용자가 잘못된 좌표를 입력한 경우
3번 칸으로 이동 → "존재하지 않는 위치 입니다" → 다시 입력받으면 해결 가능
```

예외 메시지를 사용자 친화적으로 보여주고, 재시도를 유도한다

---

### 복구 불가능한 예외

프로그래밍 버그, 시스템 오류처럼 재시도해도 해결되지 않는 예외

- NullPointerException, ArrayIndexOutOfBoundsException 등
- DB 연결 실패 등 인프라 오류

스택 트레이스를 로그로 남기고, 사용자에게는 "오류가 발생했습니다" 정도로만 안내한다

---

### 스택 트레이스를 사용자에게 보여주면 안 되는 이유

✨ **보안 위험**

스택 트레이스에는 파일 경로, 클래스명, 라이브러리 버전 등 내부 구조가 드러난다

공격자에게 시스템 구조를 노출하는 것이다

<br/>

✨ **사용자 경험 훼손**

`java.lang.NullPointerException at janggi.model.Board.move(Board.java:42)` 

이런 에러 메시지는 사용자에게 아무 의미가 없다

<br/>

✨ **신뢰 손상**

기술적 오류가 그대로 보이면 시스템을 불신하게 만든다

---

### 올바른 분리

```java
try {
    game.move(from, to);
} catch (IllegalArgumentException e) {
    // 복구 가능 — 사용자 메시지만 보여준다
    System.out.println("올바르지 않은 이동입니다. 다시 입력해주세요.");
} catch (Exception e) {
    // 복구 불가능 — 로그 남기고 프로그램 종료 또는 안전 메시지
    logger.error("예상치 못한 오류", e);
    System.out.println("오류가 발생했습니다. 관리자에게 문의해주세요.");
}
```

## 재시도 로직 - 재귀 vs 반복

> 재시도 로직은 ==while 반복문==으로 구현하는 것이 안전하다  
> 
> 재귀는 스택 오버플로우 위험이 있다

---

### 재귀 방식의 문제

```java
public void retryInput() {
    try {
        String input = scanner.nextLine();
        game.move(parsePosition(input));
    } catch (IllegalArgumentException e) {
        System.out.println("다시 입력해주세요.");
        retryInput(); // ← 스택에 쌓인다
    }
}
```

사용자가 100번 잘못 입력하면 스택이 100프레임 쌓인다

악의적인 사용자가 의도적으로 무한 오입력하면 `StackOverflowError` 가 발생한다

재시도 로직은 사용자 입력에 따라 **무한정 반복될 수 있어** 재귀에 적합하지 않다

---

### 반복문 방식

```java
public void retryInput() {
    while (true) {
        try {
            String input = scanner.nextLine();
            game.move(parsePosition(input));
            return; // 성공하면 탈출
        } catch (IllegalArgumentException e) {
            System.out.println("다시 입력해주세요.");
            // 스택은 쌓이지 않는다
        }
    }
}
```

wile 조건문만 잘 설정하면 괜찮은 방법이다

그리고 재귀와 다르게 스택에 쌓이지 않는다

---

### 재귀가 적합한 상황

재귀는 **탈출 조건이 보장되고, 깊이가 제한적일 때** 적합하다

```java
public void traverseTree(Node node) {
    if (node == null) return;
    process(node);
    traverseTree(node.left);
    traverseTree(node.right);
}
```

" 트리 탐색 깊이가 자료구조로 제한된다

## 내 기준

### 예외 처리 결정 흐름

```
예외가 발생했다
       │
       ▼
이 예외는 사용자 입력/행위로 인한 것인가?
       │
  ┌────┴────┐
 YES        NO (시스템/버그)
  │          │
  ▼          ▼
재시도로     로그 남기고
복구 가능?   안전 메시지 출력
  │
  ├── YES → 사용자 친화 메시지 + 재시도 유도
  └── NO  → "다시 시작해주세요" or 종료
```

---

### 재시도 구현 기준

| 상황 | 방법 |
|---|---|
| 사용자 입력 재시도 | `while(true)` + `try-catch` |
| 트리/재귀 탐색 | 재귀 허용 |
| 네트워크 재시도 | 최대 횟수 제한 + 지수 백오프 |

---

### 실전 체크리스트

✨ **콘솔에 스택 트레이스가 출력되는가?**

로거로 대체하고, 사용자에게는 친화적 메시지만 보여준다

<br/>

✨ **재시도를 재귀로 구현했는가?**

탈출 조건이 확실하고, 재시도 성공 확률이 높다면 팀 내 합의를 해보고,

특별한 이유가 없다면 안정성과 가독성을 위해 `while` 반복문으로 바꾼다

<br/>

✨ **`catch (Exception e)`로 모든 예외를 한 번에 잡는가?**

복구 가능한 예외와 불가능한 예외를 분리해서 처리한다

<br/>

✨ **예외 메시지가 개발자 언어인가? ("IllegalArgumentException: ...")**

사용자 언어로 바꾼다 ("잘못된 입력입니다. 다시 시도해주세요.")
