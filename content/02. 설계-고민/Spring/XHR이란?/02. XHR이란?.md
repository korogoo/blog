> XHR은 페이지를 새로 고침하지 않고 서버와 통신하는 기술이다  
> ==AJAX의 핵심이며, 현재는 Fetch API가 주로 쓰이지만 브라우저 도구에서는 여전히 XHR이라는 용어를 쓴다==

---

## 정의

XMLHttpRequest

브라우저에서 JavaScript로 HTTP 요청을 보내는 기술이다

---

## 왜 등장했는가?

초기 웹은 링크를 클릭하면 페이지 전체를 새로 불러왔다

검색 결과 하나를 바꾸기 위해 전체 페이지가 리로드됐다

XHR의 등장으로 페이지를 새로 고침하지 않고 서버에서 데이터만 받아올 수 있게 됐다

이 기술이 AJAX(Asynchronous JavaScript And XML)의 핵심이다

---

## 동작 흐름

```
브라우저(JavaScript)  →  HTTP 요청  →  서버
브라우저(JavaScript)  ←  JSON 응답  ←  서버
```

페이지는 그대로, 데이터만 바뀐다

---

## XHR → Fetch API

XHR은 구식 API가 되었고, 현재는 더 깔끔한 **Fetch API**를 많이 쓴다

```javascript
// XHR 방식 (구식)
const xhr = new XMLHttpRequest();
xhr.open('GET', '/api/user');
xhr.send();

// Fetch API 방식 (현재)
fetch('/api/user')
  .then(response => response.json())
  .then(data => console.log(data));
```

---

## 왜 알아야 하나?

브라우저 개발자 도구 → Network 탭에서 `XHR`이라는 필터를 볼 수 있다

이 필터는 JavaScript로 비동기적으로 보낸 HTTP 요청을 모아서 보여준다

Fetch API로 보낸 요청도 이 탭에서 확인된다

---

## 핵심

REST API를 개발할 때 브라우저 개발자 도구의 Network → XHR 탭에서  
실제로 어떤 요청이 오가는지, 어떤 JSON이 담기는지 확인하게 된다

이 탭을 활용하는 습관이 생기면 프론트-백 사이의 문제를 빠르게 파악할 수 있다
