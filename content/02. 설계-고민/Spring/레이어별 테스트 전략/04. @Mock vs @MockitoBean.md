> 둘 다 가짜 객체를 만들지만, 그 객체가 Spring 컨텍스트에 등록되느냐가 다르다  
> ==Spring 컨텍스트가 있는 테스트라면 @MockitoBean, 없다면 @Mock==

---

## 비교

| | `@Mock` | `@MockitoBean` |
|--|---------|----------------|
| 만드는 주체 | Mockito | Spring + Mockito |
| 컨텍스트 등록 | X | O (기존 빈을 교체) |
| 사용 위치 | `@ExtendWith(MockitoExtension.class)` | `@SpringBootTest`, `@WebMvcTest` |
| 주입 방식 | `@InjectMocks`가 직접 주입 | Spring이 컨텍스트에 넣어줌 |

---

## @Mock이 Controller 테스트에서 동작하지 않는 이유

```
@SpringBootTest 환경:
  Spring 컨텍스트 안에 MemberService(실제 빈) 존재
  
  @Mock MemberService mockService;  →  Mockito가 따로 만든 가짜 객체
                                       Spring 컨텍스트와 무관
  
  Controller → Spring 컨텍스트에서 MemberService 찾음
             → 실제 빈 주입 (Mock 아님)
```

`@Mock`은 컨텍스트 밖에 존재하기 때문에 Controller에 전달되지 않는다

---

## @MockitoBean이 동작하는 이유

```
@SpringBootTest 환경:
  @MockitoBean MemberService mockService;
  
  Spring 컨텍스트 안의 실제 MemberService 빈을 가짜로 교체
  
  Controller → Spring 컨텍스트에서 MemberService 찾음
             → 가짜 빈 주입 (Mock 적용됨)
```

---

## 언제 무엇을 쓰는가

- [I] **`@Mock`** — Spring 컨텍스트 없는 순수 단위 테스트 (`@ExtendWith`)

- [I] **`@MockitoBean`** — Spring 컨텍스트를 띄운 통합 테스트 (`@SpringBootTest`, `@WebMvcTest`)
