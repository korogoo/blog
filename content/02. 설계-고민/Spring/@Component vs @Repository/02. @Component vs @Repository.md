> @Repository는 @Component다  
> ==차이는 예외 변환(Exception Translation) 기능이 추가되어 있다는 것==

---

## @Component

Spring이 관리하는 Bean으로 등록하는 가장 일반적인 어노테이션이다

```java
@Component
public class SomeHelper {
    // Spring이 이 객체를 생성하고 관리한다
}
```

특별한 역할이 없는 일반 컴포넌트에 사용한다

---

## @Repository

```java
@Repository
public class MemberRepository {
    // 데이터 접근 계층
}
```

- [I] **@Component를 상속(메타 어노테이션)한다**

즉, @Repository를 붙이면 @Component 기능도 함께 동작한다

<br/>

- [I] **추가 기능 — 예외 변환(Exception Translation)**

DB 관련 예외(JDBC `SQLException`, JPA `PersistenceException` 등)를  
Spring의 `DataAccessException` 계층 구조로 변환해준다

```
JDBC SQLException  →  Spring DataAccessException
JPA PersistenceException  →  Spring DataAccessException
```

이 덕분에 DB 기술(JDBC, JPA, MongoDB 등)이 바뀌어도  
Service 계층에서 잡는 예외 타입이 달라지지 않는다

---

## 스테레오타입 어노테이션들

Spring은 역할을 명시하는 어노테이션을 따로 제공한다

| 어노테이션 | 역할 | 특이사항 |
|-----------|------|---------|
| `@Component` | 일반 컴포넌트 | 기본 |
| `@Repository` | 데이터 접근 계층 | 예외 변환 |
| `@Service` | 비즈니스 로직 계층 | @Component와 동일 (현재) |
| `@Controller` | 웹 요청 처리 계층 | MVC 기능 추가 |

---

## 핵심

기능적 차이는 예외 변환 하나지만,  
어노테이션 이름 자체가 이 클래스의 역할을 코드로 표현하는 수단이다

데이터 접근 객체라면 @Repository, 비즈니스 로직이라면 @Service를 쓰는 것이  
코드를 읽는 사람에게 의도를 전달한다
