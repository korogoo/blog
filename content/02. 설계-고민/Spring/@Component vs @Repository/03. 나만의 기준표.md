
> 기능적으로는 @Component가 기본이고, 나머지는 역할을 명시하는 확장이다  
> ==어노테이션 이름 자체가 코드를 읽는 사람에게 이 클래스의 역할을 알려준다==

---

## 스테레오타입 어노테이션 정리

| 어노테이션 | 역할 | 추가 기능 |
|-----------|------|---------|
| `@Component` | 일반 컴포넌트 | 없음 (기본) |
| `@Repository` | 데이터 접근 계층 | 예외 변환 (DataAccessException) |
| `@Service` | 비즈니스 로직 계층 | 없음 (@Component와 동일) |
| `@Controller` | 웹 요청 처리 계층 | MVC 관련 기능 추가 |
| `@RestController` | REST API 처리 | @Controller + @ResponseBody |

---

## 결정 흐름

```
이 클래스는 어떤 역할인가?
         │
    ┌────┼────┬────┐
  데이터   비즈  웹   기타
  접근    니스  요청
    │      │    │    │
@Repository @Service @Controller @Component
```

---

## 실전 체크리스트

- [I] **`@Component`와 `@Repository` 중 무엇을 써야 하는가?**

DB 접근 객체라면 `@Repository`를 쓴다

예외 변환 기능 외에도, 코드를 읽는 사람이 이 클래스의 역할을 즉시 파악할 수 있다

<br/>

- [I] **`@Service`를 `@Component`로 바꿔도 동작하는가?**

현재는 동작한다. 하지만 역할을 명시하는 표현력을 잃는다

<br/>

- [I] **`DataAccessException`이 발생하는 원인이 궁금한가?**

`@Repository`가 DB 관련 예외를 `DataAccessException`으로 변환해서 던진다

JDBC의 `SQLException`, JPA의 `PersistenceException`을 계층을 통일해서 잡을 수 있게 해준다
