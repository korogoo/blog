> "영속성 침해"는 두 가지 의미로 쓰인다

---

## 1. 레이어 의존 방향 문제

일반적으로 레이어 의존 방향은 아래쪽을 향해야 한다

```
Controller (Presentation)
    │
Service (Application)
    │
Domain (Entity)
    │
Repository (Infrastructure)
```

DTO는 Controller나 Service 레이어에 속한다

Entity가 `toDto()`를 가지면 ==Domain이 Application/Presentation을 알게 되는 것==이다

의존 방향이 역전되어 DTO가 바뀔 때마다 Entity도 수정해야 한다

---

## 2. JPA 영속성 컨텍스트 문제

JPA를 사용할 때 Lazy Loading으로 연관 엔티티를 가져오는 경우, ==트랜잭션이 끝난 후 접근하면 예외가 발생==한다

```java
// Service (트랜잭션 안)
Reservation reservation = reservationRepository.findById(id);

// Controller (트랜잭션 밖)
reservation.getMember().getName(); // LazyInitializationException!
```

DTO 변환을 트랜잭션 밖(Controller)에서 하면 이 문제가 생긴다

---

## 두 문제는 별개다

| | 문제 원인 | 해결 방향 |
|---|---|---|
| 레이어 침해 | Entity가 DTO를 알고 있음 | 변환 책임을 Service로 옮김 |
| 영속성 컨텍스트 | 트랜잭션 밖에서 Lazy 접근 | 트랜잭션 안(Service)에서 변환 |

결국 두 문제 모두 ==Service에서 변환==하면 해결된다
