> "DTO 변환을 어디서 할까?" 에 대한 내 답

---

## 결정 흐름

```
DTO 변환이 필요하다
        │
        ▼
JPA Lazy Loading을 쓰고 있는가?
        │
   ┌────┴────┐
  YES        NO
   │          │
   ▼          ▼
Service 안    Entity.toDto()도
(트랜잭션)에서  허용할 수 있으나
변환한다      레이어 오염 주의
```

---

## 기준표

| 상황 | 선택 |
|---|---|
| JPA + Lazy Loading 사용 | Service에서 변환 (트랜잭션 안) |
| 변환 로직이 여러 곳에서 반복된다 | Mapper 클래스 분리 |
| 단순 조회, Eager Loading | Service 변환 기본값으로 |
| 빠른 프로토타입, 소규모 | `entity.toDto()` 허용 가능 |

---

## 실전 체크리스트

- [I] **Entity에 `toDto()` 또는 `from(dto)` 메서드가 있는가?**

Domain이 DTO를 알게 된다. 변환 책임을 Service나 Mapper로 옮긴다

<br/>

- [I] **Controller에서 Entity 필드에 직접 접근하는가?**

트랜잭션 밖이므로 Lazy 필드에서 `LazyInitializationException`이 발생할 수 있다

Service에서 DTO로 변환 후 반환한다

<br/>

- [I] **같은 변환 코드가 여러 Service에 중복되는가?**

Mapper 클래스를 분리한다
