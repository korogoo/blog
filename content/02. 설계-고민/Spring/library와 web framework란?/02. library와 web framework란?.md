
> library는 내가 주도하고, framework는 framework가 주도한다  
> ==결정적 차이는 통제권(control)이 누구에게 있느냐다==

---

## library

필요할 때 꺼내 쓰는 도구 상자다

내가 원하는 시점에, 원하는 것만 골라서 쓴다

통제권이 나에게 있다

- [I] **요리할 때 칼, 냄비, 믹서기를 필요할 때마다 꺼내 쓰는 것**

어떤 도구를 언제 쓸지는 내가 결정한다

```java
// 내가 원할 때, 원하는 것만 꺼내서 쓴다
List<String> sorted = items.stream()
    .sorted()
    .collect(Collectors.toList());
```

## web framework

이미 지어진 건물에 입주하는 것이다

건물 구조(흐름)는 이미 정해져 있다

내가 할 일은 각 방(메서드)을 내 용도에 맞게 채우는 것이다

통제권이 framework에 있다 — 이것을 **제어의 역전(IoC, Inversion of Control)** 이라고 한다

- [I] **프랜차이즈 음식점에 입점하는 것**

인테리어, 주문 방식, 운영 절차는 본사가 정한다

나는 그 안에서 메뉴만 결정한다

```java
// Spring이 이 메서드를 언제 호출할지 결정한다. 나는 내용만 채운다.
@GetMapping("/hello")
public String hello() {
    return "Hello, World!";
}
```

## 참고

Martin Fowler — *Inversion of Control Containers and the Dependency Injection pattern* (2004)

> "The question is: 'in what aspect of control are they inverting?' [...] It is this inversion of control that gives frameworks their power."

## 정리

| | library | framework |
|--|---------|-----------|
| 통제권 | 나 | framework |
| 호출 방향 | 내가 라이브러리를 호출 | framework가 내 코드를 호출 |
| 예시 | Stream API, Jackson | Spring Boot, Django |

## 핵심

`@Controller`, `@Service` 같은 어노테이션을 붙이는 것은  
"이 클래스는 이런 역할로 쓸게요"라고 Spring에게 알려주는 행위다

Spring이 그 정보를 바탕으로 객체를 생성하고, 흐름을 제어한다
