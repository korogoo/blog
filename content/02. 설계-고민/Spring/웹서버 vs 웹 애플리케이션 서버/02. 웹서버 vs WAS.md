> ==결정적 차이는 비즈니스 로직을 실행하느냐다==

---

## 웹서버 (Web Server)

정적인 파일을 제공하는 서버다

클라이언트가 요청하면 미리 만들어진 파일을 그대로 돌려준다

HTML, CSS, JavaScript, 이미지 같은 것들이다

요청마다 내용이 달라지지 않는다

대표: **Nginx, Apache HTTP Server**

---

## 웹 애플리케이션 서버 (WAS)

동적인 콘텐츠를 생성하는 서버다

클라이언트 요청에 따라 비즈니스 로직을 실행하고 그 결과를 응답한다

DB에서 데이터를 꺼내고, 계산하고, 가공해서 돌려준다

요청마다 내용이 달라진다

대표: **Tomcat, Jetty**

---

## 비교

| | 웹서버 | WAS |
|-|--------|-----|
| 하는 일 | 정적 파일 제공 | 비즈니스 로직 처리 |
| 예시 요청 | `GET /logo.png` | `GET /api/user/1` |
| 응답 내용 | 항상 같은 이미지 | 요청한 사용자의 데이터 |
| 대표 제품 | Nginx, Apache | Tomcat, Jetty |

---

## 실제로는 함께 쓴다

```
클라이언트
    ↓
Nginx (웹서버)   → 정적 파일은 직접 처리
    ↓
Tomcat (WAS)    → 동적 요청만 전달받아 처리
```

Nginx가 앞단에서 빠르게 정적 파일을 처리하고,  
동적 요청만 Tomcat으로 넘기는 구조다

---

## Spring Boot에서는?

`./gradlew bootRun`으로 실행하면 내장 Tomcat이 WAS 역할을 한다

개발 환경에서는 별도로 Nginx 같은 웹서버를 띄우지 않아도 된다

실행 로그에서 보이는 `Tomcat initialized with port 8080`이 바로 이 내장 WAS가 올라오는 시점이다

---

## 핵심

Spring Boot 애플리케이션은 WAS다

`/api/**` 요청을 받아 비즈니스 로직을 실행하고 JSON을 돌려주는 것이 WAS의 역할이다
