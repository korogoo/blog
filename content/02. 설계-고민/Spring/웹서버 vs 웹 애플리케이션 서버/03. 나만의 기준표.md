> 웹서버는 있는 것을 꺼내주고, WAS는 처리해서 만들어준다  
> ==Spring Boot 앱은 WAS다==

---

## 정리

| | 웹서버 | WAS |
|-|--------|-----|
| 하는 일 | 정적 파일 제공 | 비즈니스 로직 처리 |
| 예시 요청 | `GET /logo.png` | `GET /api/user/1` |
| 응답 내용 | 항상 같은 파일 | 요청에 따라 다른 데이터 |
| 대표 제품 | Nginx, Apache | Tomcat, Jetty |

---

## 배포 환경에서의 구성

```
클라이언트
    ↓
Nginx (웹서버)    → 정적 파일 (.html, .css, .js, 이미지) 처리
    ↓
Spring Boot (WAS) → /api/** 동적 요청 처리
```

Nginx를 앞에 두는 이유:
- [I] 정적 파일을 WAS까지 보내지 않아 WAS 부담을 줄인다
- [I] SSL 처리, 로드 밸런싱을 Nginx가 담당한다
- [I] WAS를 직접 외부에 노출하지 않아 보안에 유리하다

---

## 실전 체크리스트

- [I] **개발 환경에서 Nginx 없이 Spring Boot만 쓰는 게 맞는가?**

맞다. 개발 환경에서는 내장 Tomcat만으로 충분하다

<br/>

- [I] **Spring Boot에서 정적 파일도 서빙할 수 있는가?**

`src/main/resources/static/` 폴더에 파일을 두면 Spring Boot가 정적 파일도 제공한다

소규모 서비스에서는 별도 웹서버 없이 쓸 수 있다

<br/>

- [I] **Tomcat이 내장되어 있다는 것은 무슨 의미인가?**

별도로 Tomcat을 설치하고 설정하지 않아도 Spring Boot 실행만으로 서버가 올라온다

`spring-boot-starter-web` 의존성에 내장 Tomcat이 포함되어 있다
