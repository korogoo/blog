> "어떻게 저장하는가"를 담당한다

## 개념

DAO는 SQL, JDBC, JPA 같은 **데이터 접근 기술의 세부사항**을 캡슐화한다

호출하는 쪽은 SQL이 어떻게 생겼는지, Connection을 어디서 얻는지 알 필요 없다

```java
public class GameDao {

    private final DataSource dataSource;

    public void save(Game game) {
        String sql = "INSERT INTO game (name, status) VALUES (?, ?)";
        try (Connection conn = dataSource.getConnection();
             PreparedStatement ps = conn.prepareStatement(sql)) {
            ps.setString(1, game.getName());
            ps.setString(2, game.getStatus().name());
            ps.executeUpdate();
        } catch (SQLException e) {
            throw new RuntimeException(e);
        }
    }

    public Optional<Game> findById(Long id) {
        String sql = "SELECT * FROM game WHERE id = ?";
        // ...
    }
}
```

## 특징

- [I] **DB 기술에 종속**

JDBC, JPA, MyBatis 등 어떤 기술을 쓰는지 DAO 안에 드러난다

<br/>

- [I] **테이블 단위로 대응**

보통 테이블 하나에 DAO 하나가 대응된다 (`GameDao`, `PieceDao`)

<br/>

- [I] **CRUD 중심**

`save`, `findById`, `findAll`, `update`, `delete` 등 저장소 연산을 직접 표현한다

## 왜 쓰는가?

SQL과 비즈니스 로직을 섞지 않기 위해서다

DAO 없이 Service에 SQL이 직접 있으면, DB 기술을 바꿀 때 비즈니스 로직까지 건드려야 한다

```java
// ❌ SQL이 서비스에 섞여있다
public class GameService {
    public void createGame(String name) {
        String sql = "INSERT INTO game ..."; // ← 여기 있으면 안 된다
    }
}
```

```java
// ✅ DAO가 SQL을 담당한다
public class GameService {
    private final GameDao gameDao;

    public void createGame(String name) {
        gameDao.save(new Game(name));
    }
}
```
