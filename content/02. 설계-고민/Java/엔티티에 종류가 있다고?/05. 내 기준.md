## 엔티티 정의 분리 기준

```
새 프로젝트를 시작한다
       │
       ▼
도메인 규칙이 복잡하거나 자주 바뀔 것 같은가?
       │
  ┌────┴────┐
 YES        NO
  │          │
  ▼          ▼
분리 전략    도메인 메서드 없이 JPA 엔티티 통합 사용
```

---

## 실전 기준표

| 상황 | 선택 |
|---|---|
| 미션/토이 프로젝트, 로직 단순 | 통합 (JPA 엔티티 = 도메인 엔티티) |
| 도메인 로직 단위 테스트가 필요 | 분리 |
| DB 없이 도메인을 설명할 수 있어야 한다 | 분리 |
| JPA 기본 생성자가 도메인 불변식을 깨트린다 | 분리 |
| 빠른 프로토타이핑, 이후 리팩터링 예정 | 통합으로 시작 → 복잡해지면 분리 |

---

## 기억할 것

> 분리는 목적이 아니라 수단이다  
> 
> 도메인을 DB로부터 보호해야 할 이유가 생겼을 때 분리한다
