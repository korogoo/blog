> 어떤 계층에서 다루느냐에 따라 DB 엔티티 / 도메인 엔티티 / JPA 엔티티로 나뉜다

---

## DB 엔티티

> 데이터베이스에 저장되는 테이블과 행(Row)의 단위

```sql
CREATE TABLE member (
    id       BIGINT AUTO_INCREMENT PRIMARY KEY,
    email    VARCHAR(100) NOT NULL UNIQUE,
    password VARCHAR(255) NOT NULL,
    created_at TIMESTAMP NOT NULL
);
```

- 관심사: **영속성** - 데이터를 어떻게 저장하고 조회할 것인가
- 행동(메서드)이 없다. 컬럼과 관계만 있다

---

## 도메인 엔티티

> 비즈니스 규칙과 행동을 담은 객체. 식별자로 구별한다

```java
public class Member {
    private final MemberId id;
    private Email email;
    private Password password;

    public void changeEmail(Email newEmail) {
        // 비즈니스 규칙: 인증된 이메일만 허용
        if (!newEmail.isVerified()) {
            throw new InvalidEmailException();
        }
        this.email = newEmail;
    }
}
```

- 관심사: **행동** - 이 개념이 무엇을 할 수 있는가
- DB 구조를 몰라도 된다. 테이블이 어떻게 생겼는지 알 필요 없다

---

## JPA 엔티티

> ORM이 도메인 객체를 DB 테이블에 매핑하기 위해 사용하는 클래스

```java
@Entity
@Table(name = "member")
public class MemberJpaEntity {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false, unique = true)
    private String email;

    @Column(nullable = false)
    private String password;

    @Column(nullable = false)
    private LocalDateTime createdAt;
}
```

- 관심사: **매핑** - DB 구조와 자바 객체를 어떻게 연결할 것인가
- 도메인 엔티티도, DB 엔티티도 아니다. 둘 사이의 변환 역할이다
