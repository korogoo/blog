> 인터페이스 순환참조는 컴파일러가 막지 않는다  
> ==생겼다면 의존 방향을 단방향으로 정리해야 한다는 신호다==

---

## 순환참조 감지 시점

| 종류 | 감지 시점 |
|------|---------|
| 인터페이스 순환참조 | 컴파일 통과, 런타임도 문제없음 |
| 클래스(Bean) 순환참조 | Spring 컨텍스트 로딩 시 (런타임 오류) |
| Spring Boot 2.6+ | 기본적으로 Bean 순환참조를 시작 시 감지하고 거부 |

---

## 인터페이스 순환 발생 시 해결 방법

```
A ←→ B  (순환)
```

- [I] **의존 방향을 한쪽으로 정한다**

```
A → B  (단방향)
```

A가 B를 알고, B는 A를 모르게 한다

<br/>

- [I] **중간 추상화를 도입한다**

```
A → C ← B
```

두 개념이 공통으로 의존할 수 있는 새로운 인터페이스 C를 만든다

---

## 실전 체크리스트

- [I] **인터페이스 두 개가 서로를 타입으로 참조하고 있는가?**

컴파일은 되지만, 이 두 개념이 정말 서로를 알아야 하는지 다시 생각한다

<br/>

- [I] **Spring Bean 순환참조 오류가 나는가?**

`application.properties`에 `spring.main.allow-circular-references=true`로 임시 우회할 수 있지만, 근본 원인(설계 문제)을 해결하는 것이 맞다

<br/>

- [I] **순환을 끊기 어렵다면?**

두 클래스가 하나의 책임을 나눠 갖고 있는 것일 수 있다

하나로 합치거나, 제3의 클래스로 공통 로직을 분리한다
