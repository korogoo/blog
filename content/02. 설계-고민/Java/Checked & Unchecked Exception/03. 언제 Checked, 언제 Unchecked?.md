## 기준

- [I] **회복 가능한 상황 → Checked**

호출자가 예외를 인지하고 대응할 수 있는 경우

파일이 없으면 다른 경로를 시도하거나, 네트워크 오류면 재시도하거나

컴파일러가 강제하는 이유도 여기에 있다 — ==처리하지 않으면 안 된다는 신호==

<br/>

- [I] **회복 불가능한 상황 → Unchecked**

프로그래밍 실수이거나, 호출자가 어떻게 해도 복구할 수 없는 경우

`null` 이 들어오면 안 되는 곳에 `null` 이 들어온 경우, 비즈니스 규칙 위반 등

---

## Checked → Unchecked 래핑 패턴

`SQLException` 같은 Checked 예외를 `RuntimeException` 으로 감싸 전파하는 패턴

```java
} catch (SQLException e) {
    throw new RuntimeException(e); // Checked → Unchecked 변환
}
```

> 이렇게 하는 이유는?

`SQLException` 은 JDBC 의 구현 세부사항이다  
상위 레이어(Service, Controller)가 `SQLException` 을 알 필요가 없다  
==계층 간 의존성을 끊기 위해== Unchecked 로 변환해 전파한다
