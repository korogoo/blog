> Java 예외는 크게 ==Checked== 와 ==Unchecked== 로 나뉜다
> 기준은 `RuntimeException` 을 상속하느냐 아니냐

---

## 계층 구조

```
Throwable
├── Error                          ← unchecked (JVM 수준, 복구 불가)
└── Exception
    ├── RuntimeException           ← unchecked
    │   ├── IllegalArgumentException
    │   ├── IllegalStateException
    │   ├── NullPointerException
    │   └── ...
    └── IOException                ← checked
    └── SQLException               ← checked
    └── ...
```

---

## Checked Exception

> 컴파일러가 ==처리를 강제==한다

`throws` 로 선언하거나, try-catch 로 처리하지 않으면 컴파일 에러가 난다

```java
public void readFile(String path) throws IOException { // 선언하거나
    Files.readAllBytes(Path.of(path));
}

public void readFile(String path) {
    try {                                              // 처리하거나
        Files.readAllBytes(Path.of(path));
    } catch (IOException e) {
        ...
    }
}
```

대표 클래스: `IOException`, `SQLException`, `ClassNotFoundException`

---

## Unchecked Exception

> 컴파일러가 ==처리를 강제하지 않는다==

선언하지 않아도 컴파일되고, try-catch 없이도 동작한다

```java
public void move(int index) {
    if (index < 0) {
        throw new IllegalArgumentException("인덱스는 0 이상이어야 합니다");
    }
}
```

대표 클래스: `IllegalArgumentException`, `IllegalStateException`, `NullPointerException`, `IndexOutOfBoundsException`

---

## 한눈에 비교

| 구분 | Checked | Unchecked |
| ---- | ------- | --------- |
| 상위 클래스 | `Exception` | `RuntimeException` |
| 컴파일러 강제 | O | X |
| 주요 원인 | 외부 환경 (파일, DB, 네트워크) | 프로그래밍 실수, 비즈니스 규칙 위반 |
| 대표 클래스 | `IOException`, `SQLException` | `IllegalArgumentException`, `NullPointerException` |
