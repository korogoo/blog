> try-catch 는 ==예외 처리== 를 위한 것이지, ==흐름 제어== 를 위한 것이 아니다

---

## 흐름 제어에 쓰면 안 되는 이유

```java
// 나쁜 예 — try-catch 로 이동 가능 여부를 판단
public void move(Position from, Position to) {
    try {
        route.validate(from, to); // 내부에서 예외 던짐
        executeMove(from, to);
    } catch (InvalidMoveException e) {
        // 이동 불가 처리
    }
}
```

이 코드를 읽는 사람은 `route.validate()` 내부까지 들어가야 어떤 예외가 왜 던져지는지 알 수 있다

==의도가 숨겨진다==

---

## 명시적 메서드로 대체

```java
// 좋은 예 — canMove() 로 명시적으로 판단
public void move(Position from, Position to) {
    if (!route.canMove(from, to)) {
        // 이동 불가 처리
        return;
    }
    executeMove(from, to);
}
```

> 코드만 봐도 "이동 가능 여부를 먼저 확인한다" 는 의도가 읽힌다

---

## 카프카 코멘트 — PR #245

> "try-catch 블록은 의도를 숨긴다. 독자가 내부 메서드까지 따라가야 예외 출처를 알 수 있다"
> "`canMove()` 같은 명시적 메서드를 쓰는 게 낫다"

---

## 예외는 언제 써야 하나?

> ==정말 예외적인 상황==에만 사용한다

- 프로그램이 예측하지 못한 상황
- 호출자가 반드시 인지해야 하는 오류

정상 흐름의 분기 처리는 `if` 로 한다
