> 예외도 ==레이어의 책임==이 있다
> 어디서 던지고, 어디서 잡느냐를 구분해야 한다

---

## 개념

- [I] **인프라 예외**

DB, 네트워크, 파일 등 외부 시스템과의 통신에서 발생

`SQLException`, `IOException`, `DataAccessException`

<br/>

- [I] **비즈니스 예외**

도메인 규칙 위반에서 발생

`BoardNotFoundException`, `DuplicateGameException`, `InvalidMoveException`

---

## 왜 구분해야 하나?

```java
// 나쁜 예 — UPDATE 대상이 없을 때 인프라 예외를 던짐
public void update(Long boardId, ...) {
    int affected = jdbcTemplate.update(...);
    if (affected == 0) {
        throw new DataAccessException("업데이트 실패"); // DB 오류? 비즈니스 오류?
    }
}
```

> "UPDATE 대상이 없다는 건 DB 오류가 아니라 비즈니스 오류 아닌가요?" — NewWisdom

`DataAccessException` 은 DB 접근 자체가 실패했을 때 쓰는 것  
데이터가 없는 건 도메인 규칙의 문제다

---

## 개선

```java
// 서비스 레이어에서 먼저 검증
public void updateBoard(Long boardId, ...) {
    validateBoardExists(boardId);    // 없으면 BoardNotFoundException (비즈니스 예외)
    boardDao.update(boardId, ...);   // 여기서 DataAccessException 나면 진짜 DB 오류
}
```

---

## 레이어별 예외 책임

| 레이어 | 예외 역할 |
| ------ | --------- |
| DAO / Repository | 인프라 예외 catch → Unchecked 로 래핑해 전파 |
| Service | 비즈니스 예외 던지기, 인프라 예외 처리 |
| Controller | 예외 catch → 사용자 응답으로 변환 |
