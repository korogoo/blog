> 의존성을 선언할 때 "이게 언제 필요한가"를 먼저 묻는다  
> ==스코프는 추측이 아니라 사용 시점으로 결정한다==

---

## 스코프 결정 흐름

```
이 라이브러리가 필요한가?
         │
    ┌────┴──────────────────────┐
  컴파일 시점                런타임에만
    │                           │
    ├─ 소스코드에서 import?       └─ runtimeOnly
    │    │
    │    ├─ 테스트에서만? → testImplementation
    │    │
    │    ├─ 컴파일에만 필요 (런타임엔 불필요)?
    │    │    └─ compileOnly (+ annotationProcessor)
    │    │
    │    └─ 컴파일 + 런타임 모두? → implementation
    │
    └─ 어노테이션 처리만? → annotationProcessor
```

---

## 스코프 기준표

| 상황 | 스코프 |
|------|--------|
| 소스코드에서 `import`해서 쓴다 | `implementation` |
| JDBC 드라이버처럼 런타임에 JVM이 찾는다 | `runtimeOnly` |
| JUnit, Mockito 등 테스트 도구 | `testImplementation` |
| Lombok처럼 컴파일 시 코드 생성 후 불필요 | `compileOnly` |
| Lombok, QueryDSL 어노테이션 처리기 | `annotationProcessor` |
| JUnit Platform Launcher 등 테스트 실행기 | `testRuntimeOnly` |

---

## build / clean 기준표

| 상황 | 명령 |
|------|------|
| 처음 빌드하거나 코드 변경 후 실행 | `./gradlew build` |
| 이상한 빌드 오류가 날 때 | `./gradlew clean build` |
| jar 없이 테스트만 실행하고 싶을 때 | `./gradlew test` |
| 빌드 산출물만 지우고 싶을 때 | `./gradlew clean` |

## 실전 체크리스트

- ✨ **`ClassNotFoundException`이 뜨는가?**

해당 클래스의 jar가 classpath에 없다. 의존성 선언과 스코프를 확인한다

<br/>

- ✨ **배포 jar가 너무 큰가?**

테스트 도구가 `implementation`으로 선언됐는지 확인한다. `testImplementation`으로 옮긴다

<br/>

- ✨ **Lombok이 동작하지 않는가?**

`compileOnly`와 `annotationProcessor` 두 줄이 함께 선언됐는지 확인한다

<br/>

- ✨ **의존성 추가 후에도 에러가 나는가?**

IntelliJ Gradle 새로고침(코끼리 버튼)을 눌렀는지 확인한다

<br/>

- ✨ **"고쳤는데 반영이 안 돼" 상황인가?**

`./gradlew clean build`로 이전 결과물을 지우고 처음부터 다시 빌드한다

<br/>

- ✨ **전이 의존성을 확인하고 싶은가?**

`./gradlew dependencies --configuration compileClasspath`로 의존성 트리를 확인한다
