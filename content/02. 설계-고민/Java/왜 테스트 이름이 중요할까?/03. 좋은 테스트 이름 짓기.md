> 테스트 이름은 ==조건과 결과가 드러나야 한다==

---

## 패턴

### 패턴 1: 조건 + 결과

```
[조건]이면_[결과]다

출발지와_도착지가_같으면_이동할_수_없다
경로에_기물이_없으면_포는_이동할_수_없다
```

### 패턴 2: 주어 + 행위 + 결과

```
[주어]는_[조건]에서_[결과]다

포는_기물이_정확히_하나인_경로를_넘어_이동할_수_있다
병은_앞으로만_이동할_수_있다
```

### 패턴 3: 동작 + 예외

```
[잘못된 상태]에서_[동작]하면_예외가_발생한다

기물이_없는_위치에서_이동하면_예외가_발생한다
이동_불가능한_위치로_이동하면_예외가_발생한다
```

## @DisplayName 활용

한글 메서드명이 불편하거나, 더 자세한 설명이 필요할 때 `@DisplayName`을 사용한다

```java
@Test
@DisplayName("포는 정확히 기물 하나를 넘어야 이동할 수 있다")
void cannon_must_jump_over_exactly_one_piece() { ... }
```

단, 메서드명과 `@DisplayName`이 다르면 혼란스럽다

→ 둘 중 하나에 의미를 집중하거나, 같은 내용을 두 언어로 표현한다

## DisplayName 오탈자 주의

```java
// ❌ — 오탈자가 있으면 명세서로서 신뢰를 잃는다
@DisplayName("포느 이동할 수 이뜨다")

// ✅ — 정확하게 작성
@DisplayName("포는 이동할 수 있다")
```

## 피해야 할 이름들

| 이름 | 문제 |
|---|---|
| `test1`, `test2` | 순서 외에 아무 정보도 없음 |
| `정상_케이스` | "정상"이 무엇인지 모름 |
| `이동_테스트` | 무엇을 테스트하는지 모름 |
| `실패_케이스` | 어떤 실패인지 모름 |
| `testMove` | 영어로도 의미 없음 |

## 테스트 이름 리뷰 질문

> "이 이름만 보고 어떤 규칙이 검증되는지 알 수 있는가?"

→ **YES** → 좋은 이름  
→ **NO** → 조건과 결과를 이름에 담는다
