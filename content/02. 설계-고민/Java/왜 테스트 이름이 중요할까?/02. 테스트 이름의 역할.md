
> 테스트 이름은 ==실행 가능한 명세(Specification)==다  
> 이름만 봐도 "이 코드가 어떤 규칙을 따르는지" 알 수 있어야 한다

---

## 개념

테스트는 두 가지 역할을 한다

1. **코드가 올바른지 검증한다**
2. **이 코드가 어떻게 동작해야 하는지 문서화한다**

이름이 나쁘면 첫 번째 역할만 하고, 두 번째 역할은 포기하는 것이다

---

## 나쁜 이름 vs 좋은 이름

```java
// ❌ — 무엇을 테스트하는지 알 수 없다
@Test
void test1() { ... }

@Test
void 정상_범위_테스트() { ... }

@Test
void 이동_테스트() { ... }
```

```java
// ✅ — 이름만 봐도 규칙이 보인다
@Test
void 병은_앞으로_한_칸만_이동할_수_있다() { ... }

@Test
void 포는_반드시_기물_하나를_넘어야_이동할_수_있다() { ... }

@Test
void 같은_진영의_기물_위치로는_이동할_수_없다() { ... }
```

---

## 왜 이름이 중요한가

- [I] **테스트가 실패했을 때 무엇이 문제인지 바로 안다**

`정상_범위_테스트` 실패 → "뭐가 문제야?"  
`포는_반드시_기물_하나를_넘어야_이동할_수_있다` 실패 → "포 이동 규칙에 문제가 생겼다"

<br/>

- [I] **요구사항이 테스트 이름으로 문서화된다**

코드를 읽지 않아도 테스트 목록만 보면 이 클래스의 규칙을 파악할 수 있다

<br/>

- [I] **중복 테스트를 방지한다**

이름이 명확하면 같은 규칙을 두 번 테스트하는 것을 발견하기 쉽다

---

## 좋은 이름의 구성

```
[주어]는/이 [조건]이면/일 때 [결과]다

예)
포는 경로에 기물이 없으면 이동할 수 없다
병은 앞으로만 이동할 수 있다
같은 위치로 이동하면 예외가 발생한다
```
