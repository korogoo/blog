## 패턴별 해결

👎 패턴 1: 체이닝으로 내부 탐색

```java
int score = game.getBoard().getPieces().stream()
    .mapToInt(p -> p.getSide().getScore())
    .sum();
```

👍 Board에게 일을 시킨다
```java
int score = game.calculateScore();

// Game 안에서
public int calculateScore() {
    return board.sumScore();
}

// Board 안에서
public int sumScore() {
    return pieces.values().stream()
        .mapToInt(Piece::getScore)
        .sum();
}
```

---

👎 패턴 2: getter 체이닝으로 조건 확인

```java
if (game.getBoard().getPieces().get(pos).getSide() == Side.HAN) { ... }
```

👍 Board에게 물어본다
```java
if (game.isHanAt(pos)) { ... }
```

---

👎 패턴 3: stream()을 외부로 노출

```java
// 내부 컬렉션의 stream을 꺼내줌 → 호출자가 내부를 마음대로 처리
public Stream<Piece> getPieceStream() {
    return pieces.stream();
}

// 호출부
board.getPieceStream()
    .filter(p -> p.getSide() == side)
    .count();
```

👍 필요한 결과를 Board 안에서 계산
```java
public long countBySide(Side side) {
    return pieces.values().stream()
        .filter(p -> p.getSide() == side)
        .count();
}
```

## 주의: 디미터의 법칙 예외

**점이 두 개여도 문제없는 경우**가 있다

```java
// 빌더 패턴 (같은 객체를 반환하는 체이닝)
Game.builder()
    .name("장기")
    .status(Status.RUNNING)
    .build();

// 스트림 (중간 연산 체이닝)
pieces.stream()
    .filter(...)
    .map(...)
    .collect(toList());
```

객체 구조를 **탐색**하는 것이 문제이지, **같은 타입을 반환하는 체이닝**은 다른 개념이다
