> 디미터의 법칙 — ==내가 직접 아는 객체의 메서드만 호출한다==  
> "한 줄에 점을 하나만 찍는다"로 기억하면 쉽다

---

## 개념

디미터의 법칙(Law of Demeter, LoD): 객체는 자신과 **직접 연결된** 객체에만 메시지를 보낸다

```
메서드 M에서 호출해도 되는 대상:
  1. M이 속한 클래스 자신 (this)
  2. M의 파라미터로 받은 객체
  3. M 안에서 직접 생성한 객체
  4. 클래스의 인스턴스 변수
```

---

## 위반 예시

- ⚠️ 기차 충돌(Train Wreck) 코드

```java
String color = board.getPieces().get(position).getSide().getColor();
//                    └─ Board 내부               └─ Piece 내부 └─ Side 내부
//          Board → Piece → Side → Color 까지 줄줄이 의존
```

이 코드는 `Board`의 내부 구조(`Map<Position, Piece>`)를 알고,  
`Piece`의 내부 구조(`Side`)를 알고,  
`Side`의 내부 구조(`Color`)를 알아야 한다

`Side`에 `Color`가 없어지면 이 코드도 바꿔야 한다

---

## 준수 예시

- 👍 Board에게 "이 위치의 색이 뭐야?"라고 바로 묻는다

```java
String color = board.getColorAt(position);
```

```java
// Board 안에서 처리
public String getColorAt(Position position) {
    return pieces.get(position).getColor();
}
```

호출하는 쪽은 Board 내부 구조를 전혀 몰라도 된다

---

## 왜 중요한가?

- ✨ **결합도를 낮춘다**

`board.getPieces().get(position).getSide().getColor()`는  
Board, Piece, Side의 내부 구조 모두에 결합되어 있다

하나만 바뀌어도 이 코드가 깨진다

<br/>

- ✨ **변경 범위를 줄인다**

Board 내부가 바뀌어도 Board 밖에는 영향이 없어야 한다

<br/>

- ✨ **캡슐화를 강제한다**

getter로 내부를 꺼내지 않고, 객체에게 일을 시키게 된다 (Tell, Don't Ask)
