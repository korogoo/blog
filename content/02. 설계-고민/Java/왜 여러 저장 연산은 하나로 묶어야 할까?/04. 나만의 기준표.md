> "이 연산들을 트랜잭션으로 묶어야 할까?" 에 대한 내 답

---

## 핵심 질문

> "이 중 하나가 실패했을 때, 나머지 연산이 완료된 상태가 도메인적으로 의미 있는가?"

→ **없다** → 트랜잭션으로 묶는다  
→ **있다** → 별도 트랜잭션으로 분리 가능

---

## 결정 흐름

```
여러 저장 연산이 있다
        │
        ▼
하나가 실패하면 나머지도 롤백해야 하는가?
        │
   ┌────┴────┐
  YES        NO
   │          │
   ▼          ▼
트랜잭션으로  각각 별도
묶는다       트랜잭션
```

---

## 트랜잭션 관리 방법 선택

| 환경 | 방법 |
|---|---|
| Spring 환경 | `@Transactional` |
| 순수 JDBC, Spring 없음 | `ThreadLocal<Connection>` 또는 `Connection` 직접 관리 |
| 인터페이스 추상화 유지 필요 | Connection을 파라미터에서 제거 |

---

## 인터페이스 설계 기준

| 설계 | 판단 |
|---|---|
| `void save(Game game, Connection conn)` | ❌ 기술 노출 |
| `void save(Game game)` | ✅ 기술 숨김 |
| `void save(Game game, TransactionContext ctx)` | ⚠️ 도메인 추상화라면 허용 가능 |

---

## 실전 체크리스트

✨ **두 개 이상의 저장 연산이 같은 메서드에 있는가?**

하나가 실패했을 때의 상태를 생각해본다

<br/>

✨ **Repository 인터페이스에 Connection이 있는가?**

구현 기술을 인터페이스 밖으로 빼낸다

<br/>

✨ **ThreadLocal을 쓴다면 `remove()`를 호출하는가?**

finally 블록에서 반드시 정리한다

<br/>

✨ **모든 예외를 `catch (Exception e)`로 잡는가?**

복구 가능한 예외와 불가능한 예외를 구분한다
