> 트랜잭션은 ==여러 연산을 하나의 작업 단위로 묶는 것==이다  
> 전부 성공하거나, 전부 실패하거나 — 중간 상태는 없다

---

## 개념

트랜잭션의 4가지 특성 (ACID):

| 특성 | 의미 |
|---|---|
| **A**tomicity (원자성) | 전부 성공 or 전부 실패, 중간 상태 없음 |
| **C**onsistency (일관성) | 트랜잭션 전후 DB 규칙이 유지됨 |
| **I**solation (격리성) | 동시 실행 트랜잭션이 서로 간섭하지 않음 |
| **D**urability (지속성) | 커밋된 데이터는 장애가 나도 보존됨 |

---

## 트랜잭션 없이 여러 연산을 실행하면?

```java
// ❌ — 트랜잭션 없이 두 연산을 순서대로 실행
gameDao.save(game);       // 성공
pieceDao.saveAll(pieces); // 실패 — 게임은 저장됐지만 기물은 없다!
```

이 상황에서 DB는 게임만 있고 기물이 없는 **반쪽짜리 상태**가 된다

---

## 트랜잭션을 적용하면

```java
// ✅ — Connection.setAutoCommit(false)로 트랜잭션 시작
try (Connection conn = dataSource.getConnection()) {
    conn.setAutoCommit(false);

    gameDao.save(conn, game);
    pieceDao.saveAll(conn, pieces);

    conn.commit(); // 모두 성공 → 커밋
} catch (Exception e) {
    conn.rollback(); // 하나라도 실패 → 롤백
}
```

둘 다 성공하면 커밋, 하나라도 실패하면 처음 상태로 롤백

---

## 트랜잭션이 필요한 신호

- ✨ **두 개 이상의 INSERT/UPDATE/DELETE가 하나의 비즈니스 행위를 구성한다**

게임 저장 + 기물 저장, 이체(출금 + 입금) 등

<br/>

- ✨ **중간에 실패하면 데이터가 불일치해진다**

한쪽만 반영된 DB 상태가 도메인적으로 의미가 없다
