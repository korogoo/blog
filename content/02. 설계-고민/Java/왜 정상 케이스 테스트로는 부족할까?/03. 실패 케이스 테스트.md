> 실패 케이스 테스트는 ==예외 처리가 제대로 됐는지 검증한다==  
> 정상 케이스만 있으면 방어 코드가 올바른지 알 수 없다

---

## 왜 실패 케이스가 필요한가

정상 케이스 테스트만으로는

- 예외가 올바른 시점에 발생하는지 모른다
- 예외 메시지가 적절한지 모른다
- 방어 코드가 실제로 동작하는지 모른다

---

## 예시

```java
// 정상 케이스만 있는 경우 — 방어 코드가 실제로 동작하는지 알 수 없다
@Test
void 이동_성공() {
    Board board = new Board(...);
    board.move(Position.of(1, 1), Position.of(1, 3));
    // 성공하면 이 테스트는 통과 — 하지만 방어 코드를 검증하지 않는다
}
```

```java
// ✅ 실패 케이스 추가
@Test
void 같은_위치로_이동하면_예외가_발생한다() {
    Board board = new Board(...);

    assertThatThrownBy(() -> board.move(Position.of(1, 1), Position.of(1, 1)))
        .isInstanceOf(IllegalArgumentException.class)
        .hasMessageContaining("같은 위치");
}

@Test
void 기물이_없는_위치에서_이동하면_예외가_발생한다() {
    Board board = new Board(Map.of()); // 빈 보드

    assertThatThrownBy(() -> board.move(Position.of(1, 1), Position.of(1, 3)))
        .isInstanceOf(IllegalArgumentException.class);
}

@Test
void 이동_불가능한_위치로_이동하면_예외가_발생한다() {
    Board board = new Board(...);

    assertThatThrownBy(() -> board.move(Position.of(1, 1), Position.of(5, 5)))
        .isInstanceOf(IllegalArgumentException.class);
}
```

---

## 예외 검증 방법

```java
// assertThatThrownBy — 예외 타입 + 메시지 검증
assertThatThrownBy(() -> doSomething())
    .isInstanceOf(IllegalArgumentException.class)
    .hasMessageContaining("기대하는 메시지");

// assertThatCode — 예외가 발생하지 않는 경우 검증
assertThatCode(() -> doSomething())
    .doesNotThrowAnyException();
```

---

## 실패 케이스 식별 방법

```
1. 메서드의 검증 조건(if + throw) 하나마다 테스트 하나
2. null 파라미터
3. 빈 컬렉션
4. 타입 불일치, 범위 초과
5. 순서가 잘못된 상태 전환 (PENDING 아닌 상태에서 pay() 호출)
```
