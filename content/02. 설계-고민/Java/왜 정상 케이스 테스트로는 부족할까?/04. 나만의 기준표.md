> "어떤 테스트를 작성할까?" 에 대한 내 답

---

## 테스트 체크리스트

메서드 하나를 테스트할 때 아래를 확인한다

✨ **정상 케이스** — 기대대로 동작하는가?

<br/>

✨ **실패 케이스** — 잘못된 입력에 올바른 예외가 발생하는가?

검증 조건(if + throw)마다 테스트 하나씩

<br/>

✨ **경계값** — 범위의 끝에서 올바르게 동작하는가?

min, max, min-1, max+1

<br/>

✨ **예외 케이스** — null, 빈 컬렉션, 잘못된 순서 등

---

## 테스트 완성도 확인 질문

> "이 테스트들이 통과하면 이 메서드가 올바르다고 확신할 수 있는가?"

→ YES → 테스트 완성  
→ NO → 빠진 케이스를 찾는다

---

## 흔한 실수

| 실수 | 올바른 접근 |
|---|---|
| 정상 케이스만 작성 | 실패 케이스 + 경계값 추가 |
| 예외 여부만 확인 (`assertThatThrownBy`) | 예외 타입 + 메시지까지 검증 |
| 경계와 무관한 랜덤 값으로 실패 테스트 | 실제 경계값(0, 9, 10 등)을 사용 |
| 두 개의 다른 검증이 한 테스트에 | 테스트를 분리한다 |

---

## 실전 체크리스트

✨ **각 `if + throw` 블록마다 테스트가 있는가?**

방어 코드가 실제로 동작하는지 검증한다

<br/>

✨ **경계값(min, max, min-1, max+1)이 테스트됐는가?**

정상 범위 중간값으로는 경계 버그를 잡을 수 없다

<br/>

✨ **null, 빈 컬렉션 케이스가 있는가?**

NPE와 빈 컬렉션 처리를 검증한다

<br/>

✨ **`true/false`가 바뀌는 경계 케이스가 있는가?**

조건 분기의 양쪽을 모두 테스트한다
