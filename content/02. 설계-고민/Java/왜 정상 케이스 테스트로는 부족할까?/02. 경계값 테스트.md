> 경계값 테스트는 ==버그가 가장 많이 숨어있는 곳==을 집중 검증한다  
> 정상 범위 한가운데가 아닌, 경계 지점이 핵심이다

---

## 개념

대부분의 버그는 범위의 **끝 지점**에서 발생한다

```
이동 가능 범위: 1~9
```

| 테스트 값 | 종류 |
|---|---|
| 0 | 경계 밖 (하한 - 1) |
| 1 | 경계 (하한) |
| 5 | 정상 범위 중간 |
| 9 | 경계 (상한) |
| 10 | 경계 밖 (상한 + 1) |

정상 범위 중간(5)만 테스트하면 경계 오류를 잡을 수 없다

---

## 예시: 장기 좌표 유효성 검증

```java
// 장기판: 행 1~10, 열 1~9
@Test
void 유효한_최소_좌표는_통과한다() {
    assertDoesNotThrow(() -> new Position(1, 1));
}

@Test
void 유효한_최대_좌표는_통과한다() {
    assertDoesNotThrow(() -> new Position(10, 9));
}

@Test
void 행이_0이면_예외가_발생한다() {
    assertThatThrownBy(() -> new Position(0, 1))
        .isInstanceOf(IllegalArgumentException.class);
}

@Test
void 열이_10이면_예외가_발생한다() {
    assertThatThrownBy(() -> new Position(1, 10))
        .isInstanceOf(IllegalArgumentException.class);
}
```

---

## 랜덤 값으로 부정 테스트를 하면?

```java
// ❌ — 뭘 테스트하는지 불분명하다
@Test
void 이동_실패_테스트() {
    assertThatThrownBy(() -> new Position(50, 30)) // 랜덤한 범위 밖 값
        .isInstanceOf(IllegalArgumentException.class);
}
```

이 테스트는 "경계(0, 10, 11...)에서도 실패하는가"를 보장하지 않는다

**경계값 테스트가 아닌 랜덤한 실패 확인**은 무엇을 보장하는지 불분명하다

---

## 경계값 식별 방법

```
1. 범위가 있는 값: min, max, min-1, max+1
2. 컬렉션: 0개, 1개, 최대 크기, 최대+1
3. 문자열: 빈 문자열, null, 최대 길이, 최대+1
4. 조건 분기: 조건이 true/false로 바뀌는 지점
```
