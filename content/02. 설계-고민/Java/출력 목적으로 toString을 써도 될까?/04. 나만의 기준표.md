> "toString()을 여기에 써도 될까?" 에 대한 내 답

---

## 핵심 질문

> "이 `toString()`이 사용자를 위한 것인가, 개발자를 위한 것인가?"

→ **개발자(디버그/로그)** → `toString()` 적합  
→ **사용자(화면 출력/렌더링)** → 별도 메서드나 Renderer

---

## 판단 기준표

| 상황 | toString() 사용 |
|---|---|
| 로거에 객체 상태를 남긴다 | ✅ 적합 |
| IDE 디버거에서 객체를 확인한다 | ✅ 적합 |
| 테스트 실패 메시지에서 객체를 표현한다 | ✅ 적합 |
| 사용자 콘솔에 출력한다 | ❌ 별도 메서드 |
| 화면/API 응답에 포함한다 | ❌ DTO/Renderer |
| `System.out.println(obj)`에서 포맷이 중요하다 | ❌ 별도 메서드 |

---

## toString() 구현 기준

✨ **디버깅에 유용한 정보를 담는다**

타입, 핵심 필드값 — "이 객체가 어떤 상태인지" 한 눈에 파악할 수 있게

<br/>

✨ **사용자 화면 포맷에 맞추지 않는다**

출력 포맷은 언제든 바뀔 수 있다. `toString()`은 안정적이어야 한다

<br/>

✨ **`@Override`를 붙인다**

`toString()`을 재정의한다는 의도를 명시한다

---

## 실전 체크리스트

✨ **`System.out.print(obj.toString())` 또는 `System.out.print(obj)`가 있는가?**

출력 목적이라면 별도 표현 메서드 또는 Renderer로 분리한다

<br/>

✨ **`toString()`이 화면 렌더링 포맷에 맞춰 구현되어 있는가?**

로깅 라이브러리가 호출할 때 의도치 않은 포맷이 나올 수 있다

<br/>

✨ **출력 포맷과 디버그 포맷이 같은가?**

분리하면 각각 독립적으로 바꿀 수 있다
