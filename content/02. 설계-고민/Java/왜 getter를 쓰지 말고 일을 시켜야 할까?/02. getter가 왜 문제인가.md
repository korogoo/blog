
> getter는 ==캡슐화를 깨는 문==이다  
> 값을 꺼내는 순간, 판단 로직이 객체 밖으로 새어나간다

---

## 문제의 본질

getter가 있으면 호출자가 꺼낸 값으로 스스로 판단하게 된다

그 판단 로직이 여기저기 흩어지고, 객체 안에 있어야 할 책임이 바깥으로 빠진다

```java
// ❌ — 값을 꺼내서 외부에서 판단
if (piece.getSide() == Side.HAN) {
    score += piece.getScore();
}

// 이 로직이 컨트롤러, 서비스, 유틸 여기저기에 흩어진다
```

---

## "값을 꺼낸다"가 왜 문제인가

```java
// ❌ — Board가 Piece의 내부를 꺼내서 판단한다
Piece piece = board.getPiece(position);
if (piece.getSide() == currentSide) {
    piece.move(to);
}
```

`Board`가 `Piece.side`를 알아야 하는 상황이다

`Piece`의 `side` 필드가 바뀌면 `Board`도 바뀐다

→ 높은 결합도

---

## getter를 없애면 어떻게 하나

객체에게 판단을 시킨다

```java
// ✅ — Piece에게 "네가 이 진영이야?"를 물어본다
if (piece.isOwnedBy(currentSide)) {
    piece.move(to);
}
```

```java
// ✅ — 점수 계산도 Piece에게 시킨다
int score = piece.calculateScore();
```

---

## "불변이면 getter를 써도 되는 것 아닌가?"

> 불변 여부와 getter의 문제는 별개다

불변 객체라도 getter로 값을 꺼내면 판단 로직이 밖으로 새어나가는 건 마찬가지다

```java
// ❌ — 불변 객체여도 판단 로직이 밖에 있으면 문제
final String name = player.getName();
if (name.startsWith("관리자")) {
    grant(ADMIN_ROLE);
}
```

```java
// ✅ — Player에게 시킨다
if (player.isAdmin()) {
    grant(ADMIN_ROLE);
}
```

---

## `get~`이 아니어도 getter다

메서드 이름이 `get`으로 시작하지 않아도, 내부 값을 꺼내서 반환하면 getter다

```java
// ❌ — 이름은 달라도 getter
public String name() { return this.name; }
public Side side() { return this.side; }
```

> 이름이 아니라 **값을 꺼내서 외부가 판단하는가**가 기준이다
