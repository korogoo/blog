> `stream()`을 외부로 반환하면 ==일급 컬렉션을 만든 의미가 없어진다==

---

## 문제

```java
// ❌ — stream을 그대로 반환
public class Pieces {
    private final List<Piece> pieces;

    public Stream<Piece> stream() {     // ← 내부를 그대로 노출
        return pieces.stream();
    }
}

// 호출하는 쪽이 다시 직접 처리
pieces.stream()
    .filter(p -> p.getSide() == Side.HAN)
    .mapToInt(Piece::getScore)
    .sum();
```

이 코드는 `Pieces` 밖에서 필터링과 집계를 직접 한다

`Pieces`가 있는 의미가 없다

---

## 해결

```java
// ✅ — 필요한 연산을 메서드로 제공
public class Pieces {
    private final List<Piece> pieces;

    public int totalScoreOf(Side side) {
        return pieces.stream()
            .filter(p -> p.isOwnedBy(side))
            .mapToInt(Piece::getScore)
            .sum();
    }

    public boolean hasKingOf(Side side) {
        return pieces.stream()
            .anyMatch(p -> p.isKing() && p.isOwnedBy(side));
    }

    public List<Piece> getOwnedBy(Side side) {        // 꺼내야 한다면 복사본
        return pieces.stream()
            .filter(p -> p.isOwnedBy(side))
            .collect(toList());
    }
}
```

## 컬렉션 자체를 반환해야 한다면?

```java
// ❌ — 내부 리스트를 그대로 반환 (외부에서 수정 가능)
public List<Piece> getPieces() {
    return pieces;
}

// ✅ — 불변 뷰 또는 복사본 반환
public List<Piece> getPieces() {
    return List.copyOf(pieces);          // 복사본
    // 또는
    return Collections.unmodifiableList(pieces); // 불변 뷰
}
```

## stream()을 허용하는 경우

외부에서 `stream()`을 사용하는 로직이 **단순히 읽기 전용이고, 집계가 아닌 표현이 목적**이라면

예) 뷰 레이어에서 리스트를 순회해 렌더링하는 경우

단, 이 경우도 `List<Piece>` 반환이 더 자연스럽다
