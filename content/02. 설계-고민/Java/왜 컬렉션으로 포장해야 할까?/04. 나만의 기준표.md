> "컬렉션을 일급 컬렉션으로 포장해야 할까?" 에 대한 내 답

---

## 핵심 질문

> "이 컬렉션을 다루는 로직이 여러 곳에 흩어져 있는가?"

→ **YES** → 일급 컬렉션으로 모은다  
→ **NO** → 단순한 경우 포장 불필요

---

## 포장 결정 흐름

```
List<X>를 사용하고 있다
         │
         ▼
이 컬렉션을 다루는 로직이 여러 곳에 있는가?
         │
    ┌────┴────┐
   YES        NO (한 곳에서만 사용)
    │          │
    ▼          ▼
일급 컬렉션   포장하지 않아도 된다
도입 강하게 고려
```

---

## 포장 여부 기준표

| 상황 | 판단 |
|---|---|
| 같은 filter/map/count 로직이 여러 곳에 있다 | ✅ 포장 |
| 컬렉션의 유효성 검사가 여러 곳에 흩어져 있다 | ✅ 포장 |
| stream()을 외부에 반환하고 있다 | ✅ 포장하고 메서드 제공 |
| 컬렉션이 한 곳에서만 간단하게 쓰인다 | 포장 불필요 |

---

## 일급 컬렉션 설계 원칙

- [I] **컬렉션을 그대로 반환하지 않는다**

필요한 결과를 메서드로 제공한다

<br/>

- [I] **stream()을 외부로 노출하지 않는다**

집계/변환 로직을 클래스 안에 둔다

<br/>

- [I] **생성 시점에 유효성 검사와 방어적 복사를 한다**

```java
public Pieces(List<Piece> pieces) {
    Objects.requireNonNull(pieces);
    this.pieces = List.copyOf(pieces);
}
```

<br/>

- [I] **의미 있는 이름을 붙인다**

`List<Piece>` → `Pieces` / `List<Player>` → `Players`

---

## 실전 체크리스트

- [I] **`getXxx().stream().filter()` 패턴이 여러 곳에 반복되는가?**

일급 컬렉션의 메서드로 추출한다

<br/>

- [I] **컬렉션을 `stream()`으로 반환하는가?**

필요한 연산을 메서드로 제공한다

<br/>

- [I] **컬렉션을 수정 가능한 상태로 반환하는가?**

`List.copyOf()` 또는 `Collections.unmodifiableList()`로 보호한다
