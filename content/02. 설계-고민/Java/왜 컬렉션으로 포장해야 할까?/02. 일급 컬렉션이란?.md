> 일급 컬렉션은 ==컬렉션을 유일한 인스턴스 변수로 갖는 클래스==다  
> 포장이 목적이 아니라 책임의 집중이 목적이다

---

## 개념

```java
// ❌ — 컬렉션이 노출되어 있다
public class Board {
    private Map<Position, Piece> pieces;

    public Map<Position, Piece> getPieces() { return pieces; } // ← 꺼내줌
}

// 호출하는 쪽이 직접 처리
board.getPieces().entrySet().stream()
    .filter(e -> e.getValue().getSide() == Side.HAN)
    .count();
```

```java
// ✅ — 일급 컬렉션으로 포장
public class Pieces {
    private final Map<Position, Piece> pieces;

    public long countBySide(Side side) {         // ← 책임을 안으로
        return pieces.values().stream()
            .filter(p -> p.isOwnedBy(side))
            .count();
    }

    public Optional<Piece> findAt(Position pos) {
        return Optional.ofNullable(pieces.get(pos));
    }
}
```

---

## 왜 쓰는가

- [I] **관련 로직을 한 곳에 모은다**

컬렉션을 다루는 필터, 변환, 집계 로직이 `Pieces` 안에 집중된다

같은 로직이 여러 곳에 중복되지 않는다

<br/>

- [I] **컬렉션 상태를 보호한다**

`Pieces` 밖에서 `.put()`, `.remove()`를 직접 호출할 수 없다

<br/>

- [I] **도메인 의미가 생긴다**

`Map<Position, Piece>`보다 `Pieces`가 더 의미 있는 이름이다

<br/>

- [I] **유효성 검사를 한 곳에서 한다**

```java
public Pieces(Map<Position, Piece> pieces) {
    if (pieces == null || pieces.isEmpty()) {
        throw new IllegalArgumentException("기물이 없습니다");
    }
    this.pieces = Map.copyOf(pieces); // 방어적 복사
}
```

---

## 일급 컬렉션의 조건

1. 컬렉션 이외의 다른 인스턴스 변수가 없다
2. 컬렉션에 관련된 로직을 클래스 안에 갖는다
3. 외부에 컬렉션 자체를 노출하지 않는다
