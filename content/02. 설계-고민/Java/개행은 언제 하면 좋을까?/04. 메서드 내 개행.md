
> 메서드 안에서는 ==로직의 단계(phase)가 바뀔 때==만 개행한다

---

## 개념

메서드 내부의 코드는 보통 여러 단계로 이루어진다

단계가 바뀌는 지점이 바로 개행을 넣는 자리다

```
검증 (Validation)
    ↓
처리 / 변환 (Processing)
    ↓
반환 (Return)
```

```java
public int calculate(List<Integer> scores) {
    if (scores == null || scores.isEmpty()) {      // 검증
        throw new IllegalArgumentException("점수 목록이 비어있습니다");
    }

    int total = scores.stream().mapToInt(i -> i).sum();  // 처리
    double average = (double) total / scores.size();

    return (int) Math.round(average);              // 반환
}
```

---

## 단계 구분 기준

- [I] **검증 → 처리 구간 전환**

입력을 확인하는 블록이 끝나고 실제 로직이 시작될 때 1줄

<br/>

- [I] **처리 단계 내부에서도 관심사가 바뀌면**

변환 → 필터링 → 집계처럼 성격이 다른 작업이 이어질 때 1줄

```java
public List<String> getWinnerNames(List<Player> players) {
    int maxScore = players.stream()
        .mapToInt(Player::getScore)
        .max()
        .orElseThrow();

    return players.stream()
        .filter(p -> p.getScore() == maxScore)
        .map(Player::getName)
        .collect(toList());
}
```

<br/>

- [I] **짧은 메서드는 개행 불필요**

3줄 이하의 메서드에서 개행을 넣으면 오히려 불필요한 여백이 생긴다

```java
// 개행 불필요 — 이미 충분히 짧다
public boolean isWhiteTurn() {
    return turn == Turn.WHITE;
}
```

## 흔한 실수

```java
// return 직전 습관적 개행 — 의미 없다
public int getScore() {
    int score = base + bonus;

    return score;  // ← 이 개행이 뭘 나누는 건지 불분명
}
```

```java
// 개행 없이도 충분히 명확하다
public int getScore() {
    int score = base + bonus;
    return score;
}
```
