
> 통합 테스트는 ==여러 레이어가 함께 동작하는 것을 검증하는 테스트==다

---

## 개념

실제 DB, 네트워크, 외부 시스템을 포함해 전체 흐름을 테스트한다

```java
// Testcontainers — 실제 DB를 Docker로 띄워 테스트
@Testcontainers
class GameServiceIntegrationTest {

    @Container
    static MySQLContainer<?> mysql = new MySQLContainer<>("mysql:8.0");

    @Test
    void 게임을_저장하고_DB에서_조회할_수_있다() {
        // 실제 DB와 연동해서 저장/조회
        service.createGame("장기");
        Optional<Game> game = service.findByName("장기");

        assertThat(game).isPresent();
    }
}
```

---

## 특징

- [I] **실제 환경에 가깝다**

DB, ORM, 트랜잭션이 함께 동작하는 것을 검증한다

<br/>

- [I] **느리다**

DB 연결, Docker 컨테이너 시작 등에 시간이 걸린다

<br/>

- [I] **실패 원인 추적이 어렵다**

여러 레이어가 맞물려 있어 어느 레이어에서 버그가 생겼는지 찾기 어렵다

---

## 통합 테스트만 있으면 생기는 문제

```java
// executeMove에 버그가 있는지, saveMove에 있는지, DB 설정에 있는지?
@Test
void 이동_저장_통합_테스트() {
    service.executeMove(from, to);
    // 실패하면 세 곳 중 어디가 문제인지 모른다
}
```

단위 테스트가 없으면 비즈니스 로직 버그를 통합 테스트에서 발견하게 된다

---

## 통합 테스트로 검증하기 좋은 것

- DB 저장/조회 흐름
- 트랜잭션 동작 (롤백 확인)
- 여러 서비스가 조합된 시나리오
- API 엔드포인트의 전체 흐름
