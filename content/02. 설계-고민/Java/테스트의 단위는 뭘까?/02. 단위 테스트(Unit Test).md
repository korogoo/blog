> 단위 테스트는 ==하나의 작은 단위를 외부 의존성 없이 빠르게 검증하는 테스트==다

---

## 개념

"단위(Unit)"란 무엇인가에 대한 정의는 다양하지만, 공통적인 특성이 있다

- **작다** — 하나의 클래스 또는 메서드
- **빠르다** — DB, 네트워크, 파일 없이 실행
- **독립적이다** — 다른 테스트와 순서에 무관

---

## 특징

- [I] **빠르다**

DB 연결이 없으니 밀리초 단위로 실행된다

수백 개를 실행해도 몇 초 이내

<br/>

- [I] **실패 원인이 명확하다**

하나의 클래스/메서드만 테스트하므로 실패하면 그 코드에 문제가 있다는 것을 안다

<br/>

- [I] **외부 의존성을 Mock으로 대체한다**

DB가 없는 상황에서 Repository를 테스트하려면 InMemory 구현체나 Mock을 사용한다

```java
// InMemory 구현체로 대체
class InMemoryGameRepository implements GameRepository {
    private final Map<Long, Game> store = new HashMap<>();
    // ...
}

@Test
void 게임_저장_후_조회할_수_있다() {
    GameRepository repository = new InMemoryGameRepository();
    GameService service = new GameService(repository);

    service.createGame("장기");

    assertThat(service.findByName("장기")).isPresent();
}
```

## 단위 테스트로 검증하기 좋은 것

- 비즈니스 로직 (계산, 검증, 상태 변환)
- 도메인 규칙 (이동 규칙, 점수 계산)
- 예외 처리 조건
- 경계값 로직
