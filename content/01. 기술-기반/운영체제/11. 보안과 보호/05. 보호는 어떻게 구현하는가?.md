## 최소 권한 원칙 (Principle of Least Privilege)

✨ **최소 권한 원칙: 프로세스, 사용자, 시스템 모두 자신의 작업에 필요한 최소한의 권한만 가져야 한다**

```
잘못된 예:
  일반 사용자에게 root 권한 부여
  → 실수나 공격 시 시스템 전체 위험

올바른 예:
  일반 사용자: 자신의 파일만 접근
  특정 명령 필요 시: sudo로 일시적 권한 상승
  서버 프로세스: 자신의 디렉토리만 접근
```

💬 **권한이 최소화될수록 악성 공격이 성공해도 피해 범위가 줄어든다**

| Linux 예시 | 설명 |
|---|---|
| `root` | 모든 권한 |
| `sudo` | 특정 명령에 한해 root 권한 일시 부여 |
| `chmod` | 파일 접근 권한(읽기/쓰기/실행) 설정 |

## 접근 행렬 (Access Matrix)

✨ **접근 행렬: 도메인(사용자/프로세스)과 객체(파일/장치 등)의 관계를 행렬로 표현한 보호 모델**

```
           File1   File2   File3   Printer
Domain1  [ read ]  [    ]  [read ] [     ]
Domain2  [ read ] [write]  [    ]  [print]
Domain3  [r+w  ]  [    ]  [exec ]  [     ]
```

- **행(Row)** = 도메인 (누가)
- **열(Column)** = 객체 (무엇에)
- **셀(Cell)** = 접근 권한 집합 (어떻게)

---

## ACL (Access Control List)

✨ **ACL: 접근 행렬을 열(객체) 기준으로 구현 — 각 객체에 "누가 어떤 권한을 가지는지" 목록을 저장**

```
File1의 ACL:
  Domain1: read
  Domain3: read, write

Printer의 ACL:
  Domain2: print
```

```
접근 행렬 구현 방법 비교:

열(객체) 기준 → ACL
  각 파일마다 권한 목록 저장
  "이 파일에 접근 가능한 사람은?"

행(도메인) 기준 → Capability List
  각 사용자마다 접근 가능한 객체 목록 저장
  "이 사람이 접근 가능한 파일은?"
```

## 샌드박싱 (Sandboxing)

✨ **샌드박싱: 프로세스를 제한된 환경(상자) 안에서 실행시켜 할 수 있는 행동을 제한하는 기술**

```
일반 프로세스:
  사용자가 시작 → 사용자의 모든 권한 상속
  → 악성 코드라면 파일 전체, 네트워크 전체 접근 가능

샌드박스 프로세스:
  허가된 파일만 접근
  네트워크 통신 제한
  시스템 콜 제한
```

| 플랫폼 | 구현 방식 |
|---|---|
| **Java / .NET** | 가상 머신(VM) 수준에서 샌드박싱 |
| **Android** | 강제 접근 제어(MAC)로 앱 간 샌드박싱 |
| **iOS / macOS** | 앱 샌드박스 정책 |

## 코드 서명 (Code Signing)

✨ **코드 서명: 프로그램·실행 파일에 디지털 서명을 부착해, 배포 이후 변조 여부를 검증하는 기술**

```
개발자:
  프로그램 완성 → 개인 키로 서명 → 배포

사용자/시스템:
  프로그램 실행 전 → 공개 키로 서명 검증
  서명 유효? → 실행 허용
  서명 없거나 변조됨? → 경고 또는 실행 차단
```

활용 사례:
- OS 배포 및 패치
- Windows Driver Signing
- Android / iOS 앱 스토어 앱

💬 **코드 서명 = 디지털 서명(04번 파일)의 응용 — 발신자(개발자)를 검증하고 내용(코드) 무결성을 보장**

## 전체 보호 메커니즘 요약

```
위협 탐지     → 포트 스캐닝 방어, 침입 탐지
접근 통제     → 최소 권한 원칙, 접근 행렬, ACL
실행 격리     → 샌드박싱
코드 무결성   → 코드 서명
통신 보안     → 암호화(대칭/비대칭), 인증(MAC, 디지털 서명)
```
