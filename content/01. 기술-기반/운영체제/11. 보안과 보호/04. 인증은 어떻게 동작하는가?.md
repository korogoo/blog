> 암호화는 수신자를 제한하고, 인증은 발신자를 검증한다

---

## 인증 (Authentication)

✨ **인증: 메시지를 보낸 사람이 실제로 그 사람인지, 메시지가 변조되지 않았는지 검증하는 것**

```
암호화: "이 메시지는 키를 가진 사람만 읽을 수 있다"  → 수신자 제한
인증:   "이 메시지는 키를 가진 사람이 보낸 것이다"  → 발신자 검증
```

---

## 인증 알고리즘의 구성 요소

- 키 집합 $K$, 메시지 집합 $M$, 인증자 집합 $A$
- 해시(서명) 함수 $S: K \rightarrow (M \rightarrow A)$
- 검증 함수 $V: K \rightarrow (M \times A \rightarrow \{true, false\})$

**핵심 성질:**
- 키 $k$를 가진 쪽만 인증자를 생성할 수 있다
- 키 없이는 유효한 인증자를 만드는 것이 불가능하다

---

## 해시 함수 (Hash Function)

✨ **해시 함수 H(m): 임의 길이의 메시지를 고정된 크기의 짧은 값(메시지 다이제스트)으로 변환**

```
원본 메시지 (수 MB)
       ↓ H(m)
  [고정 크기 해시값] (예: 256비트)

특성:
  - 같은 입력 → 항상 같은 해시값
  - 다른 입력 → (거의 항상) 다른 해시값
  - 해시값으로 원본 복원 불가 (단방향)
  - 메시지가 1비트라도 바뀌면 해시값이 완전히 달라짐
```

ℹ **파일이 변조되었는지 확인할 때도 해시 비교를 사용한다**

---

## MAC (Message Authentication Code)

✨ **MAC: 비밀 키를 사용해 생성하는 암호학적 체크섬 — 메시지 무결성 + 발신자 인증**

```
송신자:
  메시지 m + 비밀 키 k → MAC 생성 → (m, MAC) 전송

수신자:
  받은 m + 비밀 키 k → MAC 재계산
  재계산한 MAC == 받은 MAC? → 무결성 확인
```

---

## 디지털 서명 (Digital Signature)

✨ **디지털 서명: 개인 키로 서명하고 공개 키로 검증 — 누구나 검증 가능**

```
서명:
  송신자의 개인 키 → 메시지 해시에 서명 → 서명값 첨부

검증:
  송신자의 공개 키 → 서명값 검증 → 진짜인지 확인
  (공개 키는 누구나 가질 수 있으므로 누구나 검증 가능)
```

💬 **디지털 서명의 강점: 개인 키에서 공개 키를 역산하는 것이 계산적으로 불가능 → 부인(repudiation) 방지**

---

## 세 가지 인증 방식 비교

| 방식 | 키 종류 | 검증 가능 대상 | 특징 |
|---|---|---|---|
| **해시 함수** | 없음 | 무결성만 | 키 불필요, 발신자 인증 불가 |
| **MAC** | 대칭 키 | 무결성 + 발신자 | 키 공유 필요 |
| **디지털 서명** | 비대칭 키 | 무결성 + 발신자 | 누구나 검증 가능, 부인 방지 |

ℹ **비트코인 거래도 디지털 서명으로 인증한다 — 개인 키 없이는 다른 사람의 코인을 보낼 수 없다**
