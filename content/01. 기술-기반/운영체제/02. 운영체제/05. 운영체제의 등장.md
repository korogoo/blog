> 복잡성이 임계점을 넘으면, 관리자가 필요해진다

---

## 문제: 누가 이 모든 걸 관리하지?

우리는 이런 문제들을 봤다

- [>] 여러 프로그램이 CPU를 동시에 원한다
- [>] 프로그램들이 메모리를 나눠 써야 한다
- [>] 디스크, 키보드, 화면을 여러 프로그램이 공유해야 한다
- [>] 한 프로그램이 망가지면 다른 프로그램도 죽는다

<br/>

이것들을 개별 프로그램이 각자 해결하면?  

- [!] **프로그램마다 코드가 중복되고, 충돌이 생기고, 혼란이 온다**

모든 자원을 중앙에서 관리하는 전담 소프트웨어가 필요하다

그것이 바로 **운영체제(Operating System, OS)** 다

---

## 운영체제란 무엇인가

- ["] **컴퓨터에서 항상 실행 중인 프로그램으로, 하드웨어를 관리하고 응용 프로그램에게 서비스를 제공하며 사용자와 하드웨어 사이를 중재한다**

컴퓨터 시스템의 4대 구성요소

```
┌────────────────────────────────────┐
│            사용자 (User)            │
├────────────────────────────────────┤
│       응용 프로그램 (Apps)           │
├────────────────────────────────────┤
│       운영체제 (OS / Kernel)        │
├────────────────────────────────────┤
│         하드웨어 (Hardware)         │
└────────────────────────────────────┘
```

OS는 이 구조에서 **하드웨어와 응용 프로그램 사이의 중재자** 역할을 한다

---

## 커널(Kernel): OS의 핵심

OS를 정의할 때 가장 보편적인 표현

- [I] **컴퓨터에서 항상 실행 중인 단 하나의 프로그램**

<br/>

OS는 크게 세 종류의 프로그램으로 구성된다:

|종류|설명|예시|
|---|---|---|
|**커널**|항상 실행 중인 OS의 핵심|프로세스 관리, 메모리 관리|
|**시스템 프로그램**|OS와 함께 제공되는 유틸리티|ls, cp, ps, gcc|
|**응용 프로그램**|사용자가 실행하는 일반 프로그램|Chrome, VS Code|

---

## 유저 모드 vs 커널 모드: 왜 분리했을까?

- [!] **만약 모든 프로그램이 하드웨어에 직접 접근할 수 있다면? 시스템이 아수라장이 된다**

```
악성 프로그램 A: "나 메모리 전체 지울게"
일반 프로그램 B: "나 다른 프로그램의 데이터 읽을게"
```

<br/>

- ["] **그래서 CPU는 두 가지 실행 모드를 갖는다**

|모드|접근 권한|실행 주체|
|---|---|---|
|**커널 모드** (Kernel Mode)|하드웨어 직접 접근 가능|OS (커널)|
|**유저 모드** (User Mode)|제한된 명령어만 사용 가능|응용 프로그램|

```
[앱 실행 중 - 유저 모드]
  → 파일을 읽고 싶다
  → 시스템 콜 호출
  → [커널 모드로 전환]
  → OS가 실제 디스크 접근
  → [다시 유저 모드로 복귀]
  → 앱에게 데이터 전달
```

이 분리 덕분에 **한 프로그램이 망가져도 OS와 다른 프로그램은 보호**된다

---

## 시스템 콜(System Call): 앱이 OS에게 부탁하는 방법

앱은 직접 하드웨어에 접근할 수 없다

OS에게 "이거 해줘"라고 요청해야 한다

이 요청의 인터페이스가 **시스템 콜**이다

- ["] **시스템 콜: 응용 프로그램이 OS의 서비스를 사용하기 위해 호출하는 인터페이스 (= OS의 API)**

<br/>

대표적인 시스템 콜 예시

|분류|UNIX 예시|하는 일|
|---|---|---|
|프로세스|`fork()`, `exec()`, `exit()`|프로세스 생성/실행/종료|
|파일|`open()`, `read()`, `write()`, `close()`|파일 읽기/쓰기|
|장치|`ioctl()`, `read()`, `write()`|장치 제어|
|정보|`getpid()`, `time()`|시스템 정보 조회|
|통신|`socket()`, `send()`, `recv()`|네트워크 통신|

<br/>

우리가 C언어에서 `printf()`를 쓰면?

```
printf() → C 표준 라이브러리 → write() 시스템 콜 → OS → 화면 출력
```

프로그래머는 시스템 콜을 직접 쓰지 않아도, **라이브러리를 통해 간접적으로 사용**하게 된다

## OS가 제공하는 서비스들

OS는 응용 프로그램과 사용자에게 다양한 서비스를 제공한다

|서비스|설명|
|---|---|
|**사용자 인터페이스**|CLI(Shell), GUI, 터치|
|**프로그램 실행**|프로그램 로드 및 실행|
|**I/O 처리**|파일, 장치 입출력|
|**파일 시스템**|파일/디렉토리 관리|
|**통신**|프로세스 간, 네트워크 통신|
|**에러 감지**|하드웨어/소프트웨어 오류 처리|
|**자원 할당**|CPU, 메모리, 장치 분배|
|**보안 & 보호**|권한 관리, 접근 제어|

---

## 사용자 인터페이스의 세 가지 형태

|종류|설명|예시|
|---|---|---|
|**CLI** (Command Line Interface)|명령어를 텍스트로 입력|bash, zsh, sh|
|**GUI** (Graphical User Interface)|그래픽 환경에서 클릭|Windows, macOS, GNOME|
|**터치 인터페이스**|터치 기반|iOS, Android|

개발자에게 CLI가 중요한 이유

- [>] **자동화, 원격 접속, 서버 환경**에서 GUI가 없는 경우가 많기 때문이다
- [>] 지금 우리가 실습하는 도커 Ubuntu가 바로 CLI 환경이다
