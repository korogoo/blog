## 문제: 설계도는 나왔다. 그럼 실제 컴퓨터는 어떻게 구성되어 있을까?

폰 노이만이 설계도를 그렸다

이제 그 설계도가 실제 하드웨어에서 어떻게 구현되는지 살펴보자

현대 컴퓨터는 크게 이렇게 생겼다

```
┌──────────────────────────────────────────────┐
│  CPU       Memory      Disk     I/O Device   │
│  ┌───┐     ┌─────┐   ┌─────┐   ┌──────────┐  │
│  │CPU│     │ RAM │   │ HDD │   │ keyboard │  │
│  └───┘     └─────┘   └─────┘   │ mouse    │  │
│    ↕         ↕         ↕      │ display  │  │
|                                └──────────┘  |
│  └──────── System Bus ─────────────┘         │
└──────────────────────────────────────────────┘
```

## CPU 관련 용어 정리

헷갈리기 쉬운 개념들을 먼저 정리하자

| 용어                 | 정의                                 |
| ------------------ | ---------------------------------- |
| **CPU**            | 명령어를 실행하는 하드웨어. 연산의 주체             |
| **Processor**      | CPU를 포함하는 물리적 칩                    |
| **Core**           | CPU 안의 실제 연산 단위. 코어가 많을수록 동시 처리 가능 |
| **Multicore**      | 하나의 Processor에 여러 Core가 있는 구조      |
| **Multiprocessor** | 여러 Processor를 가진 시스템               |

우리가 ==8코어 CPU==라고 말하는 건, 하나의 칩(Processor) 안에 연산 단위(Core)가 8개 있다는 뜻이다

<br/>

### 멀티프로세서의 두 가지 방식

✨ **SMP (Symmetric MultiProcessing, 대칭형 멀티프로세싱)**

가장 일반적인 방식

모든 CPU가 **동등한 권한**으로 모든 작업을 처리

OS가 작업을 각 CPU에 균등하게 분배

<br/>

✨ **비대칭형 (Asymmetric)**

각 CPU가 **특정 역할**만 담당

ex. 하나는 입출력 전담, 하나는 연산 전담

## 버스(Bus): 컴퓨터 내부의 고속도로

CPU, 메모리, 디스크, 입출력 장치들은 **버스(Bus)** 를 통해 연결된다

ℹ **버스 = 데이터가 오가는 공통 통로**

장치 컨트롤러(Device Controller)가 각 장치를 관리하고, 버스를 통해 CPU와 소통한다

## 전원을 켜면 무슨 일이 생기나: 부트스트랩

컴퓨터 전원을 켜면 가장 먼저 실행되는 프로그램이 있다

> **부트스트랩 프로그램 (Bootstrap Program)**

ROM(비휘발성 메모리)에 저장되어 있어 전원이 꺼져도 유지됨

하드웨어를 초기화하고

저장장치에서 **운영체제를 메모리에 로드**한다

```
전원 ON → 부트스트랩 실행 → OS 로드 → OS 실행 시작
```

이 과정을 **부팅(Booting)** 이라고 한다

## 인터럽트: 하드웨어가 CPU에게 말 거는 방법

CPU는 기본적으로 명령어를 순서대로 실행한다

그런데 갑자기 키보드를 눌렀다면? 네트워크 패킷이 도착했다면?

CPU가 매번 "뭔가 일어났나?"를 확인하면 비효율적이다

그래서 등장한 것이 **인터럽트(Interrupt)** 다

<br/>

✨ **인터럽트**: 하드웨어가 CPU에게 신호를 보내 지금 처리할 일이 생겼음을 알리는 메커니즘

```
CPU 작업 중...
  → 키보드 입력 발생
  → 키보드 컨트롤러가 버스를 통해 CPU에 인터럽트 신호 전송
  → CPU가 하던 일을 잠시 멈추고 인터럽트 처리
  → 처리 완료 후 하던 일 재개
```

인터럽트가 없었다면 CPU는 모든 장치를 계속 폴링(polling)해야 해서 엄청난 낭비가 생겼을 것이다

## 폰 노이만 아키텍처: 명령어 실행 사이클

CPU가 명령어를 실행하는 과정은 항상 이 사이클을 반복한다

```
1. Fetch   : 메모리에서 명령어를 가져온다
2. Decode  : 명령어가 뭘 하라는 건지 해석한다
3. Execute : 실제로 연산을 수행한다
4. Store   : 결과를 메모리에 저장한다
```

이 사이클이 초당 수십억 번 반복되는 것이 현대 CPU다

## 스토리지 계층: 빠름 vs 저렴함의 트레이드오프

⚠️ 저장장치는 빠를수록 비싸고, 용량이 작다

<br/>

그래서 계층 구조를 만들어 효율적으로 사용한다.

```
빠름 ↑ / 비쌈 ↑ / 용량 작음 ↑
─────────────────────────────
  Registers     (CPU 내부, 극소량)
  Cache         (L1, L2, L3)
  Main Memory   (RAM, 휘발성)
  SSD / HDD     (비휘발성, 대용량)
  Optical Disk  (CD, DVD)
  Magnetic Tape (백업용, 매우 느림)
─────────────────────────────
느림 ↓ / 쌈 ↓ / 용량 큼 ↓
```


✨ **CPU는 레지스터와 캐시에서만 데이터를 직접 처리한다**  

RAM의 데이터도 캐시를 거쳐 CPU로 들어온다

## I/O 구조

OS 코드의 상당 부분은 **I/O 관리**에 할당되어 있다

입출력 과정

```
1. CPU가 I/O 장치에 명령 전달
2. I/O 장치가 작업 수행 (CPU는 다른 일 처리)
3. 작업 완료되면 인터럽트로 CPU에 알림
4. CPU가 결과를 처리
```

이처럼 CPU와 I/O 장치가 **동시에 작동**할 수 있어 효율적이다
