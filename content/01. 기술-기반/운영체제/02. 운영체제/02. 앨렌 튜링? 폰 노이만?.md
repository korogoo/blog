> "이론 없이 기계는 없고, 설계 없이 컴퓨터는 없다."

## 문제: 0과 1로 계산할 수 있다는 건 알겠는데, 어떻게 '생각하는 기계'를 만들지?

우리는 0과 1로 모든 계산이 가능하다는 걸 알았다

하지만 그걸 **실제 기계로 어떻게 구현할까?**

<br/>

20세기 초, 두 사람이 이 질문에 각자 결정적인 답을 내놨다

- [I] **앨런 튜링(Alan Turing)**: 컴퓨터의 **이론적 토대**

- [I] **존 폰 노이만(John von Neumann)**: 컴퓨터의 **실제 설계도**

---

## 앨런 튜링: 컴퓨터의 할아버지

### 튜링 머신(Turing Machine)

1936년, 튜링은 생각하는 기계를 수학적으로 정의했다

실제 기계를 만든 게 아니라, **개념으로서의 기계**를 설계한 것이다

<br/>

튜링 머신의 구조는 아주 단순하다

```
┌────────────────────────────────────────┐
│  Head (헤드)                            │
│    ↕                                   │
│ [ 0 | 1 | 1 | 0 | 1 | ... ]  ← Tape    │
└────────────────────────────────────────┘
```

| 구성요소           | 역할                        |
| -------------- | ------------------------- |
| **Tape (테이프)** | 무한히 긴 메모리. 0과 1을 저장       |
| **Head (헤드)**  | 테이프를 읽고 쓰고, 좌우로 이동        |
| **State (상태)** | 현재 어떤 작업을 하는지 기억          |
| **Rule (규칙표)** | 이 상태에서 이 값을 읽으면, 이렇게 행동해라 |

이게 전부다. 그런데 이 단순한 기계가 **모든 계산을 할 수 있다**

<br/>

### 유니버설 튜링 머신(Universal Turing Machine)

튜링은 여기서 한 발 더 나아갔다

- ["] **다른 튜링 머신의 동작을 시뮬레이션할 수 있는 튜링 머신을 만들 수 있다**

특정 계산만 하는 기계가 아니라, **어떤 계산이든 할 수 있는 범용 기계**의 개념

이것이 현대 컴퓨터의 개념적 원형이다

---

## 현대 컴퓨터와의 대응 관계

튜링 머신의 개념이 현대 컴퓨터에 어떻게 대응되는지 보면 이해가 쉽다

|튜링 머신|현대 컴퓨터|
|---|---|
|Head (헤드)|**CPU**|
|Tape (테이프)|**메모리 (RAM)**|
|Turing Machine|**응용 프로그램**|
|Universal Turing Machine|**운영체제 (OS)**|

**OS**가 ==어떤 프로그램이든 실행할 수 있는 환경을 제공==하는 것이

**유니버설 튜링 머신**이 ==어떤 계산이든 시뮬레이션하는 것==과 정확히 같은 개념이다

## 존 폰 노이만: 컴퓨터의 아버지

튜링이 이론을 만들었다면, 폰 노이만은 **실제로 만들 수 있는 설계도**를 그렸다

### 저장 프로그램 방식 (Stored-Program Computer)

폰 노이만 이전의 컴퓨터는 **계산할 내용을 하드웨어 배선으로 직접 설정**했다

계산 내용을 바꾸려면 기계를 물리적으로 다시 연결해야 했다

<br/>

폰 노이만의 혁신:

- ["] **프로그램(명령어)을 데이터와 함께 메모리에 저장하자**

```
   ┌─────────┐     bus     ┌─────────┐
   │   CPU   │ ←────────→ │   RAM   │
   └─────────┘             └─────────┘
   (명령어 실행)            (명령어 + 데이터 저장)
```

이것을 **폰 노이만 아키텍처(Von Neumann Architecture)** 라고 한다

이 구조 덕분에

- [I] 프로그램을 **소프트웨어로 교체**할 수 있게 되었다
- [I] 같은 하드웨어로 **다양한 작업**을 할 수 있게 되었다
- [I] 현재 우리가 쓰는 **모든 컴퓨터의 기본 구조**가 되었다

<br/>

### ISA: Instruction Set Architecture

폰 노이만은 또한 **ISA(명령어 집합 구조)** 개념을 정립했다

- ["] CPU가 이해할 수 있는 명령어의 집합을 정의한 것.

<br/>

예를 들어 C코드 `int c = a + b;` 는 실제로 이런 명령어들로 변환된다

```asm
movl -12(%rbp), %edx   ; a를 레지스터에 로드
movl -8(%rbp), %eax    ; b를 레지스터에 로드
addl %edx, %eax        ; 더하기
movl %eax, -4(%rbp)    ; 결과를 c에 저장
```

사람이 쓴 코드 → 컴파일러 → ISA 명령어 → CPU 실행

이 흐름이 모든 프로그래밍의 기초다
