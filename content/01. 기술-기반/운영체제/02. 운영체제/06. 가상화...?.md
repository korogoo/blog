> 추상화는 복잡성을 감추고, 가상화는 하나를 여럿으로 만든다

---

## 문제: 하드웨어는 하나인데, 여러 환경이 필요하다

서버 한 대가 있다

▶ 이 서버에서 Windows도 돌리고, Linux도 돌리고 싶다

▶ 개발 환경과 운영 환경을 분리하고 싶다

▶ 다른 팀이 같은 서버를 독립적으로 쓰게 하고 싶다

▶ 물리적 서버를 여러 대 사는 건 비싸다

▶ 그렇다고 하나의 OS에서 다 섞어 쓰면 충돌이 생긴다


<br/>

❓ **하나의 하드웨어를 여러 독립된 실행 환경으로 나눌 수 없을까?**

---

## 가상화(Virtualization)란?

✨ **하나의 컴퓨터 하드웨어를 추상화하여 여러 개의 독립된 실행 환경처럼 보이게 하는 기술**

```
물리 컴퓨터 한 대
┌─────────────────────────────────┐
│           Hardware              │
├─────────────────────────────────┤
│      VMM (가상 머신 관리자)       │
├──────────┬──────────┬───────────┤
│  VM 1    │  VM 2    │   VM 3    │
│  Ubuntu  │ Windows  │  CentOS   │
│  App A   │  App B   │  App C    │
└──────────┴──────────┴───────────┘
```

실제로는 하나의 하드웨어를 나눠 쓰고 있지만

각 VM(가상 머신)은 자신이 독립된 컴퓨터라고 믿는다

---

## VMM: 가상 머신의 관리자

✨ **VMM (Virtual Machine Manager / Hypervisor): 가상 머신들을 생성하고 관리하는 소프트웨어**

<br/>

대표적인 VMM

|이름|특징|
|---|---|
|**VMware**|상용, 기업 환경에서 많이 사용|
|**VirtualBox**|오픈소스, 개인 학습용|
|**XEN**|오픈소스, 클라우드 인프라에 사용|
|**WSL** (Windows Subsystem for Linux)|Windows에서 Linux 실행|
|**Docker**|컨테이너 방식 (VM과 다름, 아래 설명)|

---

## VM vs 도커: 같은 맥락, 다른 방식

가상화에는 크게 두 가지 방식이 있다

### 1. 가상 머신 (VM)

✨ **OS 전체를 가상화**

```
┌──────────────────────┐
│  Guest OS (Ubuntu)   │
│  ┌────────────────┐  │
│  │   Application  │  │
│  └────────────────┘  │
├──────────────────────┤
│  Hypervisor (VMM)    │
├──────────────────────┤
│  Host OS             │
├──────────────────────┤
│  Hardware            │
└──────────────────────┘
```

▶ **무겁고 느리지만 완전한 격리**
▶ 하드웨어 수준에서 분리

### 2. 컨테이너 (Docker)

✨ **Host OS의 커널을 공유**

```
┌────────┬────────┬────────┐
│ App A  │ App B  │ App C  │
├────────┴────────┴────────┤
│  Container Runtime       │
│  (Docker Engine)         │
├──────────────────────────┤
│  Host OS (커널 공유)      │  ← OS는 하나
├──────────────────────────┤
│  Hardware                │
└──────────────────────────┘
```

▶ **가볍고 빠름**
▶ 완전한 격리는 아니지만 실용적

<br/>

### 비교 요약

|항목|VM|Docker (컨테이너)|
|---|---|---|
|OS|Guest OS 별도 설치|Host OS 커널 공유|
|속도|느림 (부팅 필요)|빠름 (초 단위 시작)|
|용량|수 GB|수십~수백 MB|
|격리 수준|완전 격리|프로세스 수준 격리|
|용도|다른 OS 실행, 강한 격리|개발 환경, 배포|

---

## 우리가 쓴 도커가 바로 이것

우리가 설정한 환경

```bash
docker pull ubuntu:20.04
docker run -it --name myUbuntu ubuntu:20.04
```

이것이 바로 가상화 기술의 응용이다

▶ Mac이나 Windows 위에서 → Ubuntu 환경을 컨테이너로 실행
▶ Host OS와 커널을 공유하되 → 격리된 Ubuntu 환경 제공
▶ 교수님도, 학생도 → 동일한 환경에서 실습 가능

<br/>

클라우드(AWS, GCP, Azure)에서 서버를 빌리는 것도

결국 누군가의 물리 서버 위에 **가상화로 분리된 환경**을 쓰는 것이다
