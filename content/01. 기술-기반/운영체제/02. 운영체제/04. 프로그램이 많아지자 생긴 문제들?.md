## 먼저: 프로그램이란 무엇인가?

- ✨ **프로그램(Program): 컴퓨터 하드웨어에게 작업을 지시하는 명령어들의 집합**

우리가 작성하는 C, Python, Java 코드는 사람이 읽기 위한 것이다

이것이 컴파일러를 거치면 CPU가 이해할 수 있는 기계어(ISA 명령어)로 변환된다

```c
// 우리가 쓰는 코드
int c = a + b;
printf("%d\n", c);
```

```asm
// CPU가 실행하는 명령어
movl -12(%rbp), %edx
movl -8(%rbp), %eax
addl %edx, %eax
movl %eax, -4(%rbp)
call printf@PLT
```

## 문제: 프로그램 하나씩만 실행하면 너무 비효율적이다

초기 컴퓨터는 **한 번에 하나의 프로그램**만 실행했다

```
[프로그램 A 실행] → 완료 → [프로그램 B 실행] → 완료 → ...
```

<br/>

- ⚠️ **문제는 프로그램이 실행되는 동안 대부분의 시간을 I/O 대기에 쓴다는 것이다**

```
프로그램 A 실행 중:
CPU 연산 ████░░░░░░░░░░░░░░░░░░░░░░░░
디스크 읽기 대기 ────────────────────►
```

CPU가 디스크를 기다리는 동안 아무것도 안 하고 놀고 있다

CPU 입장에서 이건 엄청난 낭비다

---

## 해결책 1: 멀티프로그래밍 (Multiprogramming)

- 💬 **여러 프로그램을 메모리에 동시에 올려두고, CPU가 놀지 않도록 하자**

```
메모리:
┌──────────────┐
│  OS          │
├──────────────┤
│  프로그램 A   │  ← A가 I/O 대기 중이면
├──────────────┤
│  프로그램 B   │  ← CPU는 B를 실행
├──────────────┤
│  프로그램 C   │
└──────────────┘
```

프로그램 A가 디스크를 기다리는 동안, CPU는 B를 실행한다

B가 I/O 대기에 들어가면, C를 실행한다

<br/>

**결과**: CPU 활용률(Utilization)이 극적으로 향상된다

---

## 새로운 문제: 사용자가 컴퓨터와 실시간으로 대화하고 싶다

멀티프로그래밍은 CPU를 효율적으로 쓰게 해줬다

하지만 사용자 입장에서 문제가 생겼다

- ⚠️ **내가 명령을 입력했는데, 다른 프로그램이 끝날 때까지 기다려야 한다고?**

---

## 해결책 2: 멀티태스킹 (Multitasking)

- 💬 **CPU가 작업을 매우 빠르게 전환해서, 사용자가 동시에 실행되는 것처럼 느끼게 하자**

멀티태스킹은 멀티프로그래밍의 논리적 확장이다.

```
시간 →
CPU: [A][B][C][A][B][C][A][B][C]...

사용자 눈에는:
A: ─────────────────────────────►
B: ─────────────────────────────►
C: ─────────────────────────────►
(동시에 실행되는 것처럼 보임)
```

전환 속도가 너무 빠르기 때문에 사람은 동시 실행으로 느낀다

실제로는 CPU 하나가 계속 빠르게 바꿔가며 실행하는 것이다

<br/>

- ℹ **멀티프로그래밍 vs 멀티태스킹**

멀티프로그래밍: I/O 대기 시 다른 프로그램 실행 (CPU 효율 목적)

멀티태스킹: 아주 짧은 시간 단위로 강제 전환 (사용자 응답성 목적)

---

## 또 다른 문제: CPU야, 누구 일을 먼저 해줄래?

- ⚠️ **여러 프로그램이 동시에 CPU를 원한다**

CPU는 하나(또는 소수)인데, 줄 세우는 방법이 필요하다

---

## 해결책 3: CPU 스케줄링 (CPU Scheduling)

- 💬 **OS가 어떤 프로그램에게 CPU를 줄지 결정하는 것**

스케줄링 알고리즘의 목표

- ▶ CPU 활용률 최대화
- ▶ 처리량(Throughput) 최대화
- ▶ 응답 시간 최소화
- ▶ 특정 프로세스가 무한정 기다리지 않도록 (기아 방지)

<br/>

대표적인 스케줄링 방식

|방식|설명|
|---|---|
|FCFS|먼저 온 순서대로 (First Come, First Served)|
|SJF|짧은 작업 먼저 (Shortest Job First)|
|Round Robin|시간을 나눠서 돌아가며 실행|
|Priority|우선순위가 높은 것 먼저|
