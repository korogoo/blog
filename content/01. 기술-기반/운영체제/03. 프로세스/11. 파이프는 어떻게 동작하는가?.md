> UNIX에서 가장 오래된 IPC 메커니즘

---

## 파이프란

- [I] **파이프(Pipe): 두 프로세스를 연결하는 통로 — 한쪽에서 쓰고 다른 쪽에서 읽는다**

UNIX 초기부터 존재했던 IPC 방식이다

터미널에서 `ls | grep txt` 처럼 `|` 기호가 바로 파이프다

---

## 파이프 설계 시 고려할 4가지

| 질문 | 선택지 |
|---|---|
| 통신 방향 | 단방향(unidirectional) / 양방향(bidirectional) |
| 양방향일 때 | 반이중(half-duplex) / 전이중(full-duplex) |
| 프로세스 관계 필요 여부 | 부모-자식 관계 필요 / 불필요 |
| 네트워크 통신 가능 여부 | 로컬만 / 네트워크도 가능 |

---

## 두 종류의 파이프

| 종류 | 특징 |
|---|---|
| **Ordinary Pipe** | 생성한 프로세스 외부에서 접근 불가, 부모-자식 관계 필요 |
| **Named Pipe** | 부모-자식 관계 없이도 사용 가능, 파일처럼 이름으로 접근 |

---

## Ordinary Pipe 구조

- ["] **단방향**: 쓰는 쪽(write end)과 읽는 쪽(read end)이 분리됨

```
부모 프로세스                     자식 프로세스
   │                                  │
   │  fd[1] (write end)    fd[0] (read end)
   └──────────────► PIPE ────────────►┘
```

양방향 통신이 필요하면 파이프를 두 개 사용한다

---

## UNIX에서 파이프 사용하기

```c
pipe(int fd[])
```

- `fd[0]`: 읽기 끝 (read end)
- `fd[1]`: 쓰기 끝 (write end)

```c
#include <stdio.h>
#include <string.h>
#include <unistd.h>

#define BUFFER_SIZE 25
#define READ_END  0
#define WRITE_END 1

int main()
{
    char write_msg[BUFFER_SIZE] = "Greetings";
    char read_msg[BUFFER_SIZE];
    int fd[2];
    pid_t pid;

    /* 파이프 생성 */
    pipe(fd);

    pid = fork();

    if (pid > 0) {              // 부모 프로세스 (생산자)
        close(fd[READ_END]);    // 읽기 끝 닫기
        write(fd[WRITE_END], write_msg, strlen(write_msg) + 1);
        close(fd[WRITE_END]);
    }
    else if (pid == 0) {        // 자식 프로세스 (소비자)
        close(fd[WRITE_END]);   // 쓰기 끝 닫기
        read(fd[READ_END], read_msg, BUFFER_SIZE);
        printf("read %s\n", read_msg);
        close(fd[READ_END]);
    }

    return 0;
}
```

- [i] **사용하지 않는 끝은 반드시 `close()`로 닫아야 한다**

안 닫으면 EOF 신호가 전달되지 않아 프로세스가 무한 대기할 수 있다

---

## 흐름 정리

```
① pipe(fd) 호출 → 파이프 생성
② fork() 호출  → 부모/자식 모두 fd[0], fd[1]을 가짐
③ 부모: fd[READ_END] 닫고 fd[WRITE_END]로 씀
④ 자식: fd[WRITE_END] 닫고 fd[READ_END]로 읽음
```
