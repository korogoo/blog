> 지금까지의 IPC는 같은 컴퓨터 안의 이야기였다. 네트워크 너머의 프로세스와는 어떻게 통신하는가?

---

## 클라이언트-서버 통신

지금까지 본 공유 메모리, 메시지 전달, 파이프는 모두 **같은 컴퓨터 내** 프로세스 간 통신이다

네트워크로 연결된 다른 컴퓨터의 프로세스와 통신하려면 다른 방식이 필요하다

두 가지 대표적인 방법이 있다

| 방식 | 설명 |
|---|---|
| **소켓 (Socket)** | 네트워크 통신의 끝점(endpoint), 저수준 |
| **RPC** | 원격 프로시저 호출, 함수 호출처럼 추상화된 고수준 |

---

## 소켓 (Socket)

✨ **소켓: 통신의 끝점(endpoint) — IP 주소 + 포트 번호로 식별된다**

```
클라이언트                         서버
IP: 146.86.5.20                IP: 161.25.19.8
Port: 1625 (임의 할당)          Port: 80 (HTTP)
        │                              │
        └──────── 소켓 통신 ────────────┘
```

포트 번호는 어떤 프로세스에게 전달할지를 구분하는 역할을 한다

ℹ **포트 1024 미만은 well-known port — HTTP(80), HTTPS(443), SSH(22) 등이 예약되어 있다**

## Java 소켓 예제

Java는 소켓을 세 종류로 제공한다

| 클래스 | 방식 | 특징 |
|---|---|---|
| `Socket` | TCP | 연결 지향, 신뢰성 보장 |
| `DatagramSocket` | UDP | 비연결, 빠름 |
| `MulticastSocket` | UDP 멀티캐스트 | 여러 수신자에게 동시 전송 |

**서버**

```java
import java.net.*;
import java.io.*;

public class DateServer {
    public static void main(String[] args) throws Exception {
        ServerSocket server = new ServerSocket(6013);  // 6013번 포트에서 대기

        while (true) {
            Socket client = server.accept();           // 연결 수락
            PrintWriter pout = new PrintWriter(client.getOutputStream(), true);
            pout.println(new java.util.Date().toString());  // 날짜 전송
            client.close();
        }
    }
}
```

**클라이언트**

```java
import java.net.*;
import java.io.*;

public class DateClient {
    public static void main(String[] args) throws Exception {
        Socket socket = new Socket("127.0.0.1", 6013);  // 서버에 연결
        BufferedReader br = new BufferedReader(
            new InputStreamReader(socket.getInputStream())
        );

        String line;
        while ((line = br.readLine()) != null)
            System.out.println(line);

        socket.close();
    }
}
```

`127.0.0.1`은 루프백(loopback) 주소 — 자기 자신을 가리킨다

## RPC (Remote Procedure Call)

✨ **RPC: 네트워크 너머 다른 컴퓨터의 함수를 마치 로컬 함수처럼 호출하는 방식**

소켓은 "데이터를 주고받는" 저수준 통신이다

RPC는 그 위에서 "함수 호출"처럼 추상화한 것이다

```
클라이언트 코드:
result = add(1, 2);   // 로컬 함수 호출처럼 보임
                      // 실제로는 네트워크 너머 서버에서 실행됨
```

---

## RPC 동작 방식: stub

직접 네트워크를 다루지 않아도 되는 이유는 **stub** 덕분이다

```
[클라이언트]                         [서버]
  코드                                코드
   │                                   │
   ▼                                   ▼
클라이언트 stub                    서버 stub
  - 서버 위치 파악                  - 메시지 수신
  - 파라미터 직렬화 (marshaling)    - 파라미터 역직렬화
  - 네트워크로 전송                 - 실제 함수 실행
                                   - 결과 반환
```

✨ **marshaling: 파라미터를 네트워크로 전송할 수 있는 형태로 변환하는 과정**

ℹ **현대의 gRPC, REST API도 RPC 개념의 연장선에 있다**
