> 프로세스도 태어나고 죽는다. 그리고 그 사이에 부모와 자식이 있다

## 프로세스는 어디서 오는가?

OS가 부팅되면 첫 번째 프로세스(`init`, PID 1)가 생성된다

이후 모든 프로세스는 **기존 프로세스가 새 프로세스를 만드는 방식**으로 생성된다

- ✨ **생성하는 프로세스: 부모 프로세스(parent process)**
- ✨ **생성된 프로세스: 자식 프로세스(child process)**

이 관계가 반복되면서 **프로세스 트리**가 형성된다

```
init (pid=1)
├── login (pid=8415)
│   └── bash (pid=8416)
│       ├── ps (pid=9298)
│       └── emacs (pid=9204)
├── sshd (pid=3028)
│   └── sshd (pid=3610)
│       └── tcsh (pid=4005)
└── kthreadd (pid=2)
    ├── khelper (pid=6)
    └── pdflush (pid=200)
```

## fork(): 자식 프로세스 생성

- ✨ **`fork()`: 부모 프로세스를 복제하여 새로운 자식 프로세스를 만드는 시스템 콜**

`fork()` 호출 시
- ▶ 자식 프로세스는 부모의 주소 공간을 그대로 복사한다
- ▶ 부모와 자식 모두 `fork()` 다음 줄부터 실행을 계속한다
- ▶ 반환값으로 부모와 자식을 구분한다

| 반환값 | 대상 |
|---|---|
| `0` | 자식 프로세스 |
| 자식의 PID (양수) | 부모 프로세스 |
| `-1` | 오류 발생 |

```c
#include <stdio.h>
#include <unistd.h>
#include <wait.h>

int main()
{
    pid_t pid;

    pid = fork();

    if (pid < 0) {               // 오류
        fprintf(stderr, "Fork Failed");
        return 1;
    }
    else if (pid == 0) {         // 자식 프로세스
        execlp("/bin/ls", "ls", NULL);
    }
    else {                       // 부모 프로세스
        wait(NULL);
        printf("Child Complete");
    }
    return 0;
}
```

```
부모 프로세스
   │
   │  fork()
   ├──────────────► 자식 프로세스 (부모의 복사본)
   │                    │
   │  wait()            │  execlp("/bin/ls", ...)
   │  (자식 대기)        ▼
   │               ls 프로그램으로 교체되어 실행
   │                    │
   │                    │  종료
   ◄────────────────────┘
   │
   │  "Child Complete" 출력
```

## exec(): 새 프로그램으로 교체

- ✨ **`exec()`: 현재 프로세스의 메모리를 완전히 새로운 프로그램으로 교체하는 시스템 콜**

`fork()` 후 자식이 전혀 다른 프로그램을 실행하고 싶을 때 사용한다

<br/>

- ⚠️ **`exec()` 호출이 성공하면 그 이후의 코드는 절대 실행되지 않는다**

프로세스 자체가 새 프로그램으로 덮어써지기 때문이다

```c
else if (pid == 0) {
    execlp("/bin/ls", "ls", NULL);
    printf("LINE J\n");   // exec 성공 시 이 줄은 절대 실행되지 않는다
}
```

## exit(): 프로세스 종료

프로세스가 마지막 명령어를 실행하고 나면 `exit()` 시스템 콜로 종료를 요청한다

OS는 프로세스가 사용하던 자원을 회수한다

- ▶ 할당된 메모리
- ▶ 열린 파일
- ▶ I/O 버퍼

---

## 종료 후에 생기는 두 가지 문제 상황

자식이 종료되면 부모는 `wait()`를 호출해서 자식의 종료 상태를 수거해야 한다

이 과정이 제대로 이루어지지 않으면 두 가지 문제가 생긴다

<br/>

### Zombie 프로세스

- ⚠️ **자식이 종료됐는데, 부모가 아직 `wait()`를 호출하지 않은 상태**

자식은 실행이 끝났지만, PCB가 메모리에 남아있다

부모가 `wait()`를 호출하는 순간 비로소 완전히 제거된다

```
자식: exit() 호출 → 실행 종료, but PCB 남아있음 (zombie)
부모: wait() 호출 → 자식 PCB 제거 (완전 소멸)
```

### Orphan 프로세스

- ⚠️ **부모가 `wait()` 없이 먼저 종료된 경우, 자식은 고아(orphan) 프로세스가 된다**

UNIX에서는 `init` 프로세스(pid=1)가 고아 프로세스를 자동으로 입양하여 관리한다
