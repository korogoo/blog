> 프로세스는 항상 실행 중이지 않다

---

## 문제: CPU 하나로 수십 개의 프로세스를 어떻게 관리하는가?

CPU 코어는 한 번에 하나의 프로세스만 실행할 수 있다

그렇다면 나머지 프로세스들은 어디서 무엇을 하고 있는가?

- [!] **OS는 각 프로세스가 현재 "어떤 상황인지"를 구분해서 관리해야 한다**

---

## 프로세스의 5가지 상태

- [I] **프로세스는 실행되면서 상태(state)가 바뀐다**

| 상태 | 설명 |
|---|---|
| **New** | 프로세스가 막 생성된 상태 |
| **Ready** | CPU를 받을 준비가 됐지만, 아직 차례가 아닌 상태 |
| **Running** | CPU를 할당받아 명령어를 실행 중인 상태 |
| **Waiting** | I/O 완료나 특정 이벤트를 기다리는 상태 |
| **Terminated** | 실행이 끝난 상태 |

---

## 상태 전이 다이어그램

```
                    admitted
  [New] ──────────────────────► [Ready] ◄──────────────────┐
                                   │  ▲                    │
                    scheduler      │  │  interrupt         │
                    dispatches     │  │                    │
                                   ▼  │                    │
                              [Running] ────────► [Terminated]
                                   │
                                   │  I/O 또는 이벤트 대기
                                   ▼
                              [Waiting]
                                   │
                                   │  I/O 또는 이벤트 완료
                                   └──────────────────────►[Ready]
```

<br/>

**각 전이의 의미**

- [>] **New → Ready**: 프로세스 생성 완료, 실행 준비됨
- [>] **Ready → Running**: 스케줄러가 이 프로세스에 CPU 할당
- [>] **Running → Ready**: 타임 슬라이스 소진 또는 인터럽트 발생 - CPU를 빼앗김
- [>] **Running → Waiting**: I/O 요청 등 대기 이벤트 발생
- [>] **Waiting → Ready**: I/O 완료, 다시 CPU를 기다리는 줄에 합류
- [>] **Running → Terminated**: 실행 완료

---

## Ready와 Waiting의 차이

두 상태 모두 "실행 중이 아닌" 상태지만, 이유가 다르다

| 상태 | CPU가 주어지면? | 이유 |
|---|---|---|
| **Ready** | 즉시 실행 가능 | CPU만 기다리는 중 |
| **Waiting** | 실행 불가 | I/O나 이벤트가 끝나야 함 |

- [i] **Waiting 상태의 프로세스에게 CPU를 줘봤자 아무것도 못 한다**

그래서 OS는 이 둘을 분리해서 관리한다
