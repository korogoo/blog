> fork()는 읽는 것과 직접 추적하는 것이 전혀 다르다

---

## 풀기 전에: fork() 핵심 규칙 정리

- [>] `fork()` 호출 시 자식은 부모의 **주소 공간을 복사**한다 - 별도의 메모리 공간
- [>] 자식에게 반환값은 `0`, 부모에게 반환값은 자식의 PID(양수)
- [>] `fork()` 이후 부모와 자식은 **독립적으로** 실행된다
- [>] `exec()`가 성공하면 그 이후 코드는 실행되지 않는다

## Exercise 3.1: 부모의 value는 얼마인가?

```c
int value = 5;

int main()
{
    pid_t pid;
    pid = fork();

    if (pid == 0) {        // 자식 프로세스
        value += 15;
        return 0;
    }
    else if (pid > 0) {    // 부모 프로세스
        wait(NULL);
        printf("Parent: value = %d\n", value);  // LINE A
    }
}
```

**정답: `value = 5`**

<br/>

- ["] **`fork()`는 주소 공간을 복사한다 - 공유하지 않는다**

자식이 `value += 15`를 해도 그것은 자식의 메모리에서 일어난 일이다

부모의 `value`는 여전히 `5`다

## Exercise 3.2: 프로세스가 몇 개 생성되는가?

```c
int main()
{
    fork();   // ①
    fork();   // ②
    fork();   // ③
    return 0;
}
```

**정답: 8개**

<br/>

- ["] **`fork()`를 호출할 때마다 현재 존재하는 모든 프로세스가 각자 복제된다**

```
시작:          P0                          (1개)
fork() ①:     P0, P1                      (2개)
fork() ②:     P0, P1, P2, P3             (4개)
fork() ③:     P0, P1, P2, P3, P4, P5, P6, P7  (8개)
```

`fork()`가 n번 호출되면 최대 2ⁿ개의 프로세스가 생성된다

## Exercise 3.11: 루프 안의 fork()는 몇 개를 만드는가?

```c
int main()
{
    int i;
    for (i = 0; i < 4; i++)
        fork();
    return 0;
}
```

**정답: 16개**

<br/>

루프는 `fork()`를 4번 호출한다

단, 자식 프로세스도 루프를 이어서 실행하므로 단순히 4번이 아니다

```
i=0: 1개 → fork() → 2개
i=1: 2개 → 각자 fork() → 4개
i=2: 4개 → 각자 fork() → 8개
i=3: 8개 → 각자 fork() → 16개
```

2⁴ = 16개

## Exercise 3.12: LINE J는 언제 실행되는가?

```c
int main()
{
    pid_t pid;
    pid = fork();

    if (pid == 0) {        // 자식 프로세스
        execlp("/bin/ls", "ls", NULL);
        printf("LINE J\n");
    }
    else if (pid > 0) {    // 부모 프로세스
        wait(NULL);
        printf("Child Complete\n");
    }
    return 0;
}
```

**정답: LINE J는 절대 실행되지 않는다**

<br/>

- ["] **`execlp()`가 성공하면 프로세스의 메모리가 `ls` 프로그램으로 완전히 교체된다**

`printf("LINE J\n")` 코드 자체가 메모리에서 사라지므로, 실행될 수 없다

`LINE J`가 출력되는 경우는 `execlp()`가 실패했을 때뿐이다

## Exercise 3.13: 각 줄의 pid 값은 무엇인가?

```c
int main()
{
    pid_t pid, pid1;
    pid = fork();

    if (pid == 0) {        // 자식 프로세스
        pid1 = getpid();
        printf("child: pid = %d\n",  pid);   // A
        printf("child: pid1 = %d\n", pid1);  // B
    }
    else if (pid > 0) {    // 부모 프로세스
        pid1 = getpid();
        printf("child: pid = %d\n",  pid);   // C
        printf("child: pid1 = %d\n", pid1);  // D
        wait(NULL);
    }
    return 0;
}
```

**정답** (실제 PID는 실행마다 다르지만, 관계는 고정)

| 줄 | 값 | 이유 |
|---|---|---|
| **A** | `0` | 자식에서 `fork()` 반환값은 항상 0 |
| **B** | 자식의 PID (예: 5678) | `getpid()`는 자기 자신의 PID를 반환 |
| **C** | 자식의 PID (예: 5678) | 부모에서 `fork()` 반환값은 자식의 PID |
| **D** | 부모의 PID (예: 1234) | `getpid()`는 자기 자신의 PID를 반환 |

- [i] **A와 C의 `pid`는 같은 값(자식의 PID)이지만, A는 자식이 출력하고 C는 부모가 출력한다**

## Exercise 3.16: LINE X와 LINE Y의 출력은?

```c
#define SIZE 5
int nums[SIZE] = {0, 1, 2, 3, 4};

int main()
{
    pid_t pid;
    int i;
    pid = fork();

    if (pid == 0) {        // 자식 프로세스
        for (i = 0; i < SIZE; i++) {
            nums[i] *= i;
            printf("CHILD: %d \n", nums[i]);   // LINE X
        }
        return 0;
    }
    else if (pid > 0) {    // 부모 프로세스
        wait(NULL);
        for (i = 0; i < SIZE; i++) {
            printf("PARENT: %d \n", nums[i]);  // LINE Y
        }
    }
}
```

**자식 출력 (LINE X)**

```
CHILD: 0    (0 * 0)
CHILD: 1    (1 * 1)
CHILD: 4    (2 * 2)
CHILD: 9    (3 * 3)
CHILD: 16   (4 * 4)
```

**부모 출력 (LINE Y)**

```
PARENT: 0
PARENT: 1
PARENT: 2
PARENT: 3
PARENT: 4
```

- ["] **자식이 `nums`를 수정해도 부모의 `nums`는 바뀌지 않는다**

`fork()`로 복사된 별도의 주소 공간이기 때문이다 — Exercise 3.1과 동일한 원리
