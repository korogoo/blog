> 수백 개의 프로세스를 관리하려면, 각각에 대한 정보를 어딘가에 저장해야 한다

---

## 문제: 프로세스를 전환할 때 무엇을 기억해야 하는가?

프로세스 A를 멈추고 프로세스 B를 실행한다고 하자

나중에 A를 다시 실행하려면?

- [!] **A가 어디까지 실행했는지, 레지스터 값은 무엇이었는지, 어떤 파일을 열었는지 등 모든 걸 기억해야 한다**

---

## PCB: 프로세스의 정보 저장소

- [I] **PCB(Process Control Block): OS가 각 프로세스를 관리하기 위해 유지하는 자료구조**

TCB(Task Control Block) 라고도 부른다

프로세스 하나당 PCB 하나가 대응된다

---

## PCB에 저장되는 정보

| 항목 | 설명 |
|---|---|
| **Process state** | 현재 상태 (New / Ready / Running / Waiting / Terminated) |
| **Program counter** | 다음에 실행할 명령어의 주소 |
| **CPU registers** | 프로세스가 사용하던 레지스터 값들 |
| **CPU scheduling info** | 우선순위, 스케줄링 큐 포인터 등 |
| **Memory management info** | 페이지 테이블, 세그먼트 테이블 등 |
| **Accounting info** | CPU 사용 시간, 실행 시간 등 |
| **I/O status info** | 열린 파일 목록, 할당된 I/O 장치 등 |

<br/>

- ["] **PCB는 프로세스의 ==현재 스냅샷==이다**

프로세스가 실행을 멈출 때 현재 상태를 PCB에 저장하고,
다시 실행될 때 PCB에서 복원한다

---

## PCB가 없다면?

```
프로세스 A 실행 중
  → 인터럽트 발생
  → 프로세스 B 실행
  → 다시 A로 돌아왔는데...
  → A가 어디까지 했는지 모른다 → 처음부터 다시 실행?
```

- [i] **PCB 덕분에 OS는 수백 개의 프로세스를 끊김 없이 전환할 수 있다**
