> 데드락이 생기려면 반드시 네 가지 조건이 동시에 성립해야 한다

---

## 4가지 필요 조건

이 네 가지가 **동시에** 성립할 때만 데드락이 발생한다

| 조건 | 설명 |
|---|---|
| **상호 배제** (Mutual Exclusion) | 최소 하나의 자원이 비공유(non-sharable) 모드로 점유됨 |
| **점유 대기** (Hold and Wait) | 자원을 하나 이상 점유한 채로, 다른 자원을 기다림 |
| **비선점** (No Preemption) | 자원을 강제로 빼앗을 수 없음 — 스스로 반납해야 함 |
| **순환 대기** (Circular Wait) | 대기 관계가 순환을 이룸: T1→T2→T3→...→T1 |

ℹ **네 조건 중 하나라도 제거하면 데드락이 발생하지 않는다** — 이것이 데드락 예방의 원리

---

## 자원 할당 그래프 (Resource-Allocation Graph)

데드락 상태를 시각적으로 표현하는 방향 그래프

| 표기 | 의미 |
|---|---|
| 원(○) | 스레드 T |
| 사각형(□) | 자원 타입 R (안의 점 = 인스턴스 수) |
| T → R | 요청 간선: T가 R을 요청 중 |
| R → T | 할당 간선: R의 인스턴스가 T에 할당됨 |

**데드락이 있는 그래프**

```
T1 ──요청──► R2 ──할당──► T2
↑                           │
할당                         요청
│                           ▼
R1 ◄──요청── T3 ◄──할당── R1
             (T3도 R2를 요청... 순환)
```

**순환이 있어도 데드락이 아닌 경우**

자원에 여분의 인스턴스가 있으면, 순환 안에 없는 스레드가 자원을 반납해 순환이 풀릴 수 있다

---

## 그래프와 데드락의 관계

| 그래프 상태 | 결론 |
|---|---|
| 사이클 없음 | 데드락 **아님** |
| 사이클 있음, 각 자원에 인스턴스 1개 | 데드락 **맞음** |
| 사이클 있음, 자원에 인스턴스 여러 개 | 데드락일 수도, 아닐 수도 있음 |

⚠️ **사이클은 데드락의 필요조건이지, 충분조건이 아니다**
