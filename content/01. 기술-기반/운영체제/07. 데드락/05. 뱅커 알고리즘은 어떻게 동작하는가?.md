> 은행이 대출을 심사하듯, OS가 자원 할당을 심사한다

---

## 뱅커 알고리즘이란

자원에 인스턴스가 여러 개 있을 때 사용하는 **데드락 회피 알고리즘**

은행이 모든 고객의 최대 대출 한도를 알고, 현재 가용 자금이 부족해지지 않게 대출을 허용하는 방식에서 이름이 붙었다

---

## 자료 구조 (n = 스레드 수, m = 자원 타입 수)

| 자료 구조 | 설명 |
|---|---|
| `Available[m]` | 현재 사용 가능한 각 자원 타입의 인스턴스 수 |
| `Max[n×m]` | 각 스레드의 최대 자원 요구량 |
| `Allocation[n×m]` | 현재 각 스레드에 할당된 자원 수 |
| `Need[n×m]` | 각 스레드가 앞으로 더 필요한 자원 수 |

$$Need[i][j] = Max[i][j] - Allocation[i][j]$$

---

## 예제 설정

- 스레드: T0, T1, T2, T3, T4
- 자원 타입: A(10개), B(5개), C(7개)

**현재 상태**

|  | Allocation (A,B,C) | Max (A,B,C) | Need (A,B,C) |
|---|---|---|---|
| T0 | 0,1,0 | 7,5,3 | 7,4,3 |
| T1 | 2,0,0 | 3,2,2 | 1,2,2 |
| T2 | 3,0,2 | 9,0,2 | 6,0,0 |
| T3 | 2,1,1 | 2,2,2 | 0,1,1 |
| T4 | 0,0,2 | 4,3,3 | 4,3,1 |

할당 합계: A=7, B=2, C=5 → **Available = (10-7, 5-2, 7-5) = (3,3,2)**

---

## Safety Algorithm (안전 순서 탐색)

```
Work = Available = (3,3,2)
Finish = [false, false, false, false, false]

아직 끝나지 않은 스레드 중 Need[i] ≤ Work 인 것을 찾아 실행:
```

| 단계 | 선택 | Need ≤ Work? | Work 갱신 |
|---|---|---|---|
| 1 | T1 | (1,2,2) ≤ (3,3,2) ✓ | (3,3,2) + (2,0,0) = (5,3,2) |
| 2 | T3 | (0,1,1) ≤ (5,3,2) ✓ | (5,3,2) + (2,1,1) = (7,4,3) |
| 3 | T4 | (4,3,1) ≤ (7,4,3) ✓ | (7,4,3) + (0,0,2) = (7,4,5) |
| 4 | T2 | (6,0,0) ≤ (7,4,5) ✓ | (7,4,5) + (3,0,2) = (10,4,7) |
| 5 | T0 | (7,4,3) ≤ (10,4,7) ✓ | 완료 |

- 💬 **안전 순서 `<T1, T3, T4, T2, T0>` 존재 → 현재 상태는 안전 상태**

---

## Resource-Request Algorithm (요청 처리)

T1이 (1,0,2)를 요청할 때 (`Request1 = (1,0,2)`)

**Step 1**: Request ≤ Need[1] 확인
`(1,0,2) ≤ (1,2,2)` ✓

**Step 2**: Request ≤ Available 확인
`(1,0,2) ≤ (3,3,2)` ✓

**Step 3**: 임시 할당 (테스트)
```
Available    = (3,3,2) - (1,0,2) = (2,3,0)
Allocation[1]= (2,0,0) + (1,0,2) = (3,0,2)
Need[1]      = (1,2,2) - (1,0,2) = (0,2,0)
```

**Step 4**: Safety Algorithm 재실행 → `<T1, T3, T4, T0, T2>` 존재 → 안전

- 💬 **할당 승인**

---

## T4가 (3,3,0) 요청할 때

Step 1: Request ≤ Need[4]?
`(3,3,0) ≤ (4,3,1)` ✓

Step 2: Request ≤ Available?
`(3,3,0) ≤ (3,3,2)` ✓

Step 3: 임시 할당 후 Safety Algorithm → 안전 순서 없음

- ⚠️ **할당 거부 — T4는 대기**

---

## T0가 (0,2,0) 요청할 때

Step 2: Request ≤ Available?
`(0,2,0) ≤ (3,3,2)` ✓

Step 3: 임시 할당 후 Safety Algorithm → 안전 순서 없음

- ⚠️ **할당 거부**

---

## 뱅커 알고리즘의 한계

- ℹ **각 스레드가 최대 요구량을 미리 선언해야 한다 — 실제 애플리케이션에서는 어렵다**
- ℹ **스레드 수와 자원 수가 고정되어 있다고 가정한다**
- ℹ **요청마다 Safety Algorithm을 실행해야 해서 오버헤드가 크다**
