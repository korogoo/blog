## 데드락이란

✨ **데드락(Deadlock): 프로세스 집합 안의 모든 프로세스가, 그 집합 안의 다른 프로세스만이 발생시킬 수 있는 이벤트를 기다리며 영원히 대기하는 상태**

기다리는 스레드는 절대 상태를 바꿀 수 없다
왜냐하면 자신이 필요한 자원이, 자신처럼 기다리고 있는 다른 스레드들에 의해 점유되어 있기 때문이다

---

## 자원 사용의 3단계

모든 자원 사용은 이 순서를 따른다

```
Request (요청) → Use (사용) → Release (반납)
```

| 단계 | 설명 |
|---|---|
| **Request** | 자원을 요청. 즉시 할당받지 못하면 대기 |
| **Use** | 자원을 사용 |
| **Release** | 자원 반납 |

---

## 데드락이 발생하는 상황

두 스레드가 서로 상대방이 가진 뮤텍스를 기다릴 때

```c
// Thread 1              // Thread 2
pthread_mutex_lock(&A);  pthread_mutex_lock(&B);
pthread_mutex_lock(&B);  pthread_mutex_lock(&A);  ← A는 Thread 1이 보유
...                      ...
```

```
Thread 1: A 보유 → B 대기
Thread 2: B 보유 → A 대기

T1 ──보유──► A ◄──대기── T2
T1 ──대기──► B ◄──보유── T2
```

둘 다 영원히 대기 — 데드락

---

## 자원의 종류

시스템의 자원은 동일한 인스턴스를 여러 개 가질 수 있다

```
CPU 코어:    4개의 인스턴스
프린터:      2개의 인스턴스
뮤텍스 락:   1개의 인스턴스
```

같은 타입이면 어느 인스턴스를 받아도 요청이 충족된다
