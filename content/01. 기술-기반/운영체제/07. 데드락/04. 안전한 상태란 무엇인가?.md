> 지금 당장 데드락이 없더라도, 잘못된 할당이 미래에 데드락을 만들 수 있다

---

## 예방 vs 회피

| 방법 | 접근 |
|---|---|
| **예방** | 4가지 조건 중 하나를 원천적으로 제거 |
| **회피** | 각 요청을 처리할 때, 이 할당이 미래에 데드락을 유발하는지 미리 판단 |

회피는 더 유연하다 — 조건을 없애는 게 아니라, 위험한 할당만 거부한다

---

## 회피에 필요한 정보

- ✨ **각 스레드가 앞으로 최대 몇 개의 자원을 요청할지(Max) 미리 선언해야 한다**

OS는 이 정보를 이용해 "이 요청을 허락해도 안전한가?"를 판단한다

---

## 안전 상태 (Safe State)

- ✨ **안전 상태: 현재 자원을 특정 순서대로 스레드들에게 할당해서, 모든 스레드가 결국 최대 요구량을 받고 완료될 수 있는 상태**

이 순서를 **안전 순서(safe sequence)** 라고 한다

**안전 순서의 조건**: 스레드 Ti가 아직 필요한 자원의 양이, 현재 가용 자원 + Ti 앞에 있는 모든 스레드들이 반납할 자원으로 충족될 수 있어야 한다

---

## 안전 상태 / 불안전 상태 / 데드락의 관계

```
┌──────────────────────────────────┐
│           전체 상태               │
│  ┌────────────────────────────┐  │
│  │        불안전 상태          │  │
│  │  ┌──────────────────────┐  │  │
│  │  │    데드락 상태         │  │  │
│  │  └──────────────────────┘  │  │
│  └────────────────────────────┘  │
│    안전 상태                      │
└──────────────────────────────────┘
```

- ▶ 안전 상태 → 데드락이 아님 (보장)
- ▶ 데드락 상태 → 불안전 상태 (데드락은 불안전의 부분집합)
- ▶ 불안전 상태 → 데드락일 수도 있고 아닐 수도 있음

- 💬 **회피 알고리즘의 핵심: 항상 안전 상태를 유지한다**

요청이 오면 임시로 할당해보고, 안전 상태가 유지되면 허락 / 불안전해지면 거부

---

## 안전 상태 예시

12개의 테이프 드라이브, 3개 스레드

| 스레드 | 최대 요구 | 현재 보유 |
|---|---|---|
| T0 | 10 | 5 |
| T1 | 4 | 2 |
| T2 | 9 | 3 |

현재 가용: 12 - (5+2+3) = 2

안전 순서 찾기: 가용=2
- T1 필요: 4-2=2 ≤ 2 ✓ → T1 실행 → 가용=2+2=4
- T0 필요: 10-5=5 ≤ 4? No → T2 먼저
- T2 필요: 9-3=6 ≤ 4? No
- 다시 T0: 필요=5 ≤ 4? No

→ 이 상태에서는 `<T1, T0, T2>` 확인: T1(2)→가용4, T0(5) > 4 ...

실제로 가용이 2일 때 `<T1, T0, T2>`:
- T1 완료 → 가용=4
- T0 필요=5 > 4 → 아직 안됨... 

이것은 불안전 상태의 예시가 된다. 만약 가용이 3이었다면:
- T1 완료 → 가용=5
- T0 완료 → 가용=10  
- T2 완료 ✓ → 안전 상태, 순서: `<T1, T0, T2>`

- ℹ **안전 순서가 하나라도 존재하면 안전 상태다 — 유일할 필요는 없다**
