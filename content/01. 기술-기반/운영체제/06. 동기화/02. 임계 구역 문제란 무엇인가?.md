> 동시에 실행되면 안 되는 구간이 있다. 그 구간을 어떻게 보호할 것인가?

---

## 임계 구역 (Critical Section)

- ✨ **임계 구역(Critical Section): 프로세스가 공유 데이터에 접근하고 수정하는 코드 구간**

한 프로세스가 임계 구역을 실행 중일 때, 다른 프로세스는 자신의 임계 구역에 들어올 수 없다

---

## 프로세스 코드의 4가지 구간

```
while (true) {
    /* entry section */      ← 임계 구역 진입 허가 요청
    
        /* critical section */   ← 공유 데이터 접근
    
    /* exit section */       ← 임계 구역 빠져나옴을 알림
    
    /* remainder section */  ← 나머지 코드
}
```

---

## 임계 구역 문제의 3가지 요구사항

올바른 해결책은 세 가지를 모두 만족해야 한다

### 1. 상호 배제 (Mutual Exclusion)

- ✨ **한 프로세스가 임계 구역을 실행 중이면, 다른 프로세스는 자신의 임계 구역에 들어올 수 없다**

가장 기본적인 요구사항이다

### 2. 진행 (Progress) — 데드락 방지

- ✨ **임계 구역에 있는 프로세스가 없고, 들어가려는 프로세스가 있다면 다음 진입자 선택이 무한정 미뤄질 수 없다**

아무도 임계 구역을 쓰고 있지 않은데, 아무도 못 들어가는 상황을 방지한다

### 3. 유한 대기 (Bounded Waiting) — 기아 방지

- ✨ **한 프로세스가 진입 요청을 한 후, 다른 프로세스들이 임계 구역에 들어갈 수 있는 횟수에 상한이 있어야 한다**

특정 프로세스가 영원히 기다리는 상황(starvation)을 방지한다

## 현실적인 예: pid 할당의 race condition

```
next_available_pid = 2350

프로세스 A: next_pid = next_available_pid → next_pid = 2350
프로세스 B: next_pid = next_available_pid → next_pid = 2350  (같은 pid!)
프로세스 A: next_available_pid++
프로세스 B: next_available_pid++
```

두 프로세스가 같은 pid를 받는다 — 심각한 오류

## 커널에서의 접근: 선점 vs 비선점

| 방식 | 특징 |
|---|---|
| **비선점 커널** | 커널 모드에서 실행 중인 프로세스는 스스로 CPU를 양보할 때까지 선점 안 됨 — race condition 걱정 없음 |
| **선점 커널** | 커널 모드에서도 선점 가능 — 설계가 어렵지만 더 빠른 응답성 |

- ℹ **Linux, Windows는 선점 커널을 사용한다 — 응답성이 중요하기 때문**
