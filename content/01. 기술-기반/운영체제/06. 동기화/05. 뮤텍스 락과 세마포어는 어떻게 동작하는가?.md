## Mutex Lock

- [I] **Mutex(Mutual Exclusion) Lock: 임계 구역을 보호하는 가장 단순한 동기화 도구**

두 가지 연산과 하나의 변수로 이루어진다

| 요소 | 설명 |
|---|---|
| `acquire()` | 락 획득 — 이미 잠겨있으면 대기 |
| `release()` | 락 반환 |
| `available` | 락의 사용 가능 여부 (boolean) |

```c
// 임계 구역 사용 패턴
acquire();          // 잠금
/* critical section */
release();          // 잠금 해제
```

`acquire()`와 `release()`는 **원자적**으로 실행되어야 한다 — `compare_and_swap`으로 구현

---

## C 구현: pthread_mutex

```c
#include <pthread.h>

int sum = 0;
pthread_mutex_t mutex;

void *counter(void *param) {
    for (int k = 0; k < 10000; k++) {
        pthread_mutex_lock(&mutex);    // acquire
        sum++;
        pthread_mutex_unlock(&mutex);  // release
    }
    pthread_exit(0);
}

int main() {
    pthread_t tid1, tid2;
    pthread_mutex_init(&mutex, NULL);
    pthread_create(&tid1, NULL, counter, NULL);
    pthread_create(&tid2, NULL, counter, NULL);
    pthread_join(tid1, NULL);
    pthread_join(tid2, NULL);
    printf("sum = %d\n", sum);  // 항상 20000
}
```

## Busy Waiting과 Spinlock

Mutex의 기본 구현에서 락이 잠겨있으면 `acquire()` 안에서 **루프를 돌며 계속 확인**한다

```c
acquire() {
    while (!available)  // 락이 풀릴 때까지 루프
        ;
    available = false;
}
```

- [I] **Busy Waiting(바쁜 대기): 락이 풀릴 때까지 CPU를 점유하며 반복 확인하는 방식**
- [I] **Spinlock: Busy waiting 방식을 사용하는 mutex lock**

**단점**: 다른 프로세스가 쓸 수 있는 CPU 사이클을 낭비한다

**장점**: 컨텍스트 스위치가 없다 — 락 대기 시간이 매우 짧을 것으로 예상되면 오히려 효율적이다

- [i] **멀티코어 시스템에서는 spinlock이 유리한 상황이 있다**

한 코어에서 스핀하는 동안, 다른 코어에서 임계 구역을 실행하고 락을 곧 풀어준다면 — 컨텍스트 스위치 비용을 아낄 수 있다

## Semaphore

- [I] **세마포어(Semaphore): 정수 변수 S — `wait()`와 `signal()` 두 원자적 연산으로만 접근 가능**

Edsger Dijkstra가 도입했으며, P()와 V()로도 부른다
(Proberen = 테스트, Verhogen = 증가)

```c
wait(S) {
    while (S <= 0)  // 양수가 될 때까지 대기
        ;
    S--;
}

signal(S) {
    S++;
}
```

---

## 이진 세마포어 vs 카운팅 세마포어

| 종류 | 범위 | 용도 |
|---|---|---|
| **Binary Semaphore** | 0 또는 1 | Mutex lock과 동일한 역할 |
| **Counting Semaphore** | 제한 없는 정수 | 유한한 자원을 여러 개 관리 |

**카운팅 세마포어 사용법**

```
초기값 = 사용 가능한 자원 수

자원 사용 시:   wait(S)   → S 감소
자원 반납 시: signal(S)   → S 증가
S = 0 이면:  자원 없음 → 대기
```

---

## C 구현: sem_t

```c
#include <semaphore.h>

int sum = 0;
sem_t sem;

void *counter(void *param) {
    for (int k = 0; k < 10000; k++) {
        sem_wait(&sem);    // wait → S-- (0이면 대기)
        sum++;
        sem_post(&sem);    // signal → S++
    }
    pthread_exit(0);
}

int main() {
    sem_init(&sem, 0, 1);  // 이진 세마포어: 초기값 1
    // ...
}
```

**카운팅 세마포어: 스레드 5개 동시 허용**

```c
sem_init(&sem, 0, 5);  // 초기값 5 → 최대 5개 스레드 동시 접근
```

## Semaphore로 실행 순서 제어하기

mutex 외에도 두 프로세스 간의 **순서를 강제**하는 데 쓸 수 있다

S1이 반드시 S2보다 먼저 실행되어야 한다면:

```
공유 세마포어 synch = 0으로 초기화

P1:                    P2:
S1 실행;               wait(synch);  ← S1이 끝날 때까지 대기
signal(synch);         S2 실행;
```

## Semaphore 구현 개선: Busy Waiting 제거

기본 `wait()`는 busy waiting을 사용한다. 이를 개선하면:

```c
typedef struct {
    int value;
    struct process *list;  // 대기 중인 프로세스 목록
} semaphore;

wait(semaphore *S) {
    S->value--;
    if (S->value < 0) {
        // 이 프로세스를 S->list에 추가
        block();           // 대기 상태로 전환 (CPU 양보)
    }
}

signal(semaphore *S) {
    S->value++;
    if (S->value <= 0) {
        // S->list에서 프로세스 P를 꺼냄
        wakeup(P);         // P를 Ready 상태로 전환
    }
}
```
