> 하드웨어 도움 없이, 알고리즘만으로 해결할 수 있을까?

---

## Peterson's Solution

두 프로세스가 임계 구역에 교대로 진입하는 상황을 위한 **고전적인 소프트웨어 해결책**이다

두 가지 공유 변수를 사용한다

| 변수 | 역할 |
|---|---|
| `turn` | 지금 누가 임계 구역에 들어갈 차례인지 |
| `flag[2]` | 각 프로세스가 임계 구역에 들어가고 싶은지 여부 |

---

## 코드 구조

```c
int turn;
int flag[2];  // flag[0]: P0의 의사, flag[1]: P1의 의사

// 프로세스 Pi (i=0 또는 1, j는 상대방)
while (true) {
    /* entry section */
    flag[i] = true;     // "나 들어가고 싶어"
    turn = j;           // "그래도 먼저 들어가"
    while (flag[j] && turn == j)
        ;               // j가 들어가고 싶고 j 차례면 기다림

    /* critical section */

    /* exit section */
    flag[i] = false;    // "나 다 했어"

    /* remainder section */
}
```

---

## 왜 올바른가?

### 상호 배제

Pi가 임계 구역에 있으려면 `flag[j] == false` 또는 `turn == i` 여야 한다

Pj가 동시에 임계 구역에 있으려면 `flag[i] == false` 또는 `turn == j` 여야 한다

`turn`은 동시에 i와 j가 될 수 없으므로 — 둘이 동시에 진입하는 것은 불가능하다

### 진행 & 유한 대기

Pj가 임계 구역에 없고 들어가려 하지 않으면 (`flag[j] == false`), Pi는 즉시 진입한다

Pj가 임계 구역에 있고 나오면 `flag[j] = false`로 설정되어 Pi가 진입할 수 있다

한 번 기다리면 다음 차례에는 반드시 진입 가능하므로 — 유한 대기도 보장된다

## C 구현 예시

```c
// 생산자 (i=0)              // 소비자 (i=1)
flag[0] = true;              flag[1] = true;
turn = 1;                    turn = 0;
while (flag[1] && turn == 1) while (flag[0] && turn == 0)
    ;                            ;
/* critical section */       /* critical section */
sum++;                       sum--;
flag[0] = false;             flag[1] = false;
```

## 주의: 현대 CPU에서는 보장되지 않을 수 있다

- ⚠️ **현대 컴파일러와 CPU는 성능 최적화를 위해 명령어 순서를 재배치(reorder)할 수 있다**

Peterson's 알고리즘은 명령어가 순서대로 실행된다고 가정하는데,
이 가정이 깨지면 올바르게 동작하지 않을 수 있다

- ℹ **Peterson's solution은 올바른 알고리즘적 아이디어를 담고 있다 — 상호 배제/진행/유한 대기의 복잡성을 이해하는 데 여전히 중요하다**

실제 시스템에서는 하드웨어 지원이나 higher-level 도구를 사용한다
