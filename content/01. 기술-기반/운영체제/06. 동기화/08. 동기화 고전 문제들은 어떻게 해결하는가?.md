## 1. Bounded-Buffer Problem (유한 버퍼 문제)

Producer-Consumer 문제에 버퍼 크기 제한이 추가된 버전이다

**공유 자료구조**

```
세마포어 mutex = 1          (버퍼 접근 상호 배제)
세마포어 empty = n          (비어있는 버퍼 슬롯 수, n으로 초기화)
세마포어 full  = 0          (채워진 버퍼 슬롯 수, 0으로 초기화)
```

**생산자**

```c
do {
    /* 아이템 생산 */
    wait(empty);           // 빈 슬롯이 생길 때까지 대기
    wait(mutex);           // 버퍼 접근 락
    /* 버퍼에 아이템 삽입 */
    signal(mutex);
    signal(full);          // 채워진 슬롯 +1
} while (true);
```

**소비자**

```c
do {
    wait(full);            // 채워진 슬롯이 생길 때까지 대기
    wait(mutex);
    /* 버퍼에서 아이템 꺼냄 */
    signal(mutex);
    signal(empty);         // 빈 슬롯 +1
    /* 아이템 소비 */
} while (true);
```

**Java 구현 핵심 (`synchronized` + `wait`/`notify`)**

```java
synchronized public void give(int money) throws InterruptedException {
    while (count == buffer.length)  // 버퍼가 꽉 찼으면
        wait();                     // 대기 (락 반납)
    buffer[in] = money;
    in = (in + 1) % buffer.length;
    count++;
    notify();                       // 소비자 깨움
}

synchronized public int take() throws InterruptedException {
    while (count == 0)              // 버퍼가 비었으면
        wait();                     // 대기
    int money = buffer[out];
    out = (out + 1) % buffer.length;
    count--;
    notify();                       // 생산자 깨움
    return money;
}
```

## 2. Readers-Writers Problem

여러 프로세스가 하나의 데이터를 공유할 때:
- **Reader**: 읽기만 → 동시에 여러 명이 읽어도 OK
- **Writer**: 쓰기 → 반드시 독점 접근

**첫 번째 Readers-Writers 문제**: 읽고 있는 Reader가 있다면, Writer는 기다려야 한다. 단, 새 Reader는 계속 진입 가능

**공유 자료구조**

```
세마포어 rw_mutex = 1   (Writer와 Reader 간 상호 배제)
세마포어 mutex    = 1   (read_count 수정 상호 배제)
int       read_count = 0 (현재 읽고 있는 Reader 수)
```

**Writer**

```c
do {
    wait(rw_mutex);
    /* 쓰기 */
    signal(rw_mutex);
} while (true);
```

**Reader**

```c
do {
    wait(mutex);
    read_count++;
    if (read_count == 1)  // 첫 번째 Reader가 Writer를 막음
        wait(rw_mutex);
    signal(mutex);
    /* 읽기 */
    wait(mutex);
    read_count--;
    if (read_count == 0)  // 마지막 Reader가 Writer를 풀어줌
        signal(rw_mutex);
    signal(mutex);
} while (true);
```

- ℹ **이 방식에서 Writer는 기아 현상이 발생할 수 있다** — Reader가 계속 들어오면 Writer는 영원히 기다린다

**Java 구현 핵심**

```java
synchronized public void acquireReadLock() throws InterruptedException {
    while (isWriting)
        wait();
    readerCount++;
}

synchronized public void releaseReadLock() {
    readerCount--;
    if (readerCount == 0)
        notify();  // 마지막 Reader가 나갈 때 Writer 깨움
}

synchronized public void acquireWriteLock() throws InterruptedException {
    while (readerCount > 0 || isWriting)
        wait();
    isWriting = true;
}

synchronized public void releaseWriteLock() {
    isWriting = false;
    notifyAll();  // 모든 대기 스레드 깨움
}
```

## 3. Dining-Philosophers Problem (식사하는 철학자)

5명의 철학자가 원형 테이블에 앉아 있고, 젓가락이 5개 있다

- 먹으려면 양쪽 젓가락 2개를 동시에 들어야 한다
- 젓가락 하나를 들고 나머지를 기다리는 중 모든 철학자가 왼쪽 젓가락만 들면 → **데드락**

**문제의 본질**: 여러 프로세스가 여러 자원을 **동시에** 필요로 할 때 데드락 없이 할당하는 방법

---

### 단순 세마포어 해결책의 문제

```c
// 철학자 i의 동작
wait(chopstick[i]);           // 왼쪽 젓가락
wait(chopstick[(i+1) % 5]);   // 오른쪽 젓가락
/* 식사 */
signal(chopstick[i]);
signal(chopstick[(i+1) % 5]);
```

모든 철학자가 동시에 왼쪽 젓가락을 들면 → 오른쪽 젓가락이 없어 데드락

---

### 데드락 해결 방법 3가지

| 방법 | 설명 |
|---|---|
| **최대 4명만** | 동시에 앉을 수 있는 철학자를 4명으로 제한 |
| **양쪽 동시에** | 두 젓가락 모두 사용 가능할 때만 집음 |
| **비대칭** | 홀수 번 철학자는 왼쪽 먼저, 짝수 번은 오른쪽 먼저 |

---

### 모니터 해결책 (데드락 없음)

철학자의 상태를 세 가지로 구분한다: THINKING / HUNGRY / EATING

```
철학자 i는 양쪽 이웃이 모두 EATING이 아닐 때만 EATING으로 전환 가능
```

```c
void test(int i) {
    if (state[i] == HUNGRY &&
        state[leftOf(i)] != EATING &&
        state[rightOf(i)] != EATING)
    {
        state[i] = EATING;
        signal(cond_vars[i]);  // 자신을 깨움
    }
}

void pickup(int i) {
    lock();
    state[i] = HUNGRY;
    test(i);
    while (state[i] != EATING)
        wait(cond_vars[i]);  // 먹을 수 없으면 대기
    unlock();
}

void putdown(int i) {
    lock();
    state[i] = THINKING;
    test(leftOf(i));   // 왼쪽 이웃이 먹을 수 있는지 확인
    test(rightOf(i));  // 오른쪽 이웃이 먹을 수 있는지 확인
    unlock();
}
```

- 💬 **데드락은 없다 — 양쪽 모두 가능할 때만 집기 때문**
- ⚠️ **기아 현상은 여전히 가능하다** — 양쪽 이웃이 번갈아 먹으면 가운데 철학자는 영원히 못 먹을 수도

## 세 문제 비교

| 문제 | 핵심 | 필요한 도구 |
|---|---|---|
| Bounded-Buffer | 생산-소비 속도 차이 조율 | mutex + 2개 counting semaphore |
| Readers-Writers | 읽기는 공유, 쓰기는 독점 | mutex + rw_mutex |
| Dining-Philosophers | 여러 자원의 데드락 없는 할당 | mutex + condition variable |
