## 핵심 개념: 원자성 (Atomicity)

- ✨ **원자적 연산(Atomic Operation): 중간에 끊기지 않는 단 하나의 실행 단위**

`count++` 처럼 내부적으로 여러 명령어로 나뉘는 연산과 달리,
원자적 연산은 실행 중간에 다른 스레드가 끼어들 수 없다

현대 CPU는 이를 위한 특수 하드웨어 명령어를 제공한다

---

## test_and_set()

```c
// 하드웨어가 원자적으로 실행
boolean test_and_set(boolean *target) {
    boolean rv = *target;   // 현재 값 읽기
    *target = true;         // true로 설정
    return rv;              // 읽었던 값 반환
}
```

이 두 동작(읽기 + 설정)이 **원자적으로** 수행된다 — 중간에 끊기지 않는다

**적용: Mutex 구현**

```c
boolean lock = false;  // 공유 변수

do {
    while (test_and_set(&lock))  // lock이 true면(잠겨있으면) 계속 대기
        ;
    /* critical section */
    lock = false;                // 잠금 해제
    /* remainder section */
} while (true);
```

- ℹ **처음 진입하는 프로세스는 `test_and_set`이 `false`를 반환 → while 루프 탈출 → 임계 구역 진입**
- ℹ **두 번째 프로세스는 `test_and_set`이 `true`를 반환 → while 루프에서 계속 대기**

## compare_and_swap()

```c
// 하드웨어가 원자적으로 실행
int compare_and_swap(int *value, int expected, int new_value) {
    int temp = *value;
    if (*value == expected)    // 기대값과 같으면
        *value = new_value;    // 새 값으로 교체
    return temp;               // 이전 값 반환
}
```

**적용: Mutex 구현**

```c
int lock = 0;  // 0 = 사용 가능, 1 = 잠김

while (compare_and_swap(&lock, 0, 1) != 0)
    ;          // lock이 0일 때만 1로 바꾸고 진입, 아니면 대기
/* critical section */
lock = 0;      // 잠금 해제
```

## Atomic Variable

`compare_and_swap`을 기반으로 더 편리하게 사용할 수 있는 **원자적 변수** 타입을 제공한다

```java
// Java: AtomicBoolean 사용
import java.util.concurrent.atomic.AtomicBoolean;

static AtomicBoolean[] flag = new AtomicBoolean[2];

// Peterson's solution에 적용
flag[0].set(true);             // 원자적 set
while (flag[1].get() && ...)   // 원자적 get
    ;
```

- 💬 **Atomic Variable은 단일 변수에 race condition이 있는 경우에 상호 배제를 간단히 보장한다**

복잡한 임계 구역에는 mutex나 semaphore가 필요하지만,
단순한 카운터 증감 같은 경우에 아주 적합하다

## 세 가지 하드웨어 기반 도구 비교

| 도구 | 방식 | 사용 목적 |
|---|---|---|
| **Memory Barrier** | 명령어 재배치 방지 | 메모리 가시성 보장 |
| **test_and_set / CAS** | 원자적 읽기+수정 | Mutex, Lock 구현 기반 |
| **Atomic Variable** | 원자적 기본 타입 | 단순 변수의 race condition 해결 |
