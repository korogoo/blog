> 세마포어는 강력하지만, 잘못 쓰면 아무도 모르게 시스템이 망가진다

---

## 세마포어의 문제점

세마포어는 효과적이지만, **프로그래머가 직접 올바른 순서를 지켜야 한다**

조금만 실수해도 치명적인 오류가 생기고, 발견하기도 어렵다

| 실수 | 결과 |
|---|---|
| `wait()`와 `signal()` 순서를 바꿈 | 상호 배제 깨짐 — 두 프로세스가 동시에 임계 구역 진입 |
| `signal()` 대신 `wait()` 한 번 더 | 데드락 — 영원히 기다림 |
| `wait()` 또는 `signal()`을 누락 | 상호 배제 깨지거나 데드락 |

- [!] **세마포어 오류는 재현이 어렵다 — 특정 실행 순서에서만 발생하기 때문**

---

## 해결: 모니터 (Monitor)

- [I] **모니터: 상호 배제와 동기화를 언어 수준에서 캡슐화한 고수준 동기화 구조체**

ADT(Abstract Data Type)로, 내부 변수와 함수가 묶여 있고
**모니터 안의 함수는 한 번에 하나의 프로세스만 실행할 수 있다**

```
monitor MonitorName {
    // 공유 변수 선언
    
    procedure P1(...) { ... }
    procedure P2(...) { ... }
    
    초기화 코드
}
```

모니터 외부에서는 내부 변수에 직접 접근할 수 없고, 반드시 프로시저를 통해야 한다

---

## 조건 변수 (Condition Variable)

모니터만으로는 "특정 조건이 만족될 때까지 기다려라"를 표현하기 어렵다

이를 위해 **조건 변수**를 사용한다

```
condition x, y;

x.wait()    → 이 프로세스를 x 조건 큐에 넣고 대기
x.signal()  → x 조건 큐에서 하나를 깨움 (없으면 아무 일도 안 함)
```

세마포어의 `signal()`과 달리, 조건 변수의 `signal()`은 **대기 중인 프로세스가 없으면 아무 효과가 없다**

## Java 모니터: synchronized

Java는 모니터를 언어 수준에서 지원한다

- [I] **`synchronized` 키워드: 해당 코드 블록을 임계 구역으로 지정 — 모니터 락을 획득해야 진입 가능**

```java
// 방법 1: 메서드 전체를 임계 구역으로
public synchronized void increment() {
    count++;  // this 객체의 모니터 락을 획득해야 진입
}

// 방법 2: 특정 블록만 임계 구역으로
public void increment() {
    synchronized (this) {
        count++;
    }
}

// 방법 3: 특정 객체의 락을 사용
private static Object object = new Object();
public static void increment() {
    synchronized (object) {
        count++;
    }
}
```

---

## wait()와 notify()

Java의 모든 객체는 `wait()`와 `notify()`를 갖는다 (`java.lang.Object` 에 선언됨)

| 메서드 | 동작 |
|---|---|
| `wait()` | 현재 스레드를 이 객체의 모니터 대기 큐에 넣고 락을 반납 |
| `notify()` | 대기 중인 스레드 하나를 깨움 |
| `notifyAll()` | 대기 중인 모든 스레드를 깨움 |

---

## Java Synchronized 예시 — 어떤 게 올바른가?

```java
// Example 1: race condition 발생 (동기화 없음)
public static void increment() {
    count++;  // synchronized 없음
}

// Example 2: 올바름 (메서드 자체에 synchronized)
public static synchronized void increment() {
    count++;
}

// Example 3: 올바름 (공유 객체로 synchronized)
private static Object object = new Object();
public static void increment() {
    synchronized (object) { count++; }
}

// Example 4: 올바른 것처럼 보이지만 틀림
public void increment() {
    synchronized (this) { count++; }  // this가 각 인스턴스마다 다름
}
// → new MyRunnable(new Counter()) 처럼 스레드마다 다른 Counter를 쓰면
//   각자 다른 락을 획득 → 상호 배제 안 됨

// Example 5: Example 4의 수정 — 모든 스레드가 같은 Counter 인스턴스 공유
Counter counter = new Counter();
new Thread(new MyRunnable(counter));  // 같은 counter 사용
new Thread(new MyRunnable(counter));  // → 같은 락 공유 → 올바름
```

- ["] **`synchronized (this)`는 this가 같은 객체일 때만 상호 배제가 보장된다**

스레드마다 다른 객체를 `this`로 갖는다면, 락이 달라서 아무 효과가 없다
