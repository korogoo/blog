> 각자 따로 보면 정상인 코드가, 동시에 실행되면 이상해진다

## 문제: count++ 와 count-- 를 동시에 실행하면?

Producer-Consumer 문제에서 버퍼의 현재 아이템 수를 `count`로 추적한다고 하자

- 생산자: `count++`
- 소비자: `count--`

`count = 5`인 상태에서 두 스레드가 동시에 실행하면, 결과는 5가 되어야 한다

⚠️ **실제로는 4가 될 수도, 5가 될 수도, 6이 될 수도 있다**

---

## 왜 그런가? 기계어로 내려가 보자

`count++` 는 단 한 줄처럼 보이지만, 실제로는 3개의 기계어 명령어다

```
count++:                    count--:
reg1 = count   (load)       reg2 = count   (load)
reg1 = reg1 + 1             reg2 = reg2 - 1
count = reg1   (store)      count = reg2   (store)
```

두 스레드가 이 명령어들을 **임의의 순서로 섞어서** 실행할 수 있다

---

## 문제가 발생하는 시나리오

`count = 5`에서 시작

```
스레드1 (count++):   reg1 = count  → reg1 = 5
스레드2 (count--):   reg2 = count  → reg2 = 5
스레드1:             reg1 = reg1+1 → reg1 = 6
스레드2:             reg2 = reg2-1 → reg2 = 4
스레드1:             count = reg1  → count = 6
스레드2:             count = reg2  → count = 4   ← 최종값
```

결과: `count = 4` — 틀렸다

---

## Race Condition

✨ **Race Condition: 여러 프로세스(또는 스레드)가 공유 데이터에 동시에 접근하고 조작할 때, 실행 순서에 따라 결과가 달라지는 상황**

```c
// C 예시: 두 스레드가 sum을 동시에 증가
int sum = 0;

void *run(void *param) {
    for (int i = 0; i < 10000; i++)
        sum++;         // race condition 발생 지점
    pthread_exit(0);
}
```

두 스레드가 각각 10,000번 `sum++`을 하면 합계는 20,000이어야 한다

⚠️ **하지만 실행할 때마다 결과가 다르고, 20,000이 나오지 않는다**

---

## Java에서도 똑같이 발생한다

```java
// RunnableOne: 각자 자신의 count (공유 X) → race condition 없음
class RunnableOne implements Runnable {
    int count = 0;             // 인스턴스 변수 → 객체마다 별도
    public void run() {
        for (int i = 0; i < 10000; i++) count++;
    }
}
// 결과: 항상 10000, 10000

// RunnableTwo: static count (공유 O) → race condition 발생
class RunnableTwo implements Runnable {
    static int count = 0;     // 클래스 변수 → 모든 인스턴스가 공유
    public void run() {
        for (int i = 0; i < 10000; i++) count++;
    }
}
// 결과: 실행마다 다름 (20000보다 작은 임의의 값)
```

💬 **공유되는 데이터에 동시 접근이 일어날 때 race condition이 발생한다**

해결하려면 한 번에 하나의 스레드만 공유 데이터를 조작하도록 보장해야 한다 — 이것이 **동기화(Synchronization)** 의 목표다
