## Liveness

- [I] **Liveness: 프로세스들이 실행을 계속 진행할 수 있음을 보장하는 속성**

임계 구역 문제의 세 요구사항(상호 배제, 진행, 유한 대기) 중
**진행**과 **유한 대기**가 liveness와 직결된다

세마포어와 모니터는 상호 배제는 잘 보장하지만, liveness 실패가 발생할 수 있다

두 가지 대표적인 liveness 실패가 있다

---

## 데드락 (Deadlock)

- [I] **데드락: 두 개 이상의 프로세스가 서로 상대방이 점유한 자원을 기다리며 영원히 대기하는 상태**

```
S = 1, Q = 1 (두 세마포어)

P0:             P1:
wait(S);        wait(Q);
wait(Q);        wait(S);   ← S는 P0이 갖고 있음 → P1 대기
...             ...
signal(S);      signal(Q);
signal(Q);      signal(S);
```

P0은 Q를 기다리고, P1은 S를 기다린다

둘 다 영원히 기다린다 — **데드락**

```
P0 ──보유──► S
P0 ──대기──► Q ◄──보유── P1
             P1 ──대기──► S
```

## 우선순위 역전 (Priority Inversion)

- [I] **우선순위 역전: 높은 우선순위 프로세스가 낮은 우선순위 프로세스가 점유한 자원을 기다리는 상황**

```
우선순위: L < M < H

1. L이 자원 R을 획득 (락 보유)
2. H가 R을 필요로 해서 대기
3. M이 L을 선점 (M의 우선순위 > L)
   → M이 실행되는 동안 L은 R을 반납하지 못함
   → H도 계속 대기

결과: M이 H보다 먼저 실행 → 우선순위 역전
```

실제 사례: 1997년 화성 탐사선 Mars Pathfinder에서 우선순위 역전으로 시스템 리셋이 반복됐다

---

## 해결: 우선순위 상속 프로토콜 (Priority Inheritance)

- ["] **자원을 점유한 프로세스가 높은 우선순위 프로세스의 대기를 유발하면, 임시로 높은 우선순위를 상속받는다**

```
L이 R을 보유 중, H가 R 대기 중
→ L의 우선순위를 H 수준으로 일시 상승
→ M이 L을 선점할 수 없게 됨
→ L이 빠르게 R 반납
→ H가 R 획득
→ L의 우선순위 원래대로 복원
```

## 정리

| 문제 | 원인 | 해결 |
|---|---|---|
| **데드락** | 서로가 갖고 있는 자원을 서로 기다림 | 자원 획득 순서 통일, 타임아웃 등 (Chapter 8) |
| **우선순위 역전** | 낮은 우선순위가 자원을 점유해 높은 우선순위를 막음 | 우선순위 상속 프로토콜 |
