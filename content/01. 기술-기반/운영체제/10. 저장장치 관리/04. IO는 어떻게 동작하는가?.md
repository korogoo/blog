> CPU가 직접 다 하면 너무 느리다 — 장치에게, 또는 DMA에게 맡긴다

---

## I/O의 역할

💬 **컴퓨터의 두 가지 핵심 작업: I/O와 연산 — 웹 브라우저, 파일 편집, 유튜브, 게임 모두 I/O가 주**
- OS의 역할: I/O 동작과 I/O 장치를 관리하고 제어한다

---

## 장치 컨트롤러 레지스터

CPU가 장치에 명령을 내리려면 **컨트롤러**를 통해 통신한다

| 레지스터 | 방향 | 설명 |
|---|---|---|
| **data-in register** | 장치 → 호스트 | 입력 데이터 읽기 |
| **data-out register** | 호스트 → 장치 | 출력 데이터 쓰기 |
| **status register** | 장치 → 호스트 | 장치 상태 확인 |
| **control register** | 호스트 → 장치 | 명령 전달, 모드 설정 |

---

## Memory-Mapped I/O

✨ **Memory-Mapped I/O: 장치 컨트롤러 레지스터를 물리 메모리 주소 공간에 매핑하는 방식**

```
물리 메모리 주소 공간:
  0x0000 ~ 0x9FFF  → 일반 RAM
  0xA000 ~ 0xBFFF  → 그래픽 카드 컨트롤러 레지스터
  0xC000 ~ 0xCFFF  → 네트워크 카드 컨트롤러 레지스터
  ...
```

- CPU는 일반 `load` / `store` 명령어로 장치에 접근한다
💬 **별도의 I/O 명령어 없이도 장치를 제어할 수 있다**

---

## I/O 방식 3가지

### 1. 폴링 (Polling) = Busy-Waiting

✨ **폴링: CPU가 장치의 status register를 반복적으로 읽으며 완료 여부를 확인**

```
while (status_register.busy == 1) {
    // 아무것도 안 함 — 그냥 기다림
}
// busy == 0 → 장치 준비 완료
```

⚠️ **CPU가 계속 루프를 돌아서 다른 작업 불가 — 장치가 매우 빠를 때만 효율적**

---

### 2. 인터럽트 (Interrupt)

✨ **인터럽트: 장치가 준비되면 CPU에 신호를 보내 알려주는 방식 — CPU는 그동안 다른 일을 한다**

```
① CPU가 장치에 I/O 요청
② CPU는 다른 프로세스 실행 (대기하지 않음)
③ 장치 완료 → interrupt-request line에 신호
④ CPU가 인터럽트 감지
⑤ ISR(Interrupt Service Routine) 실행
⑥ 완료 처리 후 원래 작업 재개
```

✨ **인터럽트 벡터 테이블: 각 인터럽트 번호에 대응하는 ISR 주소를 저장한 테이블**

```
인터럽트 벡터 테이블 (일부):
번호  │ ISR 주소
  0   │ 0x0040  ← divide by zero
  1   │ 0x0050  ← debug
 14   │ 0x0200  ← page fault
 32   │ 0x0400  ← 키보드
 ...  │ ...
```

---

### 3. DMA (Direct Memory Access)

✨ **DMA: CPU 대신 DMA 컨트롤러가 직접 장치와 메모리 사이의 데이터 전송을 수행하는 방식**

```
① CPU가 DMA 컨트롤러에 전송 명령 (시작 주소, 길이, 방향)
② CPU는 다른 작업 수행
③ DMA 컨트롤러가 버스를 이용해 직접 메모리 ↔ 장치 전송
④ 전송 완료 → DMA가 CPU에 인터럽트 발생
⑤ CPU는 완료 인터럽트만 처리
```

💬 **대용량 데이터 전송에 효과적 — CPU는 시작과 완료만 관여**

---

## 세 가지 I/O 방식 비교

| 방식 | CPU 개입 | 적합한 상황 |
|---|---|---|
| **폴링** | 계속 대기 | 장치가 매우 빠를 때, 간단한 시스템 |
| **인터럽트** | 시작 + 완료만 | 일반적인 I/O |
| **DMA** | 시작 + 완료만 | 디스크, 네트워크 등 대용량 전송 |
