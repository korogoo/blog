> I/O 요청 후 기다리느냐, 그냥 계속 가느냐

---

## 세 가지 I/O 모델

### 1. Blocking I/O

- [I] **Blocking I/O: I/O 요청 후 완료될 때까지 스레드가 멈추는(suspend) 방식**

```
스레드:  ──── read() 호출 ──────────── [대기] ──────── 데이터 수신 → 재개 ────
                                        ↑
                              running → waiting 큐로 이동
```

- 직관적이고 프로그래밍하기 쉽다
- I/O가 완료될 때까지 CPU를 쓰지 못한다

---

### 2. Non-blocking I/O

- [I] **Non-blocking I/O: I/O 요청 후 즉시 반환 — 데이터가 있으면 반환하고, 없으면 빈 값을 반환**

```
스레드:  ──── read() 호출 → 즉시 반환 ──── 다른 작업 ──── 다시 read() ────
                ↑
          현재 가능한 만큼만 반환 (0바이트일 수도 있음)
```

- **예시**: 워드프로세서에서 키보드/마우스 입력 처리
  - 키 입력이 없어도 화면 렌더링, 커서 깜빡임 등 계속 진행
- [i] **요청한 바이트 수 전부, 일부, 또는 0바이트를 반환할 수 있다**

---

### 3. Asynchronous I/O

- [I] **Asynchronous I/O: I/O 요청을 던져놓고 스레드는 계속 실행 — I/O가 완료되면 콜백이나 시그널로 통보**

```
스레드:  ──── async_read() 호출 → 즉시 반환 ──── 다른 작업 계속 ────
                                                           ↑
                                              완료 통보 (콜백 / 시그널)
```

---

## Non-blocking vs Asynchronous 차이

- [!] **헷갈리는 포인트: 둘 다 즉시 반환하지만 의미가 다르다**

| 항목 | Non-blocking I/O | Asynchronous I/O |
|---|---|---|
| **반환 시점** | 즉시 반환 | 즉시 반환 |
| **반환 내용** | 지금 가능한 만큼만 (일부 또는 0) | "요청 접수됨" |
| **완료 시점** | 반환 즉시 (일부 완료) | 미래 어느 시점 (전체 완료) |
| **완료 알림** | 없음 (직접 확인) | 콜백 / 시그널로 통보 |
| **예시** | `O_NONBLOCK` 플래그의 `read()` | `aio_read()` |

- ["] **Non-blocking: "지금 줄 수 있는 것만 줘" → Asynchronous: "다 되면 나한테 알려줘"**

---

## 시각적 비교

```
(a) Synchronous (Blocking):
스레드   ──────[I/O 요청]──[     대기     ]──[완료]──────
                                                         ↑ 재개

(b) Asynchronous:
스레드   ──────[I/O 요청]──[다른 작업 계속]──[완료 통보]──
                                 ↑
                          I/O는 별도로 처리됨
```

- [i] **대부분의 현대 고성능 서버(Node.js, Nginx 등)는 Asynchronous I/O 모델을 사용한다**
