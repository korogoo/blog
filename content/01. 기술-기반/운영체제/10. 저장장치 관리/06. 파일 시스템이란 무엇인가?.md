> 파일 시스템은 데이터를 이름으로 찾을 수 있게 해주는 구조다

---

## 파일 시스템 (File System)

- [I] **파일 시스템: OS와 모든 사용자의 데이터·프로그램을 온라인으로 저장하고 접근하는 메커니즘**

두 가지 구성:
1. **파일(File) 집합** — 관련 데이터를 저장하는 단위
2. **디렉토리 구조(Directory Structure)** — 파일을 조직화하는 구조

---

## 파일 접근 방법

### 1. 순차 접근 (Sequential Access)

- [I] **순차 접근: 파일의 레코드를 처음부터 순서대로 읽고 쓰는 방식**

```
[레코드1] → [레코드2] → [레코드3] → [레코드4] → ...
     읽기 포인터가 앞으로만 이동
     (되감기 rewind 가능)
```

- **예시**: 테이프, 로그 파일

---

### 2. 직접 접근 (Direct Access) = 상대 접근

- [I] **직접 접근: 고정 길이 레코드로 구성된 파일에서 임의의 레코드를 바로 읽고 쓰는 방식**

```
[레코드0] [레코드1] [레코드2] [레코드3] ...
               ↑
         read(n) → n번 레코드 바로 접근
```

- ["] **순차 접근 파일을 직접 접근처럼 시뮬레이션하는 것도 가능하다 (인덱스 테이블 사용)**

---

## 디렉토리 구조

- [I] **디렉토리: 파일 이름을 파일 제어 블록(FCB, File Control Block)으로 변환하는 심볼 테이블**

### 1. 단일 수준 디렉토리 (Single-Level Directory)

```
/
├── file1
├── file2
├── file3
└── file4
```

- 모든 파일이 같은 디렉토리에 — 파일 이름 충돌 문제

---

### 2. 2단계 디렉토리 (Two-Level Directory)

```
/
├── 사용자A/
│   ├── file1
│   └── file2
└── 사용자B/
    ├── file1   ← 같은 이름 가능 (다른 경로)
    └── file3
```

- 사용자별 분리 — 사용자 간 파일 공유 어려움

---

### 3. 트리 구조 디렉토리 (Tree-Structured Directory)

```
/
├── home/
│   ├── alice/
│   │   ├── docs/
│   │   └── photos/
│   └── bob/
├── etc/
└── var/
```

- 현재 디렉토리(current directory) 개념 도입
- **절대 경로** vs **상대 경로**
- ["] **대부분의 현대 파일 시스템이 사용하는 구조 (Linux, Windows)**

---

### 4. 비순환 그래프 디렉토리 (Acyclic-Graph Directory)

```
/home/alice/shared ──┐
                     ├──► [실제 파일]
/home/bob/link    ──┘
```

- 파일이나 디렉토리를 여러 경로에서 공유 가능 (링크, 심볼릭 링크)
- [i] **순환(cycle)이 없어야 탐색 알고리즘이 무한 루프에 빠지지 않는다**

---

### 비교

| 구조 | 파일 공유 | 이름 충돌 | 탐색 |
|---|---|---|---|
| 단일 수준 | 불가 | 발생 | 단순 |
| 2단계 | 어려움 | 사용자 간 없음 | 단순 |
| 트리 | 가능 | 없음 | 경로로 구분 |
| 비순환 그래프 | 용이 | 없음 | 복잡 |
