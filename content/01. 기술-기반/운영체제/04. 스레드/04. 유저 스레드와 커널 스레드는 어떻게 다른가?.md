> 스레드를 누가 관리하느냐에 따라 두 종류로 나뉜다

---

## 두 종류의 스레드

| 종류 | 관리 주체 | 특징 |
|---|---|---|
| **유저 스레드** (User Thread) | 사용자 공간의 라이브러리 | 커널 개입 없이 빠름 |
| **커널 스레드** (Kernel Thread) | 운영체제 커널 | OS가 직접 스케줄링 |

```
[유저 공간]   ──── 유저 스레드 ──── 유저 스레드 ──── 유저 스레드
                         │                │                │
─────────────────────────────────────────────────────────────
[커널 공간]   ──── 커널 스레드 ──── 커널 스레드 ──── 커널 스레드
```

---

## 유저 스레드 vs 커널 스레드의 매핑 모델

유저 스레드와 커널 스레드를 어떻게 연결하느냐에 따라 세 가지 모델이 있다

---

### Many-to-One 모델

여러 유저 스레드 → 커널 스레드 하나

```
유저: [T1] [T2] [T3]
            │
커널:      [K1]
```

- [>] 스레드 관리가 유저 공간에서 이루어져 빠름
- [!] **하나의 스레드가 블로킹 시스템 콜을 호출하면 전체 프로세스가 블로킹**
- [!] **멀티코어를 활용할 수 없음 — 커널 스레드가 하나뿐이므로**

---

### One-to-One 모델

유저 스레드 하나 → 커널 스레드 하나

```
유저: [T1] [T2] [T3]
       │    │    │
커널: [K1] [K2] [K3]
```

- [>] 하나가 블로킹되어도 다른 스레드는 계속 실행
- [>] 멀티코어 병렬 실행 가능
- [i] **Linux, Windows가 이 모델을 사용한다**
- [!] 유저 스레드를 만들 때마다 커널 스레드도 생성 — 스레드 수에 제한이 생길 수 있음

---

### Many-to-Many 모델

여러 유저 스레드 → 그보다 적거나 같은 수의 커널 스레드

```
유저: [T1] [T2] [T3] [T4]
        ↘  ↙     ↘  ↙
커널:  [K1]      [K2]
```

- [>] Many-to-One의 블로킹 문제 해결
- [>] One-to-One의 스레드 수 제한 문제 해결
- [i] OS가 충분한 수의 커널 스레드를 유연하게 할당
- [i] 구현이 복잡하여 현대 OS에서는 One-to-One을 더 많이 채택하는 추세

---

## 정리

| 모델 | 병렬 실행 | 블로킹 문제 | 현실 사용 |
|---|---|---|---|
| Many-to-One | 불가 | 전체 블로킹 | 거의 미사용 |
| One-to-One | 가능 | 해결 | Linux, Windows |
| Many-to-Many | 가능 | 해결 | 일부 고급 시스템 |
