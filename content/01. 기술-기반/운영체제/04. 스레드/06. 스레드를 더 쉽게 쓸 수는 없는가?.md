> 스레드를 직접 만들고 관리하는 건 어렵다. OS와 컴파일러에게 맡기면 어떨까?

---

## 문제: 명시적 스레딩의 어려움

멀티코어를 활용하는 병렬 프로그램을 직접 작성하는 건 쉽지 않다

- [>] 스레드를 언제 만들고 없앨지
- [>] 몇 개의 스레드를 유지할지
- [>] 데이터를 어떻게 나눌지
- [>] 실행 순서와 동기화를 어떻게 맞출지

- [!] **이 복잡성을 매번 개발자가 직접 처리하기엔 부담이 크다**

---

## 해결: 암묵적 스레딩 (Implicit Threading)

- [I] **암묵적 스레딩: 스레드 생성과 관리를 컴파일러와 런타임 라이브러리에게 위임하는 전략**

개발자는 "무엇을 병렬로 할지"만 표시하고, 나머지는 시스템이 알아서 처리한다

대표적인 방식 네 가지

| 방식 | 특징 |
|---|---|
| **Thread Pool** | 미리 만든 스레드 집합에 작업을 할당 |
| **Fork & Join** | 명시적 스레딩이지만 암묵적 스레딩의 후보 |
| **OpenMP** | C/C++ 컴파일러 지시자로 병렬 구간 표시 |
| **Grand Central Dispatch (GCD)** | Apple macOS/iOS의 런타임 병렬 처리 시스템 |

---

## Thread Pool

- ["] **미리 일정 수의 스레드를 만들어 풀(pool)에 대기시키고, 요청이 오면 유휴 스레드에게 작업을 할당한다**

```
요청 도착 ──► [Thread Pool]
                ├── Thread 1 (작업 중)
                ├── Thread 2 (대기 중) ◄── 작업 할당
                └── Thread 3 (대기 중)
```

매번 스레드를 생성/제거하는 오버헤드가 없고,
동시에 실행되는 스레드 수를 제한할 수 있다

---

## OpenMP

- [I] **OpenMP: C/C++ 코드에서 `#pragma omp` 지시자로 병렬 실행 구간을 표시하면, 런타임 라이브러리가 자동으로 스레드를 생성해 처리한다**

**기본 병렬 실행**

```c
#include <omp.h>

int main() {
    #pragma omp parallel
    {
        printf("I am a parallel region.\n");
    }
    return 0;
}
// 컴파일: gcc -fopenmp 파일명.c
```

`#pragma omp parallel` 블록 안의 코드가 여러 스레드에서 동시에 실행된다

<br/>

**스레드 수 지정**

```c
omp_set_num_threads(4);  // 4개 스레드 사용

#pragma omp parallel
{
    printf("OpenMP thread: %d\n", omp_get_thread_num());
}
```

<br/>

**루프 자동 병렬화**

```c
#define SIZE 100000000
int a[SIZE], b[SIZE], c[SIZE];

// #pragma omp parallel for 하나로 루프를 자동으로 나눠 병렬 처리
#pragma omp parallel for
for (int i = 0; i < SIZE; i++) {
    c[i] = a[i] + b[i];
}
```

실제 성능 비교 결과

```
병렬화 없음:  real 0m0.586s
OpenMP 적용: real 0m0.423s  (user 시간은 늘어남 — 코어를 여럿 사용하므로)
```

- [i] **`user` 시간이 늘어난 것은 오류가 아니다**

여러 코어가 동시에 작업했으므로 CPU 누적 시간(`user`)은 증가하고,
실제 경과 시간(`real`)은 감소한다
