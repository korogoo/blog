## 지금까지 전제한 것

우리는 지금까지 프로세스가 **하나의 실행 흐름** 을 가진다고 가정했다

명령어를 하나씩 순서대로 실행하는 단일 스레드 구조였다

⚠️ **하지만 프로세스는 여러 개의 실행 흐름을 동시에 가질 수 있다**

---

## 스레드란

✨ **스레드(Thread): CPU 활용의 기본 단위 — 프로세스 안에서 실제로 실행되는 흐름**

스레드는 다음 네 가지로 구성된다

| 구성 요소 | 설명 |
|---|---|
| **Thread ID** | 스레드 식별자 |
| **Program Counter** | 현재 실행 중인 명령어 위치 |
| **Register Set** | 스레드가 사용하는 레지스터 값들 |
| **Stack** | 함수 호출 정보, 지역 변수 |

---

## 프로세스 vs 스레드 구조

단일 스레드 프로세스와 멀티스레드 프로세스의 차이

```
[단일 스레드 프로세스]          [멀티스레드 프로세스]

┌──────────────────┐          ┌──────────────────────┐
│  code            │          │  code                │
│  data            │          │  data                │
│  files           │          │  files               │
├──────────────────┤          ├──────┬──────┬────────┤
│  registers       │          │  T1  │  T2  │  T3    │
│  stack           │          │ regs │ regs │ regs   │
│  (단일 스레드)    │          │stack │stack │ stack  │
└──────────────────┘          └──────┴──────┴────────┘
```

💬 **스레드들은 code, data, files를 공유하고 — registers와 stack은 각자 독립적으로 가진다**

이 구조가 스레드를 "가벼운 프로세스"라고 부르는 이유다

새 프로세스를 만들면 모든 것이 복사되지만,
새 스레드를 만들면 공유 자원은 그대로 두고 stack과 레지스터만 추가된다
