## 동시성 vs 병렬성

헷갈리기 쉬운 두 개념을 먼저 구분하자

| 개념 | 설명 |
|---|---|
| **동시성 (Concurrency)** | 여러 작업이 번갈아가며 실행되어 동시처럼 보임 |
| **병렬성 (Parallelism)** | 여러 작업이 물리적으로 같은 시간에 실행됨 |

```
[단일 코어 - 동시성]
코어: [T1][T2][T3][T1][T2][T3] ...
→ 실제로는 빠르게 번갈아 실행, 동시처럼 보임

[멀티코어 - 병렬성]
코어1: [T1][T1][T1] ...
코어2: [T2][T2][T2] ...
→ 물리적으로 동시에 실행
```

- [i] **동시성은 코어 하나로도 가능하다. 병렬성은 코어가 여러 개 있어야 한다**

---

## 두 가지 병렬성 유형

| 유형 | 방식 | 예시 |
|---|---|---|
| **데이터 병렬성** (Data Parallelism) | 같은 작업을 데이터를 나눠서 각 코어에서 처리 | 배열 합산을 절반씩 나눠 계산 |
| **태스크 병렬성** (Task Parallelism) | 서로 다른 작업을 각 코어에서 처리 | 코어1은 압축, 코어2는 암호화 |

```
[데이터 병렬성]               [태스크 병렬성]
데이터: [1,2,3,4,5,6,7,8]    Task A: 압축
         ↙           ↘        Task B: 암호화
코어1:[1,2,3,4]  코어2:[5,6,7,8]    ↙       ↘
                              코어1        코어2
```

## 멀티코어 프로그래밍의 도전 과제

코어를 늘린다고 자동으로 빨라지지 않는다. 프로그래머가 신경 써야 할 것들이 있다

| 과제 | 설명 |
|---|---|
| **태스크 식별** | 어떤 부분을 병렬로 나눌 수 있는지 파악 |
| **균형** | 각 코어에 동등한 양의 작업을 배분 |
| **데이터 분할** | 데이터도 코어마다 나눠야 함 |
| **데이터 의존성** | 한 작업이 다른 작업의 결과에 의존하면 순서 보장 필요 |
| **테스트 및 디버깅** | 병렬 실행은 재현이 어렵고 디버깅이 복잡함 |

---

## Amdahl의 법칙: 코어를 늘리면 얼마나 빨라지는가?

- [I] **Amdahl's Law: 프로그램에 직렬로만 실행해야 하는 부분이 있으면, 코어를 늘려도 속도 향상에 한계가 있다**

$$speedup \leq \frac{1}{S + \frac{1-S}{N}}$$

- `S`: 반드시 직렬로 실행해야 하는 비율
- `N`: 코어 수

예시 (S = 0.25, 즉 25%는 병렬화 불가)

| 코어 수 (N) | 최대 속도 향상 |
|---|---|
| 1 | 1.0x |
| 2 | 1.6x |
| 4 | 2.28x |
| ∞ | 4.0x (1/S) |

```
코어를 무한히 늘려도 → 최대 4배 향상
(직렬 구간 25%가 병목이 됨)
```

- [!] **병렬화할 수 없는 코드가 조금이라도 있으면, 코어를 아무리 늘려도 한계가 존재한다**

성능을 높이려면 코어 수보다 **직렬 구간을 줄이는 것** 이 더 중요할 수 있다
