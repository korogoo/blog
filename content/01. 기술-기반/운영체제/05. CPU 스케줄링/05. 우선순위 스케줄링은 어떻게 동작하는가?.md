## Priority Scheduling

- [I] **우선순위 스케줄링: 각 프로세스에 우선순위(priority)를 부여하고, 가장 높은 우선순위의 프로세스에게 CPU를 할당한다**

- [i] **이 강의에서는 숫자가 작을수록 우선순위가 높다** (1 > 2 > 3 ...)

우선순위가 같으면 FCFS로 결정한다

- ["] **SJF는 우선순위 스케줄링의 특수한 경우다 — 다음 CPU burst의 역수를 우선순위로 쓰는 것**

---

## Priority Scheduling 예시

| 프로세스 | CPU Burst | 우선순위 |
|---|---|---|
| P1 | 10ms | 3 |
| P2 | 1ms | 1 |
| P3 | 2ms | 4 |
| P4 | 1ms | 5 |
| P5 | 5ms | 2 |

실행 순서: P2(1) → P5(2) → P1(3) → P3(4) → P4(5)

```
 0   1      6           16    18  19
 ├───┤──────┤────────────┤─────┤───┤
 │P2 │  P5  │     P1     │ P3  │P4 │
```

평균 대기 시간: (6 + 0 + 16 + 18 + 1) / 5 = **8.2ms**

## 문제: 기아 현상 (Starvation)

- [!] **낮은 우선순위 프로세스가 계속 밀려 영원히 실행되지 못할 수 있다**

우선순위 높은 프로세스가 계속 들어오면, 낮은 우선순위 프로세스는 무한 대기(indefinite blocking) 상태가 된다

실제로 수십 년 전 IBM 시스템을 종료할 때, 낮은 우선순위로 1973년에 제출된 프로세스가 아직 실행 대기 중이었다는 사례가 있다

---

## 해결: 에이징 (Aging)

- ["] **에이징: 오래 기다린 프로세스의 우선순위를 시간이 지남에 따라 점진적으로 높여준다**

예: 15분마다 대기 중인 프로세스의 우선순위를 1씩 올린다

아무리 낮은 우선순위로 시작해도, 충분히 기다리면 결국 CPU를 받게 된다

## RR + Priority 조합

우선순위로 실행 순서를 결정하되, 같은 우선순위 프로세스 사이에서는 Round-Robin을 적용한다

time quantum = 2ms 예시

| 프로세스 | CPU Burst | 우선순위 |
|---|---|---|
| P1 | 4ms | 3 |
| P2 | 3ms | 2 |
| P3 | 3ms | 3 |
| P4 | 1ms | 3 |
| P5 | 2ms | 1 |

```
 0   2   4   6   8   10  11    13
 ├───┤───┤───┤───┤───┤───┤─────┤
 │P5 │P5 │P2 │P2 │P2 │P1 │P1  │P3 │P4 │
```

실행 흐름: P5(우선순위 1, 전부 실행) → P2(우선순위 2, 전부 실행) → P1/P3/P4(우선순위 3, RR)
