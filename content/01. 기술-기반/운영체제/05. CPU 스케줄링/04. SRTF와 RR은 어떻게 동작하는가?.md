## SRTF: Shortest-Remaining-Time-First

- ✨ **SRTF: 선점 버전의 SJF — 새 프로세스가 도착할 때마다 남은 실행 시간을 비교해서 더 짧으면 현재 프로세스를 중단시킨다**

---

## SRTF 예시

| 프로세스 | 도착 시각 | CPU Burst |
|---|---|---|
| P1 | 0 | 8ms |
| P2 | 1 | 4ms |
| P3 | 2 | 9ms |
| P4 | 3 | 5ms |

```
 0  1      5          10               17                  26
 ├──┤──────┤──────────┤────────────────┤────────────────────┤
 │P1│  P2  │    P4    │       P1       │         P3         │
```

**추적**

- t=0: P1 시작 (남은 시간=8)
- t=1: P2 도착 (남은 시간=4) < P1 남은 시간(7) → P1 선점, P2 실행
- t=5: P2 완료. 남은: P1(7), P3(9), P4(5) → P4 실행
- t=10: P4 완료. 남은: P1(7), P3(9) → P1 실행
- t=17: P1 완료. P3 실행
- t=26: P3 완료

대기 시간 계산 (도착 시각부터 완료 시각까지 - burst 시간)

| 프로세스 | 계산 | 대기 시간 |
|---|---|---|
| P1 | (10 − 1) = 9 | 9ms |
| P2 | (1 − 1) = 0 | 0ms |
| P3 | (17 − 2) = 15 | 15ms |
| P4 | (5 − 3) = 2 | 2ms |

평균 대기 시간: (9 + 0 + 15 + 2) / 4 = **6.5ms**

- ℹ **비선점 SJF로 같은 예시를 풀면 평균 대기 시간이 7.75ms — SRTF가 더 짧다**

## RR: Round-Robin

- ✨ **RR: 선점 방식의 FCFS — 각 프로세스에게 일정 시간(time quantum)씩 번갈아 CPU를 할당한다**

- ▶ ready queue를 원형 큐로 관리
- ▶ 타임 퀀텀 안에 끝나면 자발적으로 CPU 반납
- ▶ 타임 퀀텀을 다 쓰면 인터럽트 → 강제 선점 → 큐의 맨 뒤로 이동

---

## RR 예시 (time quantum = 4ms)

| 프로세스 | CPU Burst |
|---|---|
| P1 | 24ms |
| P2 | 3ms |
| P3 | 3ms |

```
 0   4   7  10       14       18       22       26       30
 ├───┤───┤───┤────────┤────────┤────────┤────────┤────────┤
 │P1 │P2 │P3 │   P1   │   P1   │   P1   │   P1   │   P1   │
```

| 프로세스 | 대기 시간 |
|---|---|
| P1 | 10 − 4 = 6ms |
| P2 | 4ms |
| P3 | 7ms |

평균 대기 시간: (6 + 4 + 7) / 3 = **5.66ms**

---

## Time Quantum의 크기가 중요하다

| 크기 | 효과 |
|---|---|
| 너무 작음 | 컨텍스트 스위치가 너무 잦아 오버헤드 증가 |
| 너무 큼 | 사실상 FCFS와 동일해짐 |
| 적당 | 응답성과 효율성의 균형 |

```
[큰 퀀텀]  P1──────────────P2────P3────
[작은 퀀텀] P1─P2─P3─P1─P2─P3─P1─P2─P3─ (컨텍스트 스위치 폭발)
[적당한 퀀텀] P1────P2──P3──P1────P1────
```

- ℹ **일반적으로 CPU burst의 80% 정도가 time quantum보다 짧도록 설정하는 것이 이상적이다**

반환 시간 관점에서는 time quantum이 크다고 항상 좋지 않다
프로세스들이 여러 번 순환해야 끝나면, time quantum이 적당히 작은 쪽이 더 빠를 수 있다
