> 어떤 스케줄링 알고리즘이 더 좋은지 판단하려면 기준이 필요하다

---

## 5가지 평가 기준

| 기준 | 설명 | 방향 |
|---|---|---|
| **CPU 이용률** (Utilization) | CPU가 놀지 않고 일하는 비율 | 높을수록 좋음 |
| **처리량** (Throughput) | 단위 시간당 완료된 프로세스 수 | 높을수록 좋음 |
| **반환 시간** (Turnaround Time) | 제출부터 완료까지 걸린 전체 시간 | 낮을수록 좋음 |
| **대기 시간** (Waiting Time) | Ready Queue에서 기다린 시간의 합 | 낮을수록 좋음 |
| **응답 시간** (Response Time) | 요청 후 첫 번째 응답이 시작되기까지의 시간 | 낮을수록 좋음 |

---

## 각 기준의 의미

### 반환 시간 vs 대기 시간

두 개념을 혼동하기 쉬우니 짚고 넘어가자

```
시간축:
─────────────────────────────────────────►
 제출      실행 시작     I/O 대기    완료
  │            │            │          │
  └────────────┴────────────┴──────────┘
  │←────────── 반환 시간 (Turnaround) ──►│
              │←── 대기 시간 ───►│
              (Ready Queue에서 기다린 시간만)
```

- [I] **반환 시간 = 완료 시각 − 제출 시각**
- [I] **대기 시간 = 반환 시간 − 실제 실행 시간(CPU burst 합계)**

### 응답 시간

대화형 시스템(GUI, 웹 등)에서 특히 중요한 지표다

완료까지 얼마나 걸렸는지보다, **언제 첫 반응이 시작됐는지**가 사용자 경험에 직결된다

---

## 알고리즘마다 장단점이 다르다

- [i] **어떤 단일 알고리즘도 모든 기준에서 최선일 수 없다**

CPU 이용률을 높이면 응답 시간이 나빠질 수 있고,
대기 시간을 줄이면 처리량이 줄 수 있다

시스템의 목적(서버/대화형/실시간)에 따라 중요한 기준이 달라진다
