> 프로세스의 성격이 다르면, 큐도 달라야 한다

---

## 문제: 하나의 큐로 모든 프로세스를 관리하면?

시스템에는 다양한 성격의 프로세스가 존재한다

▶ 사용자와 실시간으로 상호작용하는 프로세스 (응답성 중요)
▶ 백그라운드에서 오래 실행되는 배치 작업 (처리량 중요)

하나의 큐와 하나의 알고리즘으로 이 모두를 만족시키기 어렵다

⚠️ **성격이 다른 프로세스를 같은 기준으로 스케줄링하면, 어느 쪽도 최적화되지 않는다**

---

## MLQ: Multi-Level Queue

✨ **MLQ: 우선순위별로 별도의 큐를 두고, 각 큐마다 다른 스케줄링 알고리즘을 적용한다**

```
우선순위 높음
┌────────────────────────────────┐
│  Queue 0 - 실시간 프로세스      │  → RR (짧은 퀀텀)
├────────────────────────────────┤
│  Queue 1 - 시스템 프로세스      │  → RR
├────────────────────────────────┤
│  Queue 2 - 대화형 프로세스      │  → RR
├────────────────────────────────┤
│  Queue 3 - 배치 프로세스        │  → FCFS
└────────────────────────────────┘
우선순위 낮음
```

상위 큐가 비어있어야 하위 큐의 프로세스가 실행된다

⚠️ **프로세스는 처음 배정된 큐에서 고정된다 — 승격/강등이 없다**

배치 작업은 상위 큐가 계속 바쁘면 기아 현상이 발생할 수 있다

---

## MLFQ: Multi-Level Feedback Queue

✨ **MLFQ: MLQ에 프로세스 이동(승격/강등)을 추가한 방식 — 프로세스의 실제 동작에 따라 큐 레벨이 바뀐다**

```
큐 0 (RR, q=8ms)       새 프로세스 진입
  │ q를 다 쓰면             │
  ▼ 강등                    ▼
큐 1 (RR, q=16ms)      ───►Queue 0 시작
  │ q를 다 쓰면
  ▼ 강등
큐 2 (FCFS)
```

**동작 원리**

▶ 새 프로세스는 가장 높은 우선순위 큐에서 시작
▶ 할당된 time quantum 안에 끝나면 → I/O-bound로 판단, 높은 우선순위 유지
▶ time quantum을 다 쓰면 → CPU-bound로 판단, 하위 큐로 강등
▶ 오래 기다린 프로세스는 상위 큐로 승격 (에이징 효과)

💬 **MLFQ는 프로세스가 어떤 성격인지 미리 몰라도 동작에 따라 적응적으로 스케줄링한다**

짧은 대화형 작업은 자연스럽게 상위 큐에 머물고,
긴 배치 작업은 하위 큐로 내려가 낮은 우선순위로 처리된다

## 스케줄링 알고리즘 한눈에 비교

| 알고리즘 | 선점 여부 | 특징 | 단점 |
|---|---|---|---|
| FCFS | 비선점 | 구현 단순 | Convoy Effect |
| SJF | 비선점 | 평균 대기 최소 | 다음 burst 예측 필요 |
| SRTF | 선점 | SJF보다 개선 | 예측 필요, 오버헤드 |
| RR | 선점 | 응답성 좋음 | 퀀텀 크기 민감 |
| Priority | 선택 | 중요도 반영 | 기아 현상 |
| MLQ | 선택 | 성격별 분리 | 큐 고정 |
| MLFQ | 선점 | 적응적, 실용적 | 구현 복잡 |
