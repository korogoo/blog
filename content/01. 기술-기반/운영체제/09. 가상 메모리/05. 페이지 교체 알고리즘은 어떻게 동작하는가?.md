> 어떤 페이지를 내보낼지가 성능을 결정한다

---

## 공통 예시: 참조 스트링 & 프레임 수

```
참조 스트링: 7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2, 1, 2, 0, 1, 7, 0, 1
프레임 수: 3
```

---

## 1. FIFO (First-In First-Out)

✨ **FIFO: 가장 먼저 들어온 페이지를 가장 먼저 교체한다**

```
참조:  7  0  1  2  0  3  0  4  2  3  0  3  2  1  2  0  1  7  0  1
      ─────────────────────────────────────────────────────────────
F1    7  7  7  2        2     4  4  4  0           0     7  7  7
F2       0  0  0     3  3  3  2  2  2     2        2  2  0  0  0
F3          1  1  1  1     1  1  3  3  3  3  1  1  1  1  1  1  1
      *  *  *  *     *  *  *  *  *  *        *        *  *  *
```

⚠️ **page fault: 15회**

---

## Belady's Anomaly

✨ **Belady's Anomaly: FIFO에서 프레임 수를 늘렸는데 page fault가 오히려 증가하는 현상**

```
같은 참조 스트링, 프레임 3개 → 9회 fault
                  프레임 4개 → 10회 fault  ← 더 많다!
```

💬 **직관에 반하는 결과 — FIFO는 최적성을 보장하지 못한다**
ℹ **OPT, LRU 같은 스택 알고리즘(stack algorithm)은 Belady's Anomaly가 발생하지 않는다**

---

## 2. OPT (Optimal Page Replacement)

✨ **OPT: 앞으로 가장 오랫동안 사용되지 않을 페이지를 교체한다**

```
참조:  7  0  1  2  0  3  0  4  2  3  0  3  2  1  2  0  1  7  0  1
      ─────────────────────────────────────────────────────────────
F1    7  7  7  2     2  2  2  2  2  2     2  2  2  2  2  7
F2       0  0  0  0  0  0  4  4  4  0     0  0  0  0  0  0  0  0
F3          1  1  1  3  3  3  3  3  3     3  1  1  1  1  1  1  1
      *  *  *  *     *     *           *  *              *
```

⚠️ **page fault: 9회 — 이론적 최솟값**
ℹ **미래를 알아야 하므로 실제 구현 불가능 — 다른 알고리즘의 성능 기준(upper bound)으로만 사용**

---

## 3. LRU (Least Recently Used)

✨ **LRU: 가장 오랫동안 사용되지 않은 페이지를 교체한다 — 과거로 미래를 예측**

```
참조:  7  0  1  2  0  3  0  4  2  3  0  3  2  1  2  0  1  7  0  1
      ─────────────────────────────────────────────────────────────
F1    7  7  7  2  2  2  0  0  0  3  3  3  2  2  2  2  1  1  1  1
F2       0  0  0  0  3  3  3  2  2  2  2  2  1  1  0  0  0  0  0
F3          1  1  1  1  1  4  4  4  0  0  0  0  0  0  0  7  7  7
      *  *  *  *     *  *  *  *  *  *        *        *  *
```

⚠️ **page fault: 12회**
💬 **OPT보다는 많지만 FIFO보다 적다 — 현실적으로 좋은 알고리즘**

---

## LRU 구현 방법

LRU는 정확히 구현하려면 하드웨어 지원이 필요하다

| 방법 | 설명 | 비용 |
|---|---|---|
| **Counter** | 각 페이지에 마지막 사용 시각 기록, 가장 오래된 것 교체 | 탐색 O(n) |
| **Stack** | 참조 시 해당 페이지를 스택 top으로 이동, bottom이 LRU | 업데이트 비용 높음 |

ℹ **실제 OS는 정확한 LRU 대신 근사 알고리즘을 사용한다**

---

## 4. LRU 근사: 참조 비트 (Reference Bit)

✨ **참조 비트: 페이지가 참조되면 하드웨어가 1로 세트하는 비트 — OS가 주기적으로 0으로 초기화**

참조 비트만으로는 순서를 알 수 없지만, 사용 여부는 알 수 있다

### Second-Chance (Clock) 알고리즘

✨ **Second-Chance: FIFO 기반에서 참조 비트가 1이면 한 번 기회를 더 주고(비트를 0으로 초기화), 0이면 교체**

```
        참조 비트
페이지  [1] [1] [0] [1] [0] [1]
         ↑
       포인터 (시계방향 회전)

포인터가 가리키는 페이지 확인:
  참조 비트 = 1 → 0으로 초기화, 포인터 이동 (second chance)
  참조 비트 = 0 → 이 페이지를 교체!
```

```
Clock 형태로 시각화:

        [1]
    [1]     [0]  ← 교체 대상
  [1]           [1]
    [0]     [1]  ← 교체 대상 (포인터가 먼저 만나는 쪽)
        [1]
```

💬 **Second-Chance는 Clock 알고리즘이라고도 불린다 — 원형 큐로 구현**
ℹ **모든 페이지의 참조 비트가 1이면 FIFO와 동일하게 동작한다**
