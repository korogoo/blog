
> 필요한 페이지만, 필요할 때 메모리에 올린다

---

## 요구 페이징 (Demand Paging)

- [I] **요구 페이징: 페이지를 미리 올리지 않고, 실제로 접근(요구)될 때 메모리에 올리는 방식**

```
프로세스 시작 시: 메모리에 아무 페이지도 없음
      ↓
페이지에 접근 → 메모리에 있으면 그냥 사용
             → 메모리에 없으면 page fault 발생 → OS가 디스크에서 불러옴
```

- [i] **극단적인 경우: 순수 요구 페이징(pure demand paging) — 프로세스 시작 시 아무 페이지도 올리지 않음**

## Valid-Invalid 비트로 페이지 상태 표시

페이지 테이블의 각 항목에 Valid-Invalid 비트가 있다

| 비트 | 의미 |
|---|---|
| **valid (v)** | 페이지가 메모리에 있음 → 바로 접근 가능 |
| **invalid (i)** | 페이지가 메모리에 없거나, 논리 주소 공간 밖 → page fault |

```
페이지 테이블:
페이지 0: 프레임 3  [v]  ← 메모리에 있음
페이지 1: 프레임 7  [v]  ← 메모리에 있음
페이지 2: -         [i]  ← 디스크에 있음
페이지 3: -         [i]  ← 디스크에 있음
페이지 4: 프레임 1  [v]  ← 메모리에 있음
페이지 5: -         [i]  ← 디스크에 있음
```

---

## 페이지 폴트 처리 과정 (Page Fault Procedure)

invalid 페이지에 접근하면 OS로 트랩(page fault)이 발생한다

```
① CPU가 invalid 페이지에 접근
② 하드웨어가 OS로 트랩 (page fault)
③ OS가 페이지가 유효한지 확인
   - 잘못된 접근이면 → 프로세스 종료
   - 유효한 접근이면 → 계속
④ 빈 프레임(free frame)을 찾는다
⑤ 디스크에서 해당 페이지를 프레임에 읽어들임
⑥ 페이지 테이블 업데이트: 프레임 번호 기록, valid 비트 설정
⑦ 트랩을 발생시킨 명령어를 재시작(restart)
```

- ["] **명령어를 재시작하는 것이 핵심 — 프로세스는 page fault가 있었는지 모른다**

## 지역 참조 (Locality of Reference)

요구 페이징이 잘 동작하는 이유는 프로그램의 참조 패턴 때문이다

- [I] **지역 참조: 프로그램이 짧은 시간 안에 특정 부분(지역)만 집중적으로 참조하는 성질**

최근 사용한 페이지는 곧 다시 사용될 가능성이 높다
→ 한 번 올라온 페이지는 한동안 계속 쓰인다
→ page fault가 자주 발생하지 않는다

## 유효 접근 시간 (EAT, Effective Access Time)

- p = page fault 발생 확률 (0 ≤ p ≤ 1)
- 메모리 접근 시간 = 200ns (예시)
- 페이지 폴트 처리 시간 = 8ms = 8,000,000ns (디스크 I/O 포함)

$$EAT = (1 - p) \times 200 + p \times 8{,}000{,}000$$

**예시 계산 (p = 0.001)**

```
EAT = 0.999 × 200 + 0.001 × 8,000,000
    = 199.8 + 8,000
    = 8,199.8 ns
```

- [!] **page fault가 0.1%만 발생해도 메모리 접근 속도가 40배 느려진다**

| p | EAT | 비고 |
|---|---|---|
| 0 | 200ns | page fault 없음 |
| 0.001 | 8,199.8ns | 40배 느림 |
| 1 | 8,000,000ns | 항상 page fault |

- [i] **성능 저하를 10% 이내로 유지하려면 page fault rate가 0.0000025 이하여야 한다**
