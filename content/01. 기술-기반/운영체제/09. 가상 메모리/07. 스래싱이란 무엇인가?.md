
> 페이지를 교체하느라 정작 프로세스가 실행되지 못하는 상태

---

## 스래싱 (Thrashing)

- [I] **스래싱: 프로세스가 실행보다 페이지 교체(swap in/out)에 더 많은 시간을 쓰는 현상**

```
프로세스 수 증가에 따른 CPU 이용률 변화:

CPU
이용률
  |          ★ 최고점
  |        /   \
  |       /     \  ← 스래싱 구간
  |      /       \
  |     /         \_______________
  |____/
  └──────────────────────────────▶
                           프로세스 수
```

- [!] **CPU 이용률이 낮다고 프로세스를 더 올리면 → 스래싱 악화 → CPU 이용률 더 낮아지는 악순환**

---

## 스래싱 발생 원리

```
① 프로세스 수 증가 → 각 프로세스에 할당된 프레임 수 감소
② 프레임 부족 → page fault 빈발
③ page fault 처리를 위해 CPU 시간이 디스크 I/O에 소비됨
④ CPU 이용률 하락
⑤ OS: "CPU가 한가하니까 프로세스 더 올리자" → ①로 돌아감
```

---

## 해결: 워킹셋 모델 (Working-Set Model)

- [I] **워킹셋(Working Set): 프로세스가 현재 활발하게 사용 중인 페이지들의 집합**

```
워킹셋 윈도우 Δ (delta): 가장 최근 Δ번의 참조를 기준으로 워킹셋 결정
```

**예시:**

```
참조 스트링: ... 2 6 1 5 7 7 7 5 1 6 2 3 4 1 2 3 4 4 3 4 ...
                                  ↑                   ↑
                                  t1                  t2

Δ = 10일 때:
  t1의 워킹셋: {1, 2, 5, 6, 7}   → 5 프레임 필요
  t2의 워킹셋: {1, 2, 3, 4}      → 4 프레임 필요
```

- ["] **Δ가 너무 작으면 워킹셋이 실제보다 작게 측정되고, 너무 크면 여러 지역을 포함하게 된다**

---

## 워킹셋으로 스래싱 방지

$$D = \sum WS_i$$

- $D$: 전체 프로세스의 프레임 수요 합계
- $WS_i$: 프로세스 $i$의 워킹셋 크기
- $m$: 전체 프레임 수

```
D > m 이면 → 스래싱 발생 가능
→ 프로세스 하나를 중단(suspend)시켜 프레임을 확보
```

| 상황 | 조치 |
|---|---|
| $D \leq m$ | 새 프로세스 시작 가능 |
| $D > m$ | 프로세스 하나를 스왑 아웃시켜 프레임 확보 |

---

## 워킹셋 모델 vs 페이지 폴트 빈도 (PFF)

| | 워킹셋 모델 | PFF (Page-Fault Frequency) |
|---|---|---|
| **방법** | 워킹셋 크기로 프레임 수요 예측 | page fault rate를 직접 측정 |
| **프레임 추가 시점** | 미리 예방 | fault rate가 상한선 초과 시 |
| **프레임 회수 시점** | 워킹셋에 없는 페이지 제거 | fault rate가 하한선 이하 시 |
| **특징** | 예측적(proactive) | 반응적(reactive) |

- [i] **두 방법 모두 지역 참조(locality of reference) 성질을 활용한다**
