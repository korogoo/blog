> 프레임이 너무 적으면 page fault가 폭증하고, 너무 많이 주면 다른 프로세스가 손해다

---

## 프레임 할당의 기본 제약

- 각 프로세스에 할당되는 프레임 수에는 상한과 하한이 있다
- **하한**: 명령어 하나를 실행하는 데 필요한 최소 프레임 수 (아키텍처가 결정)
  - 예: 간접 주소 지정 명령어는 최소 3개 프레임 필요
- **상한**: 전체 물리 프레임 수 (당연히 그 이상 줄 수 없다)

- [!] **프레임이 너무 적으면 스래싱(thrashing) 발생 → 다음 파일 참고**

---

## 할당 방식 1: 균등 할당 (Equal Allocation)

- [I] **균등 할당: 전체 프레임을 프로세스 수로 나눠 똑같이 배분**

```
전체 프레임: 100개, 프로세스: 5개
→ 각 프로세스에 100 / 5 = 20 프레임
```

| 장점 | 단점 |
|---|---|
| 구현 단순 | 프로세스 크기 무시 — 작은 프로세스에 낭비, 큰 프로세스엔 부족 |

---

## 할당 방식 2: 비례 할당 (Proportional Allocation)

- [I] **비례 할당: 프로세스의 크기(가상 메모리 크기)에 비례해서 프레임을 배분**

$$a_i = \frac{s_i}{\sum s_j} \times m$$

- $s_i$: 프로세스 $i$의 크기
- $m$: 전체 프레임 수
- $a_i$: 프로세스 $i$에 할당할 프레임 수

```
예시:
  프로세스 1: 크기 10, 프로세스 2: 크기 127, 전체 프레임: 62

  프로세스 1에 할당: 10/137 × 62 ≈ 4.5 → 4 프레임
  프로세스 2에 할당: 127/137 × 62 ≈ 57.5 → 57 프레임
```

- [i] **우선순위(priority)에 따라 프레임을 배분하는 방식도 있다 — 우선순위 높은 프로세스에 더 많이**

---

## 교체 범위: 전역 vs 지역

page fault 발생 시 어느 프레임을 교체 대상으로 볼 것인가?

| | **전역 교체 (Global Replacement)** | **지역 교체 (Local Replacement)** |
|---|---|---|
| **대상** | 전체 프레임 중 victim 선택 | 자신에게 할당된 프레임 중에서만 선택 |
| **장점** | 전체 시스템 처리량(throughput) 높음 | 다른 프로세스 영향 없음, 예측 가능 |
| **단점** | 다른 프로세스의 프레임을 빼앗을 수 있음 | 개별 프로세스 성능 최적화 어려움 |

- ["] **실제 OS는 대부분 전역 교체를 사용한다 — 전체 시스템 효율이 더 중요하기 때문**
