> fork()를 해도 실제로 복사하지 않는다 — 쓸 때만 복사한다

---

## 문제: fork()는 너무 비싸다

fork()는 부모 프로세스의 메모리를 자식에게 통째로 복사한다

- 자식이 exec()을 바로 호출하면 복사한 내용이 다 버려진다
- [!] **대부분의 fork() + exec() 패턴에서 복사 비용이 완전히 낭비된다**

---

## Copy-on-Write (COW)

- [I] **Copy-on-Write: fork() 직후에는 부모와 자식이 같은 물리 프레임을 공유하고, 실제로 쓰기가 발생할 때만 그 페이지를 복사하는 기법**

```
fork() 직후:

부모 페이지 테이블    물리 메모리    자식 페이지 테이블
  페이지 A ────────► 프레임 1 ◄──── 페이지 A   (공유, COW 표시)
  페이지 B ────────► 프레임 2 ◄──── 페이지 B   (공유, COW 표시)
  페이지 C ────────► 프레임 3 ◄──── 페이지 C   (공유, COW 표시)
```

```
자식이 페이지 B를 수정하면:

부모 페이지 테이블    물리 메모리    자식 페이지 테이블
  페이지 A ────────► 프레임 1 ◄──── 페이지 A   (여전히 공유)
  페이지 B ────────► 프레임 2        (부모만 사용)
                     프레임 4 ◄──── 페이지 B   (자식 전용 복사본)
  페이지 C ────────► 프레임 3 ◄──── 페이지 C   (여전히 공유)
```

---

## 동작 원리

1. fork() 시 모든 페이지를 COW 페이지로 표시
2. 부모/자식 중 하나가 **읽기만** 하면 → 그냥 공유 프레임 사용
3. 부모/자식 중 하나가 **쓰기**를 하면
   - OS가 트랩을 받음
   - 해당 페이지의 복사본을 새 프레임에 만듦
   - 쓰기한 쪽의 페이지 테이블이 새 프레임을 가리키도록 업데이트
   - 쓰기 작업 재개

- ["] **수정되지 않은 페이지는 영원히 공유 — 실제 필요한 경우에만 복사가 일어난다**

---

## 장점

| 항목 | 설명 |
|---|---|
| **속도** | fork() 직후 불필요한 복사 없음 → 빠른 프로세스 생성 |
| **메모리** | 공유 페이지를 통해 물리 메모리 절약 |
| **exec() 최적화** | exec() 호출 시 어차피 전체 교체 → 복사 자체가 불필요 |

- [i] **vfork()는 COW조차 없이 부모 메모리를 직접 공유한다 — exec()을 곧바로 호출할 것이 보장될 때 사용**
