> 메모리가 꽉 찼을 때, 누군가를 내보내야 한다

## 문제: 빈 프레임이 없을 때 page fault 처리

page fault가 발생했는데 빈 프레임이 없다면?

```
① page fault 발생 (접근하려는 페이지가 메모리에 없음)
② 빈 프레임 탐색 → 없음!
③ 희생 페이지(victim page) 선택
④ victim을 디스크에 swap out
⑤ 원하는 페이지를 그 프레임에 swap in
⑥ 페이지 테이블 두 개 업데이트
⑦ 명령어 재시작
```

- [!] **victim을 swap out + 새 페이지 swap in → 디스크 I/O가 2번 발생해 매우 느리다**

---

## Modify(Dirty) 비트로 I/O 최소화

모든 페이지에 **modify bit (dirty bit)** 를 유지한다

| 상태 | 의미 | swap out 시 |
|---|---|---|
| modify = 0 | 메모리에 올라온 후 수정 안 됨 | 디스크에 이미 최신본 → 그냥 버리면 됨 |
| modify = 1 | 수정됨 | 디스크에 써야 함 (I/O 필요) |

- ["] **dirty bit = 0인 페이지를 victim으로 선택하면 swap out I/O를 생략할 수 있다**

---

## 페이지 교체의 두 가지 선택

페이지 교체 알고리즘이 결정해야 할 것:

1. **어떤 페이지를 내보낼 것인가?** → 교체 알고리즘 (replacement algorithm)
2. **몇 개의 프레임을 이 프로세스에 줄 것인가?** → 프레임 할당 (frame allocation)

- [I] **목표: page fault rate를 최소화한다**

---

## 성능 평가 방법: 참조 스트링 (Reference String)

알고리즘 성능은 특정 메모리 참조 순서(참조 스트링)에서 page fault 횟수로 비교한다

```
예시 참조 스트링:
7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2, 1, 2, 0, 1, 7, 0, 1

프레임 수가 많을수록 page fault는 줄어든다 (일반적으로)
```

- [i] **같은 참조 스트링에서 프레임 수가 늘어나도 page fault가 늘어나는 현상 → Belady's Anomaly (다음 파일 참고)**
