
> 프로그램 전체가 메모리에 없어도 실행할 수 있다

---

## 문제: 프로그램 전체를 메모리에 올려야 하는가?

실제 실행 시 프로그램의 모든 부분이 동시에 필요하지 않다

- 에러 처리 코드는 거의 실행되지 않는다
- 배열, 리스트, 테이블 전체가 항상 필요한 것은 아니다
- 특정 기능(옵션)은 아예 사용하지 않을 수도 있다

- [!] **전체를 메모리에 올리는 것은 낭비다**

---

## 가상 메모리 (Virtual Memory)

- [I] **가상 메모리: 프로세스 전체가 메모리에 없어도 실행이 가능하도록 하는 기법**

실제로 필요한 페이지만 메모리에 올린다

```
가상 주소 공간 (논리)      물리 메모리
┌──────────────┐         ┌──────────┐
│   페이지 0   │──────►  │ 프레임 1  │  ← 메모리에 있음
├──────────────┤         ├──────────┤
│   페이지 1   │──────►  │ 프레임 4  │  ← 메모리에 있음
├──────────────┤         ├──────────┤
│   페이지 2   │  (없음)  │          │  ← 디스크에 있음
├──────────────┤         └──────────┘
│   페이지 3   │  (없음)       디스크
└──────────────┘
```

---

## 가상 주소 공간 (Virtual Address Space)

- [I] **가상 주소 공간: 프로세스가 바라보는 논리적인 메모리 레이아웃 — 0번지부터 연속된 것처럼 보인다**

```
가상 주소 공간 (예: 0 ~ max)
┌──────────────────────┐  ← max
│     스택 (Stack)      │  ↓ 아래로 성장
│                      │
│        (빈 공간)      │  ← sparse address space
│                      │
│      힙 (Heap)        │  ↑ 위로 성장
├──────────────────────┤
│      데이터           │
├──────────────────────┤
│      코드             │
└──────────────────────┘  ← 0
```

- ["] **스택과 힙 사이의 빈 공간은 실제 물리 메모리를 차지하지 않는다**

---

## 가상 메모리의 장점

| 장점 | 설명 |
|---|---|
| **더 많은 프로세스 실행** | 각 프로세스가 실제 사용하는 부분만 메모리에 올라오므로 동시에 더 많은 프로세스 실행 가능 |
| **더 큰 프로그램 실행** | 물리 메모리보다 큰 프로그램도 실행 가능 |
| **빠른 로딩** | 전체를 로드하지 않아도 되므로 실행 시작이 빠름 |

## 페이지 공유 (Page Sharing)

가상 메모리는 페이지 공유를 자연스럽게 지원한다

```
프로세스 A         물리 메모리         프로세스 B
가상 주소 공간                        가상 주소 공간

페이지 3 ────────► 프레임 7: libc ◄──── 페이지 2
페이지 4 ────────► 프레임 8: libc ◄──── 페이지 3

페이지 0 ────────► 프레임 1: A 데이터
                   프레임 2: B 데이터 ◄──── 페이지 0
```

- [i] **fork() 시 부모-자식 프로세스가 페이지를 공유하는 것도 이 덕분이다 (→ Copy-on-Write)**
