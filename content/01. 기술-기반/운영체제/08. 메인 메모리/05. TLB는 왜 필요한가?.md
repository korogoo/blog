> 페이지 테이블 조회마다 메모리를 두 번 접근하는 건 너무 느리다

---

## 문제: 페이지 테이블은 메모리에 있다

매번 주소 변환에 메모리를 두 번 접근해야 한다

```
1. 메모리 → 페이지 테이블 읽기
2. 메모리 → 실제 데이터 접근
```

메모리 접근 속도가 사실상 절반이 된다

---

## 해결: TLB (Translation Look-aside Buffer)

- ✨ **TLB: 최근에 사용한 페이지 테이블 엔트리를 저장하는 작고 빠른 하드웨어 캐시**

```
CPU ──[논리 주소 p,d]──►
                         ┌──────────┐
                    TLB  │ p → f ?  │  TLB Hit → 즉시 f 반환
                         └──────────┘
                              ↓ TLB Miss
                    메모리의 페이지 테이블 조회 (+ TLB에 저장)
                              ↓
                    물리 주소 f,d 계산 → 메모리 접근
```

TLB에 있으면(Hit) 페이지 테이블 조회 없이 바로 물리 주소를 얻는다

---

## 유효 메모리 접근 시간 (EAT)

메모리 접근 시간 = 10ns, TLB 접근 시간 ≈ 0 (무시) 로 가정

| 상황 | 메모리 접근 횟수 | 소요 시간 |
|---|---|---|
| TLB Hit | 1회 (데이터만) | 10ns |
| TLB Miss | 2회 (페이지 테이블 + 데이터) | 20ns |

$$EAT = \alpha \times 10 + (1-\alpha) \times 20$$

| Hit Rate (α) | EAT |
|---|---|
| 80% | 0.80×10 + 0.20×20 = **12ns** |
| 99% | 0.99×10 + 0.01×20 = **10.1ns** |

- 💬 **TLB hit rate가 99%이면, 메모리 접근 속도가 거의 1회와 동일해진다**

---

## Valid-Invalid 비트: 페이지 테이블의 보호

페이지 테이블의 각 항목에 추가적인 비트가 붙는다

| 비트 | 의미 |
|---|---|
| **valid (v)** | 이 페이지가 프로세스의 논리 주소 공간에 존재 → 합법적 접근 |
| **invalid (i)** | 이 페이지가 프로세스의 논리 주소 공간에 없음 → 불법 접근 |

프로세스가 invalid 페이지에 접근하면 OS가 트랩을 발생시킨다

---

## 공유 페이지 (Shared Pages)

페이징의 추가적인 이점 — 공통 코드를 여러 프로세스가 공유할 수 있다

```
프로세스 A         물리 메모리         프로세스 B
page table                          page table
  0 → 3 ──────► 프레임 3: libc ◄──── 0 → 3
  1 → 4 ──────► 프레임 4: libc ◄──── 1 → 4
  2 → 6 ──────► 프레임 6: libc ◄──── 2 → 6
  3 → 1 ──────► 프레임 1: A의 데이터
                프레임 2: B의 데이터 ◄── 3 → 2
```

- 💬 **reentrant code(재진입 가능 코드): 실행 중에 내용이 변하지 않는 코드 — 여러 프로세스가 동시에 공유 가능**

표준 C 라이브러리(`libc`), 텍스트 편집기, 컴파일러 등이 이 방식으로 공유된다
