## 페이징 (Paging)

- [I] **페이징: 프로세스의 논리 주소 공간을 고정 크기의 블록으로 나눠, 물리 메모리의 임의 위치에 분산 배치하는 메모리 관리 기법**

연속 메모리 할당의 두 가지 문제를 해결한다

- [>] 외부 단편화 없음 — 페이지 단위로 아무 빈 프레임에나 배치
- [>] 압축 불필요

## 페이지와 프레임

| 개념 | 위치 | 설명 |
|---|---|---|
| **페이지 (Page)** | 논리 메모리 | 고정 크기로 나뉜 논리 메모리 블록 |
| **프레임 (Frame)** | 물리 메모리 | 페이지와 같은 크기의 물리 메모리 블록 |

페이지 크기 = 프레임 크기 = 하드웨어가 결정 (보통 4KB ~ 1GB, 항상 2의 거듭제곱)

```
논리 메모리           물리 메모리
┌──────────┐         ┌──────────┐
│ 페이지 0  │──────►  │ 프레임 3  │
├──────────┤         ├──────────┤
│ 페이지 1  │──────►  │ 프레임 7  │
├──────────┤         ├──────────┤
│ 페이지 2  │──────►  │ 프레임 1  │  ← 물리적으로 비연속
└──────────┘         └──────────┘
```

## 주소 변환: 페이지 번호 + 오프셋

CPU가 생성하는 논리 주소는 두 부분으로 나뉜다

```
논리 주소:  [ 페이지 번호 p | 페이지 오프셋 d ]
                 m-n 비트         n 비트
```

- 논리 주소 공간이 2^m, 페이지 크기가 2^n이면
  - 상위 m-n 비트 = 페이지 번호 (p)
  - 하위 n 비트 = 오프셋 (d)

**변환 과정**

```
① 논리 주소에서 페이지 번호 p 추출
② 페이지 테이블[p]에서 프레임 번호 f 조회
③ 물리 주소 = f × 페이지크기 + d
```

---

## 구체적인 예시 (페이지 크기 = 4바이트, 논리 주소 = 4비트)

```
논리 주소 형식: [p:2비트 | d:2비트]

논리 주소 0 = 00|00 → p=0, d=0
논리 주소 5 = 01|01 → p=1, d=1
논리 주소 9 = 10|01 → p=2, d=1

페이지 테이블:
페이지 0 → 프레임 5
페이지 1 → 프레임 6
페이지 2 → 프레임 1
페이지 3 → 프레임 2

논리 주소 5 변환:
  p=1 → 프레임 6, d=1
  물리 주소 = 6×4 + 1 = 25
```

## 페이지 테이블의 위치

- [I] **PTBR (Page-Table Base Register): 각 프로세스의 페이지 테이블이 저장된 메모리 주소를 가리키는 레지스터**

페이지 테이블은 메인 메모리에 저장되고, PTBR은 PCB에 보관된다

컨텍스트 스위치 시 PTBR 값만 교체하면 된다 → 빠른 컨텍스트 스위치

- [!] **문제: 메모리 접근이 두 번 필요하다**

```
① 페이지 테이블 읽기 (메모리 접근 1회)
② 실제 데이터 접근 (메모리 접근 1회)
```

→ 메모리 접근 속도가 절반으로 떨어진다

## 내부 단편화는 여전히 존재

페이지 크기가 2048바이트이고 프로세스가 72,766바이트를 필요로 할 때

72,766 / 2048 = 35페이지 + 1086바이트 나머지

36번째 페이지에 1086바이트만 사용 → 2048 - 1086 = **962바이트 낭비**

- [i] **페이징은 외부 단편화를 없애지만, 내부 단편화는 최대 페이지 크기만큼 발생할 수 있다**

페이지를 작게 할수록 내부 단편화가 줄지만, 페이지 테이블 크기가 커진다
