> 메모리를 프로세스별로 연속된 구간으로 나눠주는 가장 단순한 방법

---

## 연속 메모리 할당 (Contiguous Memory Allocation)

✨ **연속 메모리 할당: 각 프로세스에게 메모리의 연속된 하나의 구간을 통째로 할당하는 방식**

메모리는 크게 두 영역으로 나뉜다

```
┌──────────────────┐  ← 높은 주소
│   프로세스 영역   │
├──────────────────┤
│   OS 영역        │
└──────────────────┘  ← 낮은 주소 (0)
```

---

## 가변 분할 (Variable Partition)

✨ **각 프로세스가 필요한 만큼 메모리를 할당받는 방식**

프로세스가 종료하면 그 자리가 **홀(hole)** 이 되고, 새 프로세스가 들어올 홀을 찾아야 한다

```
초기:           P1 로드:         P2 로드:         P1 종료:
┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
│          │   │   P1     │   │   P1     │   │  hole    │
│          │   │          │   │          │   │          │
│  가용    │   │  가용    │   │   P2     │   │   P2     │
│          │   │          │   │          │   │          │
│          │   │          │   │  가용    │   │  가용    │
└──────────┘   └──────────┘   └──────────┘   └──────────┘
```

---

## 세 가지 홀 탐색 전략

| 전략 | 방법 | 특징 |
|---|---|---|
| **First-Fit** | 충분히 큰 첫 번째 홀 | 빠름 |
| **Best-Fit** | 충분히 큰 홀 중 가장 작은 것 | 남는 공간 최소화 |
| **Worst-Fit** | 가장 큰 홀 | 남는 공간이 커서 재사용 용이 |

**예시**: 홀 크기가 100, 170, 40, 205, 300, 185(KB) 일 때 212KB 요청

| 전략 | 선택 | 이유 |
|---|---|---|
| First-Fit | 300 | 순서상 첫 번째로 충분한 홀 |
| Best-Fit | 212... 없음 → 300? | 가장 작으면서 212 이상인 것 = 300 |
| Worst-Fit | 300 | 가장 큰 홀 |

ℹ **성능 비교: First-Fit과 Best-Fit이 Worst-Fit보다 시간과 공간 활용에서 우수하다**

## 단편화 문제

연속 메모리 할당의 근본적인 문제다

### 외부 단편화 (External Fragmentation)

✨ **남은 홀들의 총 크기는 충분하지만, 연속된 공간이 없어서 프로세스를 올릴 수 없는 상태**

```
╔════╗     ╔════╗     ╔════╗
║ P1 ║ 홀  ║ P2 ║ 홀  ║ P3 ║ 홀
╚════╝10KB ╚════╝15KB ╚════╝8KB

총 33KB의 여유가 있지만, 25KB 프로세스는 올릴 수 없다
```

**해결**: 압축(Compaction) — 모든 홀을 한쪽으로 모으기 (비용이 크다)

### 내부 단편화 (Internal Fragmentation)

✨ **프로세스에게 요청보다 조금 더 큰 공간을 할당했을 때, 남는 내부 공간이 낭비되는 상태**

```
요청: 18,462 바이트
할당: 18,464 바이트 (4바이트 단위 정렬)
낭비: 2 바이트 (내부에 갇혀 사용 불가)
```
