> CPU가 생성하는 주소와 실제 메모리의 주소는 다르다

---

## 문제: 프로세스는 자신이 0번 주소에서 시작한다고 생각한다

프로그램은 컴파일될 때 "0번 주소부터 시작한다"는 가정으로 작성된다

하지만 실제 메모리에는 여러 프로세스가 동시에 올라와 있어, 각자 다른 위치에 배치된다

- [!] **CPU가 생성하는 주소(논리 주소)와 실제 메모리 주소(물리 주소)를 분리해야 한다**

---

## 논리 주소 vs 물리 주소

| 종류 | 설명 |
|---|---|
| **논리 주소** (Logical Address) | CPU가 생성하는 주소 — 프로세스의 관점 |
| **물리 주소** (Physical Address) | 실제 메모리 하드웨어의 주소 — 메모리 주소 레지스터에 들어가는 값 |

```
프로세스: "346번 주소의 데이터를 읽어"  ← 논리 주소
MMU가 변환
실제 메모리: "14346번 주소에서 읽음"    ← 물리 주소
```

논리 주소 공간과 물리 주소 공간은 완전히 분리되어 있다

---

## MMU (Memory Management Unit)

- [I] **MMU: 논리 주소를 물리 주소로 변환하는 하드웨어 장치**

가장 단순한 MMU는 **재배치 레지스터(relocation register)** 를 사용한다

```
물리 주소 = 논리 주소 + 재배치 레지스터 값

재배치 레지스터 = 14000 이면:
  논리 주소 346 → 물리 주소 14346
  논리 주소 0   → 물리 주소 14000
```

```
CPU ──[논리 주소 346]──► MMU ──[물리 주소 14346]──► 메모리
                         (+ 14000)
```

프로세스 자체는 논리 주소만 알고, 물리 주소를 알 필요가 없다

OS는 컨텍스트 스위치 시 재배치 레지스터 값을 교체해 각 프로세스가 자신의 메모리 영역에만 접근하도록 한다
