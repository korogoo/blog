## 바리바리를 왜 확장하려고 하는가?

### Situation

쌍둥이가 만든 라이딩 코스 저장 앱을 구경했다.

 나 혼자만 쓰면 늘 달리던 루트만 반복하게 되고, 다
 
 른 라이더들이 아는 좋은 코스를 찾을 방법이 없었다.



### Behavior

라이딩 코스를 서로 공유하는 커뮤니티를 만들고,

실시간 위치 기반으로 근처 라이더와 자연스럽게 조우할 수 있는 시스템을 추가했다.


### Impact

(나중에 수치로 채울 부분 — DAU, 공유된 코스 수, 조우 발생 횟수 등)

## 왜 갑자기?

내 쌍둥이는 개발자이자, 오토바이를 타는 라이더이다.

최근 IOS 공부를 하더니 라이딩 코스를 저장하는 앱 `바리바리`를 만들었다.

구경해봤다...노잼이었다.

## 바리바리 서버는 어케 돌아감?

일단 대충 기능은 살펴봤고,,

서버가 어떻게 돌아가려나 봤다.

Swift 를 몰라서 코드를 다 까보기는 어렵고,  
그리고 깃허브가 오픈 소스길래, 깃헙 링크 가져와서 클로드한테 동작 분석해달라고 했다.


<br/>

✨ **데이터가 어디에 저장되나**

폰 안에만 저장된다 (사실상 서버가 없는 것)

```
  폰 내부 저장소 (Realm)
  ├── 코스 폴더 (CourseFolderTable)
  │   └── 코스 (CourseTable)
  │       ├── 제목, 내용, 거리, 지역
  │       ├── 썸네일 이미지
  │       └── 핀들 (PinTable) ← 지도의 점들
  │           └── 위도, 경도, 주소

```

❓ **근데 Realm이 뭐지?**

알아보니 폰 안에 있는 DB.  
앱 지워도 데이터 남고, 인터넷 없어도 쓸 수 있다고 한다.


<br/>

  ✨ **외부 연결은 뭐가 있나**

  - 네이버 지도 API -> `지도 표시`, `주소 변환`
  - Unsplash API -> `추천 코스 이미지 생성`
  - Firebase -> `앱 사용 통계`


<br/>

✨ **앱 내부 구조**

  MVVM 패턴 사용

❓ **MVVM 이 뭐지?**

Model, View, ViewModel 의 이니셜.

- 화면 (View)
- 로직 (ViewModel)
- 데이터 (Model)

뷰모델이 잘 안 와닿았는데, 대충 MVC 패턴에서 Service 역할? 로 이해된다.

### API

위 두가지 기능을 구현하기 위한 인터페이스를 설계했다.

사실 기능이 굉장히 간단해서 CRUD 뿐이긴 하다.



✨ `POST /posts`  내 코스 게시글 공유하기

✨ `PATCH /posts/{id}`  내 코스 게시글 수정하기

✨ `DELETE /posts/{id}`  내 코스 게시글 삭제하기

✨  `GET /posts?lat=37.5&lng=126.9&sortBy=nearby`  거리순으로 코스 게시글 목록 조회하기

✨ `GET /posts/{id}`  코스 게시글 단건 조회하기


<br/>

⚠️ **아직 로그인은 붙이지 않는다!**

인가 없이 api 를 구현하고, 나중에 인증/인가 처리를 추가한다.

솔직히 인증/인가 딸깍 하면 구현되는 거 알지만,,,  
우선 메인 기능에 집중하고, 제대로 잘 돌아가면 추가해도 늦지 않는다.

### Spring Boot 의존성 세팅

## Spring Web

웹으로 소통해야 하는데,  
웹과 소통하려면 소켓 열기 -> 바이트 읽기 -> 헤더 파싱 -> 라우팅을 구현해야 한다.

근데 이 라이브러리를 사용하면 스프링 웹 내부 DispatcherServlet 이 직접 처리하고,  
개발자는 @GetMapping() 만 적어주면 되어  

**전송계층을 신경쓰지 않고, 비지니스 로직에만 집중할 수 있다.**
 
<br/>

## Spring Data JPA

JPA 가 없다면?

가장 Raw 단계는 Driver Manager 만 사용하는 것이다.

⚠️ **SQL 을 직접 작성 + 쿼리를 날릴 때 커낵션과 같은 여러 연결을 직접 가져오고 닫아줘야 한다.**

이 연결/닫기가 너무 번거롭고, 코드가 지저분해져서 실제 로직이 눈에 잘 안 들어온다. 

<br/>

그래서 쓰는게 JdbcTemplate 이다.

이 추상화 객체를 사용하면 커낵션 같은 자원을 알아서 관리해줘서 개발자는 신경쓰지 않아도 된다.

⚠️ **근데 문제는 SQL 도 직접 써야 하고, DB 결과를 객체로 매핑하는 과정이 정말 번거롭다**

사용하다보면 이게 객체 지향이 맞나..? 점점 객체지향과 멀어지는 더러운 코드가 된다.

<br/>

그래서 쓰는게 Spring Data 이다.

DB 종류가 MongoDB, RDB 등 다양하고, 각 DB 마다 접근 방식이 다른데, 

**어떤 DB 를 쓰든 레포지토리 코드는 동일하게 유지할 수 있다.**


<br/>

그 중에서도 RDB 용은 Spring Data JPA 인 것이다.

이 라이브러리를 사용하면

JPA 가 자동으로 객체와 테이블을 매핑해서 처리하고,  

간단한 쿼리를 메서드 이름만으로 구현할 수 있게 해준다.

그래서 이 라이브러리를 쓰면 **객체지향적인 코드 작성에 도움**이 된다.

이번 ERD 는 관계형 데이터베이스로 설계했으니 JPA 를 사용한다.
 
<br/>

 
## H2 Driver

우선 H2를 쓰는 이유는 빠르게 구현하기 위해서이다.

설정도 굉장히 간단하고, 별도의 설정 없이 h2-console 로 웹 상에서 DB 데이터 상태를 확인할 수 있다.


<br/>

그리고 H2 Driver 는 이 H2 데이터 베이스를 JVM 인메모리에서 설치 없이 바로 사용할 수 있도록 도와준다.

근데 서버를 재시작하면 데이터가 사라지는 한계가 있어서, 

1차 MVP 검증 후 MySQL로 전환할 계획이다.

<br/>

## Lombok

JPA 와 JPA 엔티티를 사용하려면 객체에 getter, setter, 기본 생성자 등이 필요하다.

Lombok 없이 구현하면 getter 만해도 3줄인데,  읽어야 하는 코드가 너무 많아지고 시선이 분산된다.


DB 엔티티를 포함해 다양한 객체에 필요한 기본적인 getter, setter, contructer 등을  
어노테이션만 달면  자동으로 컴파일 시점에 바이트 코드로 변환해준다.
