## 예외 처리 결정 흐름

```
예외가 발생했다
       │
       ▼
이 예외는 사용자 입력/행위로 인한 것인가?
       │
  ┌────┴────┐
 YES        NO (시스템/버그)
  │          │
  ▼          ▼
재시도로     로그 남기고
복구 가능?   안전 메시지 출력
  │
  ├── YES → 사용자 친화 메시지 + 재시도 유도
  └── NO  → "다시 시작해주세요" or 종료
```

---

## 재시도 구현 기준

| 상황 | 방법 |
|---|---|
| 사용자 입력 재시도 | `while(true)` + `try-catch` |
| 트리/재귀 탐색 | 재귀 허용 |
| 네트워크 재시도 | 최대 횟수 제한 + 지수 백오프 |

---

## 실전 체크리스트

✨ **콘솔에 스택 트레이스가 출력되는가?**

로거로 대체하고, 사용자에게는 친화적 메시지만 보여준다

<br/>

✨ **재시도를 재귀로 구현했는가?**

탈출 조건이 확실하고, 재시도 성공 확률이 높다면 팀 내 합의를 해보고,

특별한 이유가 없다면 안정성과 가독성을 위해 `while` 반복문으로 바꾼다

<br/>

✨ **`catch (Exception e)`로 모든 예외를 한 번에 잡는가?**

복구 가능한 예외와 불가능한 예외를 분리해서 처리한다

<br/>

✨ **예외 메시지가 개발자 언어인가? ("IllegalArgumentException: ...")**

사용자 언어로 바꾼다 ("잘못된 입력입니다. 다시 시도해주세요.")
