> 개행이 없어서 나쁜 코드보다, ==의미 없는 개행이 있어서 나쁜 코드==가 더 많다

---

## 안티패턴 목록

### return 직전 습관적 개행

`return` 이 메서드의 마지막 문장이면, 앞에 개행을 붙여도 아무것도 나뉘지 않는다

```java
public int getScore() {
    int score = base + bonus;

    return score;
}
```

return 이 단순 반환이라면 붙여도 충분히 읽힌다
```java
public int getScore() {
    int score = base + bonus;
    return score;
}
```


<br/>

⚠️ **단, return 전에 독립적인 처리 단계가 있고 그걸 구분할 때는 개행이 맞다**

```java
public List<String> getWinnerNames() {
    int maxScore = findMaxScore();
    List<Player> winners = filterByScore(maxScore);

    return winners.stream().map(Player::getName).collect(toList());
}
```

### 메서드 첫 줄 개행

메서드 시그니처와 본문 사이를 벌릴 이유가 없다

```java
public void move(Position from, Position to) {

    validate(from, to);
    board.move(from, to);
}
```
---

### 메서드 마지막 줄 개행

닫는 `}` 직전 빈 줄도 아무 의미가 없다

```java
public boolean isFinished() {
    return status == Status.END;

}
```

---

### 모든 문장마다 개행

모든 줄을 나누면 오히려 묶음이 사라져서 어디서 단계가 바뀌는지 알 수 없다

```java
public boolean canMove(Position from, Position to) {

    if (from.equals(to)) {
        return false;
    }

    Piece piece = board.getPiece(from);

    if (piece == null) {
        return false;
    }

    return piece.getMovablePositions(from, board).contains(to);

}
```

---

### 필드 하나씩 개행

필드를 하나씩 나누면 같은 그룹이라는 인식이 사라진다

```java
public class Player {

    private final String name;

    private int score;

    private boolean isEliminated;
}
```

### 파일 마지막 개행이 없는 경우

⚠️ No newline at end of file

자바를 포함한 대부분의 프로그래밍 언어 컨벤션에서 파일의 끝은 빈줄로 끝나야 한다는 규칙이 강력하게 권장된다

이는 POSIX 표준에 근거한 것으로, 파일의 마지막 줄이 올바르게 종료되었음을 보장하기 위함이다
