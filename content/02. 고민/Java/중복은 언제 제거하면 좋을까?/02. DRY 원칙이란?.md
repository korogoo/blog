## 핵심: "지식"의 중복이 문제다

DRY는 **코드 형태의 중복 제거**가 아니라 **지식의 단일화**다

| 구분 | 예시 |
|---|---|
| 코드 형태는 같지만 지식이 다른 것 | 배송지 주소 vs 청구지 주소 |
| 코드 형태는 다르지만 지식이 같은 것 | 보드 크기가 여러 곳에 흩어진 경우 |

---

## 지식의 중복 vs 코드의 중복

```java
// 두 클래스의 코드가 거의 같다
public class Row {
    private final int value;
    public boolean isValid() { return value >= 1 && value <= 10; }
    public Row add(int n) { return new Row(value + n); }
}

public class Column {
    private final int value;
    public boolean isValid() { return value >= 1 && value <= 9; }
    public Column add(int n) { return new Column(value + n); }
}
```

코드 형태는 거의 같지만, 행은 상하 방향, 열은 좌우 방향을 담당한다

변경되는 이유가 다르다 -> **하나로 합치지 않는다**

```java
// 이건 진짜 지식 중복
private static final int BOARD_SIZE = 10; // Game.java에도, Board.java에도, Renderer.java에도
```

`장기판 크기는 10이다`라는 하나의 사실이 여러 곳에 표현된다 -> **하나로 합친다**
