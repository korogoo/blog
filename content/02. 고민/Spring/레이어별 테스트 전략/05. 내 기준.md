> 레이어마다 테스트 목적이 다르고, 목적에 맞는 도구가 다르다  
> 
> ==빠른 피드백을 위해 가능한 한 가벼운 방식을 먼저 고려한다==

---

## 레이어별 테스트 전략 정리

| 레이어              | 어노테이션                                 | Mock 방식                  | 목적               |
| ---------------- | ------------------------------------- | ------------------------ | ---------------- |
| Controller       | `@SpringBootTest(RANDOM_PORT)`        | `@MockitoBean`           | 실제 HTTP 요청/응답 검증 |
| Controller (가볍게) | `@WebMvcTest`                         | `@MockitoBean`           | MVC 레이어만 검증      |
| Service          | `@ExtendWith(MockitoExtension.class)` | `@Mock` + `@InjectMocks` | 비즈니스 로직 단위 검증    |
| Repository       | `@DataJpaTest` , `@JdbcTest`          | —                        | 쿼리 검증            |


## 실전 체크리스트

❓ **Controller 테스트에서 Service Mock이 적용 안 되는가?**

`@Mock` 대신 `@MockitoBean`을 사용한다

<br/>

❓ **Service 테스트가 너무 느린가?**

`@SpringBootTest` 대신 `@ExtendWith(MockitoExtension.class)`를 사용한다

컨텍스트 로딩 없이 밀리초 단위로 실행된다

<br/>

❓ **RestAssured vs MockMvc 중 무엇을 쓰는가?**

실제 HTTP 요청을 보내는 통합 테스트라면 RestAssured (`RANDOM_PORT`)

MVC 레이어만 검증하는 슬라이스 테스트라면 MockMvc (`@WebMvcTest` 또는 `MOCK`)

<br/>

❓ **Spring Boot 3.2 이상을 쓰는가?**

`@MockBean`은 deprecated다

`@MockitoBean`을 사용한다
