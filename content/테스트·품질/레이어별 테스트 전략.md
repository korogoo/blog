## 발단

Controller 테스트를 작성하다가 `@Mock`으로 의존성을 교체했더니 Spring 컨텍스트에 반영이 안 됐다

`@MockitoBean`으로 바꾸자 동작했는데, 둘의 차이가 뭔지 몰랐다

Service 테스트는 `@SpringBootTest` 없이 짜야 한다는 말도 들었는데, 그 이유도 명확하지 않았다

---

### 생겼던 질문

- Controller 테스트와 Service 테스트는 왜 다른 방식으로 작성하는가?
- `@Mock`과 `@MockitoBean`은 무엇이 다른가?
- `@ExtendWith(MockitoExtension.class)`는 무엇을 하는가?
- Service 테스트에 `@SpringBootTest`를 쓰면 안 되는 이유는?
- RestAssured는 무엇이고, MockMvc와는 어떻게 다른가?

---

### 왜 중요한가?

> 레이어마다 테스트 전략이 다르다  
> 
> ==목적에 맞는 도구를 쓰지 않으면 테스트가 느려지거나, 검증 범위가 틀어진다==

Controller 테스트에서 `@Mock`을 쓰면 Spring이 실제 빈을 사용해서 의도한 Mock이 적용되지 않는다

Service 테스트에서 `@SpringBootTest`를 쓰면 불필요한 DB, JPA 설정까지 올라와 느려진다


---

## Controller 테스트

> Controller 테스트는 실제 HTTP 요청/응답 흐름을 검증한다  
> 
> ==Spring 컨텍스트가 반드시 필요하고, 의존하는 빈은 @MockitoBean으로 교체한다==

---

### 기본 구조

```java
@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT)
class MemberControllerTest {

    @MockitoBean
    private MemberService memberService;

    @LocalServerPort
    int port;

    @Test
    void 회원을_조회한다() {
        given(memberService.findById(1L))
            .willReturn(new MemberResponse("코로구", 25));

        RestAssured
            .given().port(port)
            .when().get("/members/1")
            .then()
            .statusCode(200)
            .body("name", equalTo("코로구"));
    }
}
```

---

### 각 구성요소

✨ **`@SpringBootTest(webEnvironment = RANDOM_PORT)`**

실제 내장 서버를 랜덤 포트로 띄운다

실제 HTTP 요청/응답 흐름 전체를 검증할 수 있다

<br/>

✨ **`@MockitoBean`**

Spring 컨텍스트에 등록된 실제 `MemberService` 빈을 가짜로 교체한다

Controller가 의존하는 Service를 교체해야 하기 때문에 컨텍스트 안에 등록이 필요하다

<br/>

✨ **RestAssured**

실제 HTTP 요청을 보내서 응답을 검증하는 라이브러리다

`given().when().then()` 구조로 요청과 검증을 작성한다

`RANDOM_PORT`로 서버를 띄운 경우에 주로 쓴다

---

### @Mock을 쓰면 안 되는 이유

⚠️ **Spring 컨텍스트와 무관하게 생성된 가짜 객체**

```java
@Mock
private MemberService memberService;
```

`@Mock`은 순수 Mockito가 만드는 가짜 객체다

Spring 컨텍스트에 등록되지 않기 때문에,  
Controller가 주입받는 `MemberService`는 여전히 실제 빈이다

Mock을 만들어도 Controller에 전달되지 않는다

---

### 참고

- Spring Boot 3.2 이후 `@MockBean` → `@MockitoBean`으로 변경됨
- `@MockBean`은 deprecated (Spring Boot 3.4+)

## Service 테스트

> Service 테스트는 비즈니스 로직만 빠르게 검증한다  
> 
> ==Spring 컨텍스트 없이 순수 Mockito만으로 충분하다==

---

### 기본 구조

```java
@ExtendWith(MockitoExtension.class)
class MemberServiceTest {

    @Mock
    private MemberRepository memberRepository;

    @InjectMocks
    private MemberService memberService;

    @Test
    void 존재하지_않는_회원을_조회하면_예외가_발생한다() {
        given(memberRepository.findById(99L))
            .willReturn(Optional.empty());

        assertThatThrownBy(() -> memberService.findById(99L))
            .isInstanceOf(MemberNotFoundException.class);
    }
}
```

---

### 각 구성요소

✨ **`@ExtendWith(MockitoExtension.class)`**

Spring 컨텍스트 없이 순수 Mockito를 사용할 수 있게 해주는 JUnit 확장이다

애플리케이션 전체를 로딩하지 않으므로 빠르다

<br/>

✨ **`@Mock`**

Spring과 무관하게 Mockito가 만드는 가짜 객체다

`memberRepository.findById()`가 어떻게 동작할지를 `given()`으로 정의해서 쓴다

<br/>

✨ **`@InjectMocks`**

테스트 대상 클래스(`MemberService`)에 `@Mock`으로 만든 가짜 객체를 직접 주입한다

Spring의 `@Autowired`가 아닌 Mockito가 직접 주입을 처리한다

---

### @SpringBootTest를 쓰지 않는 이유

 ✨ @SpringBootTest 사용 시 올라오는 것들

- Spring 컨텍스트 전체
- JPA, Hibernate 설정
- DataSource, Connection Pool
- 모든 @Bean 등록

⚠️ **Service 비즈니스 로직을 검증하는 데는 이 모든 것이 필요 없다**

`@ExtendWith(MockitoExtension.class)`는 밀리초 단위로 실행된다

---

### 테스트 속도 비교

| 방식 | 실행 시간 |
|------|---------|
| `@SpringBootTest` | 수 초 (컨텍스트 로딩 포함) |
| `@ExtendWith(MockitoExtension.class)` | 밀리초 (컨텍스트 없음) |


---

## @Mock vs @MockitoBean

> 둘 다 가짜 객체를 만들지만, 그 객체가 Spring 컨텍스트에 등록되느냐가 다르다  
> 
> ==Spring 컨텍스트가 있는 테스트라면 @MockitoBean, 없다면 @Mock==

---

### 비교

|         | `@Mock`                               | `@MockitoBean`                   |
| ------- | ------------------------------------- | -------------------------------- |
| 만드는 주체  | Mockito                               | Spring + Mockito                 |
| 컨텍스트 등록 | X                                     | O (기존 빈을 교체)                     |
| 사용 위치   | `@ExtendWith(MockitoExtension.class)` | `@SpringBootTest`, `@WebMvcTest` |
| 주입 방식   | `@InjectMocks`가 직접 주입                 | Spring이 컨텍스트에 넣어줌                |

---

### @Mock이 Controller 테스트에서 동작하지 않는 이유

> @SpringBootTest 환경을 가정한다

<br/>


⚠️ **`@Mock`은 컨텍스트 밖에 존재하기 때문에 Controller에 전달되지 않는다**

```java
@Mock MemberService mockService
```

Spring 컨텍스트 안에 MemberService(실제 빈)이 존재한다

mockService 는 Mockito가 따로 만든 가짜 객체이므로 Spring 컨텍스트와 무관하다

<br/>

이 상태에서 Controller 가 Spring 컨텍스트에서 MemberService 찾는다

memberService 는 실제 빈으로 주입된다


---

### @MockitoBean이 동작하는 이유

> @SpringBootTest 환경을 가정한다

<br/>

⚠️ **`@MockitoBean`은 컨텍스트 안에 존재하기 때문에 Controller에 전달된다**
```java
@MockitoBean MemberService mockService
```

Spring 컨텍스트 안의 실제 MemberService 빈을 가짜로 교체한다

Controller 가 Spring 컨텍스트에서 MemberService 을 찾는다

가짜 빈인 mockService 이 주입된다 (Mock 적용됨)


---

### 언제 무엇을 쓰는가

✨ **`@Mock`** 

Spring 컨텍스트 없는 순수 단위 테스트 (`@ExtendWith`)

<br/>


✨ **`@MockitoBean`**

Spring 컨텍스트를 띄운 통합 테스트 (`@SpringBootTest`, `@WebMvcTest`)

## 내 기준

> 레이어마다 테스트 목적이 다르고, 목적에 맞는 도구가 다르다  
> 
> ==빠른 피드백을 위해 가능한 한 가벼운 방식을 먼저 고려한다==

---

### 레이어별 테스트 전략 정리

| 레이어              | 어노테이션                                 | Mock 방식                  | 목적               |
| ---------------- | ------------------------------------- | ------------------------ | ---------------- |
| Controller       | `@SpringBootTest(RANDOM_PORT)`        | `@MockitoBean`           | 실제 HTTP 요청/응답 검증 |
| Controller (가볍게) | `@WebMvcTest`                         | `@MockitoBean`           | MVC 레이어만 검증      |
| Service          | `@ExtendWith(MockitoExtension.class)` | `@Mock` + `@InjectMocks` | 비즈니스 로직 단위 검증    |
| Repository       | `@DataJpaTest` , `@JdbcTest`          | —                        | 쿼리 검증            |

---

### 결정 흐름

```
무엇을 검증하려 하는가?
         │
    ┌────┼──────────────┬──────────────┐
  실제 HTTP  MVC 레이어  비즈니스 로직   DB 쿼리
  흐름 전체  (Controller) (Service)    (Repository)
    │          │              │                 │
RANDOM_PORT  @WebMvcTest  @ExtendWith        @DataJpaTest
+RestAssured +MockMvc    +@Mock/@InjectMocks @JdbcTest
```

---

### Mock 선택 기준표

```
Spring 컨텍스트가 필요한 테스트인가?
         │
    ┌────┴────┐
    Yes       No
    │         │
@MockitoBean  @Mock
(컨텍스트 내   (@InjectMocks로
 빈을 교체)    직접 주입)
```

---

### 실전 체크리스트

❓ **Controller 테스트에서 Service Mock이 적용 안 되는가?**

`@Mock` 대신 `@MockitoBean`을 사용한다

<br/>

❓ **Service 테스트가 너무 느린가?**

`@SpringBootTest` 대신 `@ExtendWith(MockitoExtension.class)`를 사용한다

컨텍스트 로딩 없이 밀리초 단위로 실행된다

<br/>

❓ **RestAssured vs MockMvc 중 무엇을 쓰는가?**

실제 HTTP 요청을 보내는 통합 테스트라면 RestAssured (`RANDOM_PORT`)

MVC 레이어만 검증하는 슬라이스 테스트라면 MockMvc (`@WebMvcTest` 또는 `MOCK`)

<br/>

❓ **Spring Boot 3.2 이상을 쓰는가?**

`@MockBean`은 deprecated다

`@MockitoBean`을 사용한다
