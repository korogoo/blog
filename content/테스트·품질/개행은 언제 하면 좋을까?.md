## 개행의 역할

> 개행은 ==코드의 문단 구분자==다 
>  
> 이 위 덩어리와 이 아래 덩어리는 다른 이야기다라고 독자에게 알리는 신호

---

### 개념

글에서 문단이 주제의 전환을 알리듯, 코드에서 개행은 ==관심사의 전환==을 알린다

⚠️ **개행이 없으면 전부 하나의 덩어리처럼 읽힌다**

```java
public boolean canMove(Position from, Position to) {
    if (from.equals(to)) throw new IllegalArgumentException("같은 위치입니다");
    Piece piece = board.getPiece(from);
    if (piece == null) throw new IllegalArgumentException("기물이 없습니다");
    List<Position> movable = piece.getMovablePositions(from, board);
    return movable.contains(to);
}
```

✨ **개행이 있으면 단계가 눈에 들어온다**
```java
public boolean canMove(Position from, Position to) {
    if (from.equals(to)) {
	    throw new IllegalArgumentException("같은 위치입니다");
	}
    Piece piece = board.getPiece(from);
    if (piece == null) {
	    throw new IllegalArgumentException("기물이 없습니다");
	}

    List<Position> movable = piece.getMovablePositions(from, board);
    return movable.contains(to);
}
```

---

### 개행의 역할
> 코드도 글이다
> 
> 읽히는 순서와 흐름을 설계하는 것이 개행의 목적이다

<br/>

✨ **관심사를 묶는다**

같은 관심사에 속하는 코드는 붙여두고, 다른 관심사가 시작되면 빈 줄로 나눈다

<br/>

✨ **읽는 속도를 조절한다**

빈 줄이 없으면 독자는 멈추지 않고 계속 읽는다

중요한 흐름의 전환 지점에서 빈 줄이 있으면 자연스럽게 한 박자 쉬고 다음 단계를 인식한다

<br/>

✨ **'왜 여기서 나뉘지?'가 생기면 나쁜 개행이다**

독자가 빈 줄을 보고 이유를 추측해야 한다면, 그 개행은 의미 전달에 실패한 것이다

## 클래스 레벨 개행

> 클래스 안에서는 ==같은 종류끼리 묶고, 종류가 바뀌면 개행==으로 구분한다

---

### 기본 구조

Java 클래스의 일반적인 선언 순서와 개행 위치는 아래와 같다

```java
public class ChessBoard {

    // 상수 그룹
    private static final int SIZE = 8;
    private static final String EMPTY = ".";

    // 인스턴스 필드 그룹
    private final Map<Position, Piece> pieces;
    private Turn turn;
                                            // ← 필드 블록 끝, 생성자 시작 전 1줄
    public ChessBoard(Map<Position, Piece> pieces) {
        this.pieces = Map.copyOf(pieces);
        this.turn = Turn.WHITE;
    }
                                            // ← 생성자/메서드 사이 1줄
    public boolean canMove(Position from, Position to) {
        ...
    }
                                            // ← 메서드 사이 1줄
    public void move(Position from, Position to) {
        ...
    }
}
```

---

### 규칙별 정리

✨ **상수와 인스턴스 필드는 그룹을 구분한다**

성격이 다른 필드끼리는 1줄로 나눈다

```java
private static final int MAX_SCORE = 100;  // 상수
private final String name;                  // ← 빈 줄 없으면 같은 그룹처럼 보임
private int score;
```

```java
private static final int MAX_SCORE = 100;  // 상수
                                            // ← 1줄로 구분
private final String name;                  // 인스턴스 필드
private int score;
```

<br/>

✨ **필드 블록과 생성자 사이 1줄**

선언부와 행동부(생성자, 메서드)를 분리해서 훑는 흐름을 만든다

<br/>

✨ **메서드와 메서드 사이 1줄**

메서드 경계가 명확하게 보인다

<br/>

✨ **관련 메서드는 가까이 둔다 (Step-down Rule)**

호출하는 메서드 바로 아래에 호출되는 메서드를 두면, 위에서 아래로 읽히는 흐름이 만들어진다

```java
public void move(Position from, Position to) {
    validate(from, to);        // ← 호출자
    ...
}

private void validate(Position from, Position to) {  // ← 피호출자 — 바로 아래
    ...
}
```

---

### 하지 말아야 할 것

```java
public class Order {

    private final Long id;

    private final String customerName;       // ← 필드 하나씩 개행 → 불필요

    private OrderStatus status;

    public Order(Long id, String customerName) {
                                             // ← 메서드 첫 줄 개행 → 불필요
        this.id = id;
        this.customerName = customerName;
        this.status = OrderStatus.PENDING;
                                             // ← 메서드 마지막 줄 개행 → 불필요
    }
}
```

> 필드 하나마다 빈 줄을 넣으면 묶음이 사라져서 클래스 전체가 파편화되어 보인다

## 메서드 내 개행

> 메서드 안에서는 ==로직의 단계가 바뀔 때==만 개행한다

---

### 개념

메서드 내부의 코드는 보통 여러 단계로 이루어진다

단계가 바뀌는 지점이 바로 개행을 넣는 자리다

```java
public int calculate(List<Integer> scores) {
    if (scores == null || scores.isEmpty()) {      // 검증
        throw new IllegalArgumentException("점수 목록이 비어있습니다");
    }

    int total = scores.stream().mapToInt(i -> i).sum();  // 처리
    double average = (double) total / scores.size();

    return (int) Math.round(average);              // 반환
}
```

---

### 단계 구분 기준

✨ **검증 -> 처리 구간 전환**

입력을 확인하는 블록이 끝나고 실제 로직이 시작될 때 1줄

<br/>

✨ **처리 단계 내부에서도 관심사가 바뀔 때**

변환 -> 필터링 -> 집계 처럼 성격이 다른 작업이 이어질 때 1줄

```java
public List<String> getWinnerNames(List<Player> players) {
    int maxScore = players.stream()
        .mapToInt(Player::getScore)
        .max()
        .orElseThrow();

    return players.stream()
        .filter(p -> p.getScore() == maxScore)
        .map(Player::getName)
        .collect(toList());
}
```

<br/>

⚠️  **짧은 메서드는 개행 불필요**

3줄 이하의 메서드에서 개행을 넣으면 오히려 불필요한 여백이 생긴다

```java
// 개행 불필요 — 이미 충분히 짧다
public boolean isWhiteTurn() {
    return turn == Turn.WHITE;
}
```

---

### 개행 판단 질문

❓ 이 개행을 없애도 단계가 구분되어 보이는가?


❓ 이 개행을 넣으면 새로운 단계가 시작되는 느낌인가?


---

### 흔한 실수
⚠️ **return 직전 습관적 개행**
```java
public int getScore() {
    int score = base + bonus;

    return score;  // ← 이 개행이 뭘 나누는 건지 불분명
}
```

> `return` 직전 개행은 [[#개행 안티패턴]] 에서 자세히 다룬다

## 테스트 코드 개행

> 테스트 코드에서 개행은 ==given / when / then 절을 눈에 보이게 나누는 역할==을 한다

---

### 개념

테스트 코드는 BDD(Behavior-Driven Development) 스타일로 세 구절로 나뉜다


- `given`: 이런 상황이 주어졌을 때
- `when`: 이 행동을 하면
- `then`: 이런 결과가 나와야 한다


```java
@Test
void 점수가_가장_높은_플레이어가_우승자다() {
    Player playerA = new Player("A", 80); // given
    Player playerB = new Player("B", 95);
    Players players = new Players(List.of(playerA, playerB));
    
    List<String> winners = players.findWinners(); // when
    
    assertThat(winners).containsExactly("B"); // then
}
```

---

### 규칙

✨ **given / when / then 사이에 1줄씩**

절의 경계가 명확해지고, 어디서 준비하고 어디서 실행하는지 바로 보인다

<br/>

✨ **주석(`// given`)을 쓸 거라면 개행도 함께**

주석과 개행을 같이 쓰면 더 명확하지만, 둘 다 없거나 둘 다 있어야 한다

```java
@Test
void 이동_가능한_위치를_반환한다() {
    // given
    Board board = new Board(...);
    Position from = Position.of(1, 1);

    // when
    List<Position> result = board.getMovablePositions(from);

    // then
    assertThat(result).containsExactlyInAnyOrder(...);
}
```

<br/>

⚠️ **주석은 있는데 개행이 없으면 절 구분이 모호해진다**
```java
@Test
void 이동_가능한_위치를_반환한다() {
    // given
    Board board = new Board(...);
    Position from = Position.of(1, 1);
    // when
    List<Position> result = board.getMovablePositions(from);
    // then
    assertThat(result).containsExactlyInAnyOrder(...);
}
```

<br/>

✨ **given 블록이 길 때 내부에서도 의미 단위로 묶는다**

준비가 복잡할 때는 given 안에서도 개행으로 묶음을 만든다

```java
@Test
void 장군_상태에서_이동하면_예외가_발생한다() {
    // given
    Piece king = new King(Side.WHITE);
    Piece rook = new Rook(Side.BLACK);

    Board board = new Board(Map.of(
        Position.of(4, 4), king,
        Position.of(4, 8), rook
    ));
    Position kingPosition = Position.of(4, 4);

    // when & then
    assertThatThrownBy(() -> board.move(kingPosition, Position.of(4, 5)))
        .isInstanceOf(IllegalStateException.class);
}
```

> 테스트 코드는 구조가 더 명시적으로 보여야 하므로, 프로덕션보다 개행 기준이 더 고정적이다

## 개행 안티패턴

> 개행이 없어서 나쁜 코드보다, ==의미 없는 개행이 있어서 나쁜 코드==가 더 많다

---

### 안티패턴 목록

#### return 직전 습관적 개행

`return` 이 메서드의 마지막 문장이면, 앞에 개행을 붙여도 아무것도 나뉘지 않는다

```java
public int getScore() {
    int score = base + bonus;

    return score;
}
```

return 이 단순 반환이라면 붙여도 충분히 읽힌다
```java
public int getScore() {
    int score = base + bonus;
    return score;
}
```


<br/>

⚠️ **단, return 전에 독립적인 처리 단계가 있고 그걸 구분할 때는 개행이 맞다**

```java
public List<String> getWinnerNames() {
    int maxScore = findMaxScore();
    List<Player> winners = filterByScore(maxScore);

    return winners.stream().map(Player::getName).collect(toList());
}
```

---

#### 메서드 첫 줄 개행

메서드 시그니처와 본문 사이를 벌릴 이유가 없다

```java
public void move(Position from, Position to) {

    validate(from, to);
    board.move(from, to);
}
```
---

#### 메서드 마지막 줄 개행

닫는 `}` 직전 빈 줄도 아무 의미가 없다

```java
public boolean isFinished() {
    return status == Status.END;

}
```

---

#### 모든 문장마다 개행

모든 줄을 나누면 오히려 묶음이 사라져서 어디서 단계가 바뀌는지 알 수 없다

```java
public boolean canMove(Position from, Position to) {

    if (from.equals(to)) {
        return false;
    }

    Piece piece = board.getPiece(from);

    if (piece == null) {
        return false;
    }

    return piece.getMovablePositions(from, board).contains(to);

}
```

---

#### 필드 하나씩 개행

필드를 하나씩 나누면 같은 그룹이라는 인식이 사라진다

```java
public class Player {

    private final String name;

    private int score;

    private boolean isEliminated;
}
```

---

#### 파일 마지막 개행이 없는 경우

⚠️ No newline at end of file

자바를 포함한 대부분의 프로그래밍 언어 컨벤션에서 파일의 끝은 빈줄로 끝나야 한다는 규칙이 강력하게 권장된다

이는 POSIX 표준에 근거한 것으로, 파일의 마지막 줄이 올바르게 종료되었음을 보장하기 위함이다

## 내 기준

### 상황별 기준표

#### 클래스 레벨

👍 상수 필드 <--> 인트선트 필드

👍 필드 <--> 생성자

👍 생성자 <--> 메서드

👍 메서드 <--> 메서드

<br/>

👎 필드 하나씩

👎 메서드 첫 줄

👎 메서드 마지막 줄

#### 메서드 내부

👍 검증 블록 <--> 처리 시작

👍 처리 단계 내 관심사 전환

<br/>

👎 짧은 메서드 (3줄 이하)

👎 return 직전 (단순 반환)

👎 모든 문장 사이

#### 테스트 코드

👍 given <--> when <--> then

👍 given 내부 준비 대상이 다를 때

👍 //given, //when, //then 주석 전
